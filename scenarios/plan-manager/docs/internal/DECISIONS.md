# Decisions — Plan Manager

This document records durable decisions and tradeoffs future agents
should not accidentally relitigate.

## Purpose Of This Document

Use this document when a choice:

- affects multiple files or future agents,
- rejects a plausible alternative,
- changes architecture, deployment, data, security, monetization, or
  testing direction,
- needs a revisit trigger.

Routine implementation log entries belong in [`PROGRESS.md`](PROGRESS.md).
Known unresolved issues belong in [`PROBLEMS.md`](PROBLEMS.md).

## Decision Log

These were converged in the founding idea-workshop (2026-06-25) before any code.
They are the load-bearing choices; do not relitigate without a stated trigger.

| Date | Decision | Context | Consequences | Revisit Trigger |
|---|---|---|---|---|
| 2026-06-25 | Use the generated `react-vite` scenario documentation contract. | Scenario scaffold was generated from the template. | Docs start with stubs and maturity metadata in `docs/manifest.json`. | Revisit when scenario adopts a different template or doc contract. |
| 2026-06-25 | plan-manager is the **plan-logic SSOT**, exposed as a guided wizard runtime — not just a plan store. | Plan logic is scattered/trapped today (swarm-manager `phased-plan-drain`, the prose authoring skill, project hygiene, and legacy root plan storage). | Other surfaces become thin consumers that delegate here (inversion of control). | If a second authority for plan logic is proposed, reconcile rather than fork. |
| 2026-06-25 | The deterministic **wizard + validators** are the primary local-model unlock; just-in-time context injection is the multiplier. | North star: drive the tokens + intelligence cost of plan work low enough for local models. | Mechanical work (anchor, required-reading, refs, status, baseline scope) moves into code; the model supplies only genuine prose. | If empirical trials show prose authoring still needs a large model, revisit which steps are deterministic. |
| 2026-06-25 | **Storage = scenario owns logic over a durable `~/.vrooli` home store** (not a scenario-private DB). | Plans must persist outside the server process. | plan-manager owns schema/validation/logic; persistence is process-independent. | If multi-host/remote storage is required, revisit the substrate. |
| 2026-06-25 | **Artifact = structured phases as first-class records**, markdown is a rendered view. | Computed status + staleness require structured data, not prose. | Phase status is a typed transition; the agent never hand-edits plan markdown. | If structured authoring proves too heavy for the smallest models, revisit. |
| 2026-06-25 | **Validation autonomy = compute + run, agent in the loop.** | Agents shouldn't reason about which scenarios to baseline. | plan-manager derives the exact baseline/check set and runs it on request; agents may run baselines, never commit. | If a fully autonomous background refresh is wanted, revisit. |
| 2026-06-25 | **Sequencing = build standalone first, invert consumers later** (OT-P2-002). | swarm-manager is mid-refactor; lower blast radius to prove standalone first. | Consumer inversion is deferred to a later phase. | After P0/P1 are green and proven standalone. |
| 2026-06-25 | **Code references via today's `[CODE:]`/code-facts now; unified code identifier is a drop-in upgrade later.** | The unified identifier is still being designed in another track. | Staleness is computable today; soft-depend, do not block. | When the unified code identifier ships, swap the locator. |
| 2026-06-25 | **Handoff ownership split:** plan-manager owns the *structured* handoff; the *prose* final-message catch-all is owned by the orchestration layer (agent-manager transcript → swarm-manager operating mode). | plan-manager is a tool agents call; it never sees the chat stream and must not read transcripts. | Prose detection/extraction/attribution-crossoff live at the spawner; plan-manager links to it by reference. | Never folds transcript-reading into plan-manager. |
| 2026-06-25 | **Findings are filed as candidate (unvalidated); an operator triages** before they become real bugs. | Small/local models produce noisy/transient "bugs". | A candidate finding is never presented as a confirmed bug; promotion is a separate human step. | If a reliable auto-validation gate is built, revisit promotion. |
| 2026-06-25 | **Project-level validation is consumed, not owned.** | It belongs with test-genie / scenario-validation / MoM's Validate projection. | plan-manager reads validation results; it does not test resources/packages/project. | If no owner emerges, reconsider. |
| 2026-06-27 | **Continue-loop commands are the primary small-agent path.** | `author next`/`phase-next` and `exec resume`/`next` exposed useful primitives, but small agents still had to infer sequencing from prose. | `author continue` and `exec continue` delegate sequencing to API-owned guidance and return one recommended next action; lower-level commands remain available as the actions the guidance points to. | Revisit only if API guidance becomes too coarse for a real consumer inversion workflow. |
| 2026-06-27 | **New phases must carry setup context or a typed no-context reason.** | Validation already treated phase setup context as required, while authoring finalization did not. | Authoring validation now rejects phases without `relevant_context[]` unless the phase records a `NO_CONTEXT: <reason>` relevant-context note. Legacy `required_reading[]` remains migration input. | Revisit when a first-class `no_context_reason` field is added to the shared phase model. |
| 2026-06-27 | **Regression anchors are typed validation inputs, not prose.** | The model had typed anchor fields, but authoring could still store arbitrary anchor text as `baseline_name`, making validation depend on accidental string shape. | Authoring finalization and markdown import now parse structured anchor bullets into typed fields and canonical commands. Legacy prose is preserved as `legacy_prose`/degraded when it cannot safely produce an oracle. Validation derives commands from typed anchor fields when stored commands are absent. | Revisit only when adding first-class degraded/detail fields beyond the current `unavailable` marker. |
| 2026-06-27 | **`done` phase transitions require fresh passing validation or a typed override.** | `exec transition --status done` could previously mark a phase complete even when the validation seam had no stored result, a failed result, unknown degradation, or stale context. | `TransitionPhase` now rejects `done` unless the last stored phase validation is `pass` + `fresh`, or the caller supplies `validation_override.reason` (`--validation-override-reason` in the CLI). `exec continue` recommends `validate run <plan> --phase <phase>` before recommending the `done` transition. | Revisit if validation freshness gains a richer recency model than the current staleness tier. |
| 2026-06-27 | **A single `log` domain is the execution-log ledger; decisions, findings, bug reports, records, and notes are DISTINCT entry types and are never conflated.** | Capture of an agent's work products was scattered on the execution runner and the distinct concepts (an unvalidated finding ≠ a filed bug ≠ reusable learning) blurred together. | `[CODE: api/internal/planlog/]` owns one `log_entries` ledger (`[CODE: packages/proto/schemas/plan-manager/v1/log/log.proto]` `LogService`). A finding is unvalidated/candidate, a `bug_report` is filed to the issue tracker, a `record` is reusable learning — each is its own typed `LogEntryType`. Findings promote (not mutate) into a bug or record via `PromoteEntry`, preserving the original. | Revisit only if a sixth typed work product needs first-class capture. |
| 2026-06-27 | **Downstream bug-report and record forwarding is owned INTERNALLY via seams; durable-local and never fatal.** | An agent must never be told to shell `scenario-qa` / `swarm-manager` CLIs from the plan workflow, and a downed downstream must not block plan execution. | `BugReporter`/`RecordWriter` seams (`[CODE: api/internal/planlog/seams.go]`) forward bugs→scenario-qa and records→swarm-manager. Production wiring installs live HTTP adapters: bugs write Prompt Manager `scenario-qa` knowledge entries under `bug-inbox/code-defect/<slug>`; records write Swarm Manager `/api/v1/records`. Both adapters lookup by deterministic Plan Manager entry provenance before create so `log sync` retries do not duplicate downstream artifacts. Discovery/network/5xx unavailability persists `pending`; downstream rejection persists `sync_failed`; explicit pending stubs remain degraded/test fallbacks. | Revisit if scenario-qa ships a dedicated bug API or Swarm Manager adds first-class external idempotency keys. |
| 2026-06-27 | **Decisions and findings moved OUT of execution into the `log` domain; the handoff carries a compact log summary, not embedded decision/finding lists.** | Execution owned `RecordDecision`/`RecordFinding`/`ListCandidateFindings`/`TriageFinding` and its own decision/finding SQLite tables, duplicating ledger concerns and entangling capture with the runner. | Those RPCs/commands and tables were removed. Execution reads the ledger through a read-only `LogLedger` seam (`[CODE: api/internal/execution/seams.go]`); the canonical `Handoff` record carries a `LogSummary` plus the run's snapshotted `LogEntries` (the proto wire `Handoff` exposes the `log_summary`), and `PhaseContext` gained `log_summary`. Completion nudges are typed + Plan-Manager-local (`record_finding`/`file_bug`/`capture_record`/`confirm_phase_status`) and point only at `plan-manager log ...`. | Revisit only if execution needs to write the ledger directly rather than read it. |
| 2026-06-27 | **The Go package is named `planlog`; the user-facing name stays `log` everywhere.** | The stdlib package `log` clashes with an internal package named `log`. | The internal package is `[CODE: api/internal/planlog/]`, while the proto package, CLI group, and docs vocabulary all use `log` ("execution log"). | None expected; rename only if the stdlib clash is otherwise resolved. |
| 2026-07-03 | **Authoring context discovery is a prompt-manager skill-pack bootstrap, not a curated candidate workflow.** | The curated context/reference batch layer duplicated prompt-manager/search-hub UX, trained agents to keep one minimal skill, and made useful context feel like paperwork. | `author skill-pack` runs `prompt-manager discover --type skill --json`, auto-upserts the returned skills as global relevant context, and prints the read command plus budget status. Search-hub is run directly by the agent/operator when docs/records/code context is useful; plan-manager stores only durable submitted context/references. Missing skill context is advisory, not a finalization blocker. | Revisit only if agents still fail to load broad skill packs by default; fix prompt-manager discovery/read guidance before reintroducing plan-manager curation. |

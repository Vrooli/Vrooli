# Decisions — Program Runtime

This document records durable decisions and tradeoffs future agents
should not accidentally relitigate.

## Purpose Of This Document

Use this document when a choice:

- affects multiple files or future agents,
- rejects a plausible alternative,
- changes architecture, deployment, data, security, monetization, or
  testing direction,
- needs a revisit trigger.

Routine implementation log entries belong in [`PROGRESS.md`](PROGRESS.md).
Known unresolved issues belong in [`PROBLEMS.md`](PROBLEMS.md).

| 2026-08-06 | Program friction feeds `gaps`/`focus next`; it is **not** a coverage projection. | 2026-08-06 | The operator console is designed as an **IDE for programs an agent wrote**, with a real code editor as its anchor. | The primary user is an agent that never opens the UI, so the console is forensic rather than task-oriented. Five surfaces become panels around one center. | 2026-08-06 | The editor's squiggles are produced by the **same** pre-flight validator the API uses to refuse a call — never a reimplementation. | An editor-side validator would be faster to build and could drift. | The editor cannot lie about what will be accepted. Stated as a design invariant rather than an implementation preference. | Never. A divergence here makes the editor actively misleading. |
| 2026-08-06 | No friction-analysis surface in this scenario's UI. The statistics surface renders **declared measures** instead. | A "Problems panel" aggregating recurring failure shapes was proposed and rejected — it would have been exactly the scenario-local analysis stack already ruled out. | Friction analysis stays in agent-manager, fed by emitted events; program detail links out to the owning run's investigation rather than reimplementing it. | 2026-08-06 | **Unbound** and **refused** are distinct concepts with distinct surfaces. | Both are "a thing an agent could not call" and were initially conflated. | *Unbound* is static registry state — a fleet capability with no typed binding (no manifest, `binding.kind: "local"`, an `omitted` RPC, external-tool-only). It renders in the binding registry and is the Act numerator. *Refused* is a runtime denial of an existing binding (`run_eligible: false`, destructive without a grant). It renders inline on the offending program line. Act cell vocabulary (`COVERED`/`PARTIAL`/`MISSING`) belongs to operation classes and is never reused for individual bindings. | The governance vocabulary in `cli-manifest.schema.json` changes shape. |
| 2026-08-06 | Operators may author and submit programs from the console, not only replay and fork. | Owner decision. The raised concern was that a second submission path carries operator identity rather than agent identity, and would pollute the corpus that feeds meta-optimization. | Accepted with a mitigation that is now `OT-P1-008`: provenance is recorded on every submission and operator-submitted programs are excluded from corpus mining by default. The corpus keeps measuring what agents attempt. | Corpus mining begins reporting shapes traceable to operator experimentation. |
| 2026-08-06 | The binding registry surface is promoted from `OT-P2-001` to `OT-P1-007`. | The whole operator UI sat at P2 (MAY). | It is the only operator surface that carries information before any program has run, and it renders the same registry state the P0 Act numerator computes — so the data exists regardless. The rest of the operator UI stays at P2. | The Act numerator ships with an adequate consumer elsewhere and this surface earns no additional use. |
| 2026-08-06 | `refine` is **not** a domain of this scenario. | Session-local harness refinement is a real capability and was considered here. | Its evidence is the run trajectory, which agent-manager owns; its durable write targets are prompt-manager and vrooli-memory. Tier-1 refine belongs with the working agent (taught by a prompt-manager skill); durable promotion follows CLAUDE.md rule 6. Recorded so `DOMAINS.md`'s "not a domain" row resolves here. | A refinement need appears whose evidence is the program corpus rather than the run trajectory. |
| 2026-08-06 | Requirement modules are grouped by **owning domain**, but requirement **IDs stay priority-based** (`PRT-P<priority>-<n>`). | The generator emitted priority-bucket modules (`01-must-ship`/`02-post-launch`/`03-future`), which is the current template default. Mature scenarios (meta-optimization-manager, prompt-manager) use per-capability modules with domain-encoded IDs. | Domain grouping gives a per-domain progress view that matches the build order in `DOMAINS.md`; priority-based IDs stay stable because they are cited from outside this scenario — `meta-optimization-manager/docs/concepts/COVERAGE-MODEL.md` and `docs/spaces/act-space.md` both name `PRT-P0-007` and `PRT-P0-008`. Taking both changes at once would have broken those references for no gain. | A requirement's priority changes, making its ID misleading — then rename deliberately and update every external citation in the same change. |
| 2026-08-06 | The Act projection is built **before** the kernel, not after it. | The original launch sequencing put Act at step 5, after handles and telemetry. | `actspace` reads `bindings` only, so the numerator is a pure read over the binding registry with no Python involved. `meta-optimization-manager` is already waiting on it with a placeholder branch in `numeratorclient.go`. Steps 1–2 become a coherent shippable slice — a governed binding registry plus a live Act projection — that converts manifest coverage from an anecdote into a tracked board number before any program has run. | The binding registry cannot resolve enough cells for a numerator to be meaningful. |
| 2026-08-06 | The thesis metric asserts **non-scaling**, not an absolute byte budget. | The requirement originally pinned context bytes for one large-result query. | A budget proves handle discipline but cannot falsify the PRD's actual claim — that context cost stops scaling with inspected volume. The replacement runs the same query across result sets differing by four orders of magnitude and asserts a constant band. It also avoids needing a tool-call baseline harness, which would have to be maintained and would rot. | The claim in the PRD changes from a scaling claim to an absolute one. |
| 2026-08-06 | Delegation uses a private session-gated bridge to agent-manager's typed workflow routes. | Manifest-bound Connect calls correctly exclude agent-manager's write/run-ineligible workflow-start command, but Phase 11 still requires a program to launch a governed workflow and collect its result. | `vrooli.agent.run(owner, workflow_key, input)` cannot reach the network directly; Go validates the live program session, supplies a replay-safe idempotency key, waits for terminal state, and returns only the explicit result projection as a handle. An unavailable or missing workflow is surfaced as a typed program failure. | Agent-manager publishes a dedicated run/delegation binding with an equivalent governance contract. |
| 2026-08-07 | Delegated examples use a terminal validator workflow and a synchronous `Handle`. | The runtime submits delegation synchronously and returns a bounded result handle; an approval-gated investigation workflow cannot provide deterministic example completion. | `delegated-run.py` exercises the governed Agent Manager bridge with `development-toolchain-validator/skill-experiment-audit`, records its structured evidence, and avoids direct network or shell access. The bridge wait request includes the execution ID required by Agent Manager's typed route. | Agent Manager publishes a stable dedicated delegation contract, at which point the example may move off the validator workflow. |
| 2026-08-06 | Typed inference is shipped through ai-gateway; delegated-run spend uses an agent-manager per-execution receipt. | The original plan deferred PRT-P1-002 to ai-gateway structured-extract promotion. That promotion and the governed classify/extract/judge facade are now live. Agent Manager now publishes a stable terminal ChargeReceipt with currency, metering basis, and measured/unmeasured semantics. | Programs fail closed when ai-gateway is unavailable, local JSON Schema validation remains authoritative, inference and delegation ceilings are durable, and delegation responses never fabricate a zero-cost claim when the upstream billing basis is unavailable. | Agent Manager preserves the explicit unmeasured receipt for provider executions that cannot be attributed to a metered charge. |
| 2026-08-06 | Use a dedicated generated capabilities message for the operational REST probe. | proto-health rejected an untyped `google.protobuf.Struct` declaration because the descriptor image only accepts scenario-owned full message names for REST payload declarations. | The capability registry output is decoded into `capabilities.DescribeResponse` and re-encoded through protojson; the endpoint remains lifecycle-friendly while its wire contract is typed and discoverable. | The capability probe becomes a Connect method with a stable service contract. |
| 2026-08-06 | Keep optional event-bus reachability in both lifecycle dependencies and the capability registry. | Scenario Dependency Analyzer requires a recovery-aware registry entry for every declared scenario dependency. | `vrooli-events` uses `try_start`, has a checker/operator action, and degrades to local persistence when unavailable; the dependency graph and runtime capability surface tell the same story. | Telemetry becomes a mandatory dependency rather than an optional enhancement. |
| 2026-08-11 | Use a local supervisor boundary instead of container isolation for the first production runtime. | Program Runtime executes trusted-local agent programs and needs a portable development path. The shipped boundary now allowlists environment, pins a mode-0700 work directory, applies Linux resource limits, and kills process groups on deadline. | The runtime is materially safer and cross-platform lifecycle-compatible, but a Python program can still import `subprocess` and reach host resources. | Untrusted or multi-tenant execution enters scope; revisit with workspace-sandbox plus container/VM isolation and a deployment contract. |
| 2026-08-12 | The kernel uses a standard-library-only, lock-derived Python environment. | Admit IPython or a general data-science package set into the kernel. | Data shaping stays in bounded `Handle` operations and governed bindings; uv/CPython 3.12 become explicit host-tool requirements and first-use provisioning adds startup latency. | A named workload cannot be expressed through the current handle vocabulary and governed bindings, and measured evidence shows the missing capability belongs in the kernel rather than a domain binding. |
| 2026-08-14 | Binding results use descriptor-selected rows plus explicit metadata/raw projections. | The prior first-list heuristic was compact but depended on JSON map order and dropped response fields. | Ambiguous repeated fields fail closed with named candidates; `Handle.meta()` and `Handle.raw()` preserve the response contract within output bounds. | A future typed response projection can prove a stronger schema-level contract without reintroducing field-order inference. |
| 2026-08-14 | Discovery retrieves only binding/library leaf types and judges only an identity-joined candidate set. | Federated default retrieval had poor recall, while score order was not a stable identity signal. | `fast` is zero-inference, `judged` uses governed `judge.default`, and `deep` has a three-query cap; unknown judge IDs and unsafe/unavailable intents return null. | A reviewed provider can supply a stronger typed candidate contract or the judged floor falls below the recorded suite floor. |
| 2026-08-14 | Library promotion is explicit, copy-on-promote, versioned, and frozen per session. | Automatically promoting successful programs would let agent experiments become ambient code and would break reproducibility. | Operators control promotion/current selection; retention preserves source copies; `vrooli.lib` exposes only current versions through the governed surface. | A separate audited promotion authority and isolation boundary is proven for multi-tenant/untrusted code. |
| 2026-08-14 | Program Runtime owns library/discovery measures as counters over typed outcomes. | Search Hub query volume alone cannot prove that a reusable program was selected or that discovery abstained safely. | Library-backed selections and null-verdict rate are visible through declared measures; provider retrieval remains a separate concern. | A durable windowed measures store becomes available and can replace process-local counters without changing the contract. |
| 2026-08-17 | Delegate Python scope analysis to `kernel/host/analyze.py` (`symtable` + `ast`) instead of resolving names in Go. | The first pre-flight resolver re-implemented Python scoping with regular expressions over source lines. It treated every name bound by a `def`, `lambda`, comprehension, `for`, `with`, or `except` as an unresolved global, so it refused ordinary correct programs before execution — including four of the eight shipped examples. | Scope analysis now matches the interpreter exactly, because it *is* the interpreter's analysis. The cost is one short-lived subprocess per submission (~40 ms) and a Python file the Go resolver depends on. Go keeps policy: it decides severity by joining the analyzer's facts against the live registry. | The subprocess cost becomes material at submission volume, or a non-Python kernel is admitted and needs its own analyzer. |
| 2026-08-17 | Pre-flight resolution is conservative: a false negative is acceptable, a false positive is not. | Refusing a correct program costs a full authoring round-trip and teaches the agent a wrong lesson; missing a diagnostic only costs a runtime error the kernel already raises with the same information. | Analyzer unavailability, a degraded result, and a syntax error all return zero diagnostics rather than a refusal. Syntax errors stay owned by the kernel so they carry the `kernel_syntax` cause instead of being attributed to name resolution. | Never. Relaxing this reintroduces the defect this rule was written for. |
| 2026-08-17 | One builtin allowlist, shared by the kernel and the analyzer (`kernel/host/safebuiltins.py`). | The kernel and the resolver each carried their own list. The kernel withheld every standard exception, so `except KeyError:` was refused, and the resolver's 17-name list flagged `round`, `type`, and `getattr`. | The lists cannot drift, because there is one. The surface now covers ordinary programming including every standard exception; `eval`, `exec`, `compile`, `globals`, `locals`, `vars`, and `input` stay withheld as an accident guardrail, not a security boundary. | A program needs a withheld builtin for a stated reason, or the trusted-local-agent posture changes. |
| 2026-08-17 | Only an unresolved *capability* is written to the unresolved-attempt ledger. | The ledger answers the Act denominator's question — what did an agent try to invoke and could not. Recording protected-name assignments, shadow warnings, Python builtins, and local variable names answered that question with names that resolve perfectly well. | `unresolved_binding_attempts` is filtered at three write paths and historical pollution is purged at startup. A language-level miss raises a plain `NameError` and is not recorded. | A consumer needs language-level miss telemetry; then give it its own surface rather than reusing this one. |
| 2026-08-17 | Nearest-match suggestions use normalized edit distance with a 0.62 floor. | The prior metric scored shared characters without order or length, so `KeyError` suggested `discover` and `text` suggested `agent`. | No suggestion is offered unless a candidate is genuinely close. A model acts on a suggestion, so a wrong one is worse than silence. | Measured evidence that the floor withholds suggestions agents would have used. |
| 2026-08-17 | Projection verbs compose governed bindings; a verb whose owner has no binding fails closed rather than opening a private client. | `recall`, `validate`, and `capture` each resolve through the same registry a program calls directly, inheriting argument validation, reachability, governance, and invocation recording. `guide` has no such path because prompt-manager exposes no resolved manifest binding. | A verb is never a second, less-governed outbound path. `guide` stays declared and reports its own unavailability, so the gap is visible instead of silently absent. `validate` reads the latest recorded verdicts because starting a run is run-ineligible and no governed binding exists for it. | prompt-manager ships a governed binding, or test-genie exposes a run-start binding with an equivalent governance contract. |

| 2026-08-17 | Every time budget on the execution path is a rung of one nested ladder, asserted at startup, with Go as the sole authority. | The budgets were independent literals in four files and two languages: the kernel gave `discover` 10s, the judge role declared 120s, its HTTP client allowed 3 minutes, and the API inherited api-core's 30s write deadline because `main.go` never set one. Nothing derived from anything. | A slow dependency now surfaces as a typed error from the innermost layer that owns it, instead of a connection severed by the outermost. `Validate()` fails the process on a violated ladder, because a runtime that reports healthy while returning `unexpected EOF` is worse than one that will not start. The kernel receives its timeouts at spawn rather than declaring them, so a second list cannot drift from the first. | A layer needs a budget the ladder cannot express — most likely a streaming response, which is not bounded by a write deadline at all. |
| 2026-08-17 | Waiting is a server-side primitive (`WaitForProgram`), not a client loop. | The CLI polled `GetProgram` every 50ms for the life of the program. It contradicted the project rule that a caller blocks once and never polls, and because it lived in the CLI, every other consumer — a workflow step, another scenario, this scenario's own authoring eval — had to reimplement it or hold a long request open instead. | One request replaces roughly twenty per second. The wait wakes on the terminal transition through an in-process broadcast, which is complete because one API process owns the runner. Exceeding the deadline returns the current non-terminal program with `terminal=false` rather than an error, so a caller resumes explicitly instead of spinning. | Program execution moves out of the API process, at which point the broadcast is no longer complete and the wait needs a durable notification path. |
| 2026-08-17 | `vrooli.` carries project commands only; the runtime verbs live exclusively at the top level. | `vrooli` was a `Namespace`, and `Namespace` implements seven of the ten verbs as methods. Ordinary attribute lookup found them before `__getattr__` ran, so `vrooli.discover` worked and `vrooli.recall` did not. Nobody chose that split — it followed from whether each verb happened to be a method or a closure. | A surface that works often enough to be learned and then fails unpredictably is worse than one that fails consistently; two of twelve authoring-eval cases failed on exactly this. `_ProjectNamespace` resolves project bindings and refuses verbs with a message naming the correct form. The verb list is declared once and the kernel refuses to start if the surface drifts from it. | Never expected. Reintroducing verbs on `vrooli.` would restore the ambiguity this removed. |
| 2026-08-17 | Discovery distinguishes "nothing serves this" from "discovery failed" as a typed field, not a reason string. | Both outcomes carry an empty `binding_id`, and the skill instructs an agent to treat an empty `binding_id` as a stop. A degraded judge therefore taught agents that the fleet had no such capability — while the discovery eval, which uses a different path, reported 42/43 and passed its floor. | `unavailable` is a proto field on `DiscoverResult` and a key on the kernel row. A null verdict is a stop; unavailable is a retry or a downgrade to `mode="fast"`. `discover` also accepts `mode`, which the skill had documented for months while the kernel hardcoded `judged`. | A third outcome appears that is neither a verdict nor a dependency failure. |
| 2026-08-17 | The authoring brief is a versioned contract checked against the other two teaching surfaces, not a Go string constant. | The brief is the harness state Prime Agent's design treats as self-modifiable. As a constant it was unversioned, unattributable, and unchecked: it never mentioned that `gather` takes zero-argument callables, so two of twelve eval cases failed on an omission rather than on model capability, and the score was partly measuring the prompt. | `internal/harness/contract.json` declares each rule once with the text the model sees and a probe that must appear in `program-construction.md` and in the skill. The brief is generated from the rules; the drift test fails when a surface falls behind, and found five such gaps on its first run. Results carry a `harness_stamp`, so two scores are comparable only when measured against the same brief. | A rule is genuinely audience-specific and belongs in one surface only — then it needs an explicit exemption rather than a silently absent probe. |

| 2026-08-18 | Accept ergonomic aliases additively and desugar fixed labels into the existing classify schema path. | The model-facing names `text=` and `binding_id=` are more likely than the canonical wire-aligned `source=` and `binding=`; fixed-label classification otherwise requires hand-authored JSON Schema. | Canonical names remain stable, aliases collide explicitly when both forms are supplied, and `labels=[...]` uses the same local validation authority as ordinary classification. No second inference role or heuristic keyword mapping is introduced. | A future generated surface can prove a stronger typed ergonomic contract without breaking these callers. |
| 2026-08-18 | Bind teaching-surface discovery intents into the primary discovery corpus and promote reviewed construction patterns before hand-authoring new ones. | A documented run-verdict query returned the wrong fast binding, and eight reviewed examples were not available through the library. | The guide, skill, and eval now share discoverable vocabulary; `lib.list()` is the first reuse path, while promoted sources remain versioned and frozen per session. | A library promotion authority or discovery corpus generator replaces the current checked-in review process. |
| 2026-08-18 | Use one fleet-wide receipt aggregate for Exercise and retain the local invocation ledger only for per-program provenance. | Per-owner synthetic or program-only counts cannot establish whether the fleet calls a capability, and a per-scenario RPC fan-out caused condition reads to hit their deadline. | `vrooli-events` owns the durable receipt aggregate and declared measure; Program Runtime makes one aggregate read per condition window, maps observations to binding legs, and reports verified caller counts beside unattributed remainders. | Receipt retention or query volume requires a materialized aggregate, but the owner and semantics remain unchanged. |
| 2026-08-18 | Publish Act reachability basis fields through the meta-optimization projection. | The numerator changes with host reachability, so a ratio without its manifest and reachability basis conflates supply with runtime state. | Program Runtime returns manifest, total, reachable, unreachable, and probe timestamp fields; the meta projection carries the same values for board consumers. | The Act model changes its denominator or adopts a durable fleet inventory snapshot. |
| 2026-08-18 | Preflight persistent session names from prior submitted programs. | A session-persistent kernel correctly retains `prior_result`, but a stateless preflight resolver rejected it before execution and made session reuse impossible. | The analyzer reports module bindings; the service adds names from the session's prior submissions to the conservative known set. Execution remains authoritative if a prior assignment did not actually survive. | Execution moves to a separate process or a durable variable store, requiring a new state-introspection seam. |
| 2026-08-18 | Keep grouped counts integer-compatible while adding bounded per-group `count()`, and accept `join(on=)` additively. | Models naturally write `groups[key].count()` and `join(..., on="id")`; changing the existing dict/int or canonical `key=` shape would break callers. | `GroupedCount` subclasses `int`, and `Handle.join` rejects simultaneous `key`/`on` rather than choosing silently. | A generated typed kernel surface replaces these Python compatibility affordances. |
| 2026-08-18 | Authoring oracles must consume declared result fields, not any non-empty output. | The original evaluator ignored `value`, `relation`, `key`, and `cause` fields and could report success for arbitrary output, making its floor meaningless. | Oracles now compare declared text/count/key/cause semantics; caught typed failures accept only their canonical human error phrases. Corpus version 3 makes required inputs and outputs explicit. | A typed result oracle protocol replaces the bounded stdout adapter. |
| 2026-08-18 | Fast discovery rejects weak lexical matches with a null verdict. | Search Hub returns a 0.25 catch-all hit for unrelated intents; selecting it as a capability is worse than saying nothing because fast mode has no judge to recover. | A 0.5 score floor preserves reviewed exact/alias matches while returning `fast.null` for the catch-all. | The provider publishes a calibrated confidence contract with a stronger threshold authority. |
| 2026-08-19 | A control-plane binary refuses a runtime registry newer than its supported schema, and the Connect status path exposes that refusal as an actionable precondition. | Schema 8 added start-operation provenance and supervision semantics. The old schema-7 root API returned an opaque HTTP 500 while the freshly rebuilt CLI succeeded, tempting callers to relax an intentional storage-safety guard. | The guard remains strict and is represented by `scenarioruntime.SchemaCompatibilityError`. `GetScenarioStatus` maps it to Connect `failed_precondition` and instructs the operator to rebuild and restart through `vrooli develop`; current binaries read normally. | A versioned compatibility contract proves older writers safe for every semantic change, or the root API gains automatic zero-downtime replacement on source/schema skew. |

# Inactive finite broker and confinement decision

7 November 2026. The selected implementation direction is a separate trusted finite broker and a network-denied worker. The broker operation core and native receipt/service-admission ownership components are implemented and offline-tested; canonical finite owner adapters and collector-terminal retirement are implemented but unregistered. An inactive Linux anonymous-pipe transport component now exists (see PRIVATE-IPC.md); the actual confined process, production joined transport and live authority do not. See [the ownership continuation](OWNERSHIP.md) for exact implemented boundaries and remaining gates. Program Runtime main remains default-disabled, with no provider/runner. This work changes no live API authorization, anonymous callers, credentials, grants, network/security settings, subscriptions, services or deployment.

## Decision and threat boundary

Generic Events routes remain anonymous, and Program Runtime authentication remains passive. A worker with access to those routes can omit a bearer. Giving that worker a narrow token does not confine it. Changing all existing owner ingress would affect user/CLI callers and active services, so it is not the default continuation path.

The chosen boundary treats the worker and its requests as untrusted. A small, immutable trusted broker retains source authority and exposes only named operations. The worker must be unable to reach generic owner APIs or read broker credentials, even after arbitrary code execution inside the worker. The broker is part of the trusted computing base; compromising its executable or owner adapter is outside the claim. This is not a proposal to grant business-data operations to the root privilege broker.

The old Python `OwnerClient` and `ProcessRunner` remain unchanged and unconnected to this core. They still expose source credentials to Python and use loopback networking. They do not meet the selected confinement boundary. Neither `SealedProvider` mount checks nor this core create kernel isolation, and neither may be described as closing the anonymous-route bypass.

## Implemented inert slice

`api/internal/localworkbridge/source_broker.go` provides `NewSourceBroker` and `Execute`. It has no listener, socket, subprocess, filesystem storage, secret discovery, issuer, environment activation flag or production registration. Disabled construction/execution touch no dependency. Enabled construction only validates supplied trusted wiring; it is not confinement proof.

A 4 KiB maximum request has schema `flywheel.local-work-source-broker.v1` and exactly one operation:

- `read_event`: exactly `schema`, `operation`, `event_id`. The ID must occur in the trusted SourceGate selection, at most 64 IDs.
- `observe_collector`: exactly `schema`, `operation`.
- `admit_collector`: exactly `schema`, `operation`.
- `wait_collector`: exactly `schema`, `operation`, `program_id`, `timeout_ms`, with a wait from 1 to 90,000 milliseconds.

The worker cannot supply URLs, methods, headers, credentials, source code, collector names/digests/inputs, policy, caller attribution, grants, request keys or admission deadlines. Unknown/duplicate fields, aliases, extra JSON values, excessive depth and changed shapes fail before credential access. Requests are reconstructed through the existing canonical SourceGate parser and verifier. The two gates must share owner, subject, commissioned source instance and epoch, with distinct source bindings.

One trusted `SourceBrokerSelection` pins the durable collector request key and fixed admission deadline. The existing declared-admission owner remains responsible for idempotency. All observe/admit calls use that same pair, and wait results must belong to that same retained key. This prevents a compromised worker from inventing new keys to repeatedly admit the same selected snapshot. The trusted selection owner must retain the pair with the exact selected event set across restart; a new launch generation must not mint a new attempt. The config object is not proof that this durable owner exists.

Credentials are requested lazily for only `events_reader` or `runtime_collector`. They go only to the canonical verifier, never worker responses or the owner adapter. Returned buffers are cleared. Transient Go string copies are not guaranteed to be erased; stopping/joining the broker and cleanup of authority leases remain necessary. A broad bearer with narrow metadata is still forbidden and fails the existing source checks.

The fence receives the exact owner, subject, source instance/epoch, launch generation, both policy digests and selected request key/deadline. It runs before credential access. The broker also installs it into the owner's `SourcePermit.Recheck`, which runs the fence before a fresh authority/expiry read. This order prevents a slow fence from extending grant validity. Owner final admission/read checks must serialize with both session invalidation and source-authority changes. A precheck followed by an unrelated commit is not sufficient, and a post-call failure cannot undo an admitted execution.

Finite owner methods receive the permit, not raw HTTP, bearer headers or worker JSON. Event identity is derived from the actual bounded canonical envelope and checked before normalized result bytes are returned. Duplicates at every JSON depth, mismatched ID/type/source, oversize results and multiple/trailing values fail closed. A missing canonical event returns an explicit empty result, not invented occurrence data.

Collector results require an owner-retained identity matching declaration/digest, owner/subject, binding/version, policy, selected request key and program ID when waiting. Responses are reconstructed from finite fields. Raw program source, stderr, arbitrary owner fields and caller attribution are not in the result contract. Only successful collector stdout is released, at most 64 KiB. Missing admission is explicit; failed/running programs cannot release partial stdout.

Execution is serialized with no unbounded queue, automatic retry or goroutine that abandons owner work. Cooperative calls have an overall 100-second maximum, bounded further by token expiry, the fixed admission deadline where applicable, the caller deadline and the requested wait duration. Final release rechecks current session and authority. An uncooperative owner/fence/provider is an availability failure; caller lifecycle must cancel and join it before replacement. Direct Execute still returns bytes without transport. The inactive SourceTransport path retains the permit through bounded pipe writes under an explicit release-owner boundary. Production transport-time revocation and delivery still require the actual joined owner; partial bytes cannot be retracted and strict kernel-write expiry is not qualified.

## Ownership and remaining engineering gate

1. **Control-plane lifecycle owner (`internal/`)**: prepare the reviewed immutable broker/worker runtime closure and dedicated identities, then implement the joined launch fence and private transport. Provisioning kernel/network/security state requires action-time approval. The worker must have no generic network escape: IPv4/IPv6/loopback, Unix pathname or abstract sockets, inherited connected sockets, proxy helpers, alternate namespaces, mount access to host sockets, proc/ptrace/credential-FD access and privilege regain all belong in adversarial qualification. A different network namespace or `seccomp` mode number alone is not proof. Use a reviewed deny boundary, exact descriptor allowlist, no capabilities, NoNewPrivs and the prior immutable mount/storage constraints. No filter, mount, namespace or UID has been installed by this slice.
2. **Native local-work receipt owner**: the inert Go owner now authenticates receipts before storage, retains exact source/epoch/type, and durably binds one selection to its request key/deadline across restart. Broker permits enforce its exact authenticated event identities. Production key provenance/custody, joined native authority guards and inaccessible storage still require implementation/qualification. Collector-terminal retirement and later batches now use immutable gate bindings and tombstones; cloud delivery and pruning remain separate. The worker-writable outbox cannot attest authority. See [ownership details](OWNERSHIP.md).
3. **Events owner**: provide canonical selected-record reads through the finite owner adapter and current authority rechecks. Do not substitute a generic anonymous HTTP wrapper.
4. **Program Runtime library/program admission owner**: service owner, subject, binding/version, policy and request key can now be inserted atomically into the existing durable admission row, with immutable ownership on Save and checked replay/read/wait. The final composite boundary is an explicit trusted callback contract, not a production lock implementation. Finite admit/observe/wait adapters, archived source/input resolution and canonical one-shot-session wiring now exist as inactive components. Actual source-authority and lifecycle composition still require qualification. No second execution ledger or fabricated verified-agent identity is introduced. Existing generic user/CLI routes preserve their behavior.
5. **Scenario Authenticator / credential authority**: supply real exclusive-purpose verification, live approved binding/revocation lookup and cancellation-cooperative custody/delivery. No authority is minted or installed here.
6. **Bridge host/worker integration owner**: replace the old credential pipe and direct Python network access with the reviewed finite operation transport. Native HMAC verification and cloud signing/egress also must stay outside a credential-free, network-denied worker. This source-only core does not implement those operations or a generic sign/request escape. Keep fixed cloud destination, narrow reviewed projection, output limits and existing pause/mute/permission/checkpoint holds.
7. **Qualification owner**: test a joined real launcher, immutable runtime, private transport, native selection, owner transaction and revocation path before activation. Attempt credential omission and generic API access from the actual worker, not a mocked denial. Exercise restart, concurrent invalidation/commit, expiry during waits, lost responses, replay, inherited descriptors, IPC backpressure and stop/join. Then separately prove the source-to-cloud-to-handler reconciliation/readback chain and two later separated authorized changes.

The next engineering gate is production joined authority, lifecycle recovery proof, owner composition, fence and private transport, building on the inert canonical adapters and durable selection retirement. Action-time approval for isolation, persistent access/capability creation/placement, subscriptions, service enablement/deployment and named transmissions comes before provisioning, not instead of these missing implementations. Owner-wide mandatory auth remains an alternative requiring a separately reviewed compatibility migration, not a hidden fallback.

## Qualification evidence

Evidence is retained at `.vrooli/evidence/local-work-bridge-20261106/broker-confinement-20261107/`. The suite uses fixture credentials and in-memory owner/fence adapters; no live source/cloud call or network-denied process is claimed. Checks and exact counts are summarized there. Existing protobuf freshness failures from the earlier source-policy qualification remain a separate unclosed repository prerequisite; this slice edits no generated artifacts or shared authentication configuration.

Independent review found and repaired: the missing owner-facing session fence, the requested wait not bounding owner context, and a slow fence crossing grant expiry. Additional adversarial regressions reject worker-controlled request keys/deadlines, wrong retained program identity, malformed/oversize event responses, source revocation and concurrent operation admission. These prove the inert component contract, not deployed least privilege or a passing full scenario gate.

Work-ladder scope: W3 continuation of the established disabled bridge contract in SOURCE-POLICY.md. This document and retained check evidence are the active workflow record; unrelated W0-W2 or scenario-wide readiness gates are not claimed.

# Disabled local-work adapter candidate

Status: disabled implementation candidate, 7 November 2026. See [managed integration and recovery](MANAGED-INTEGRATION.md) and [private process boundary](PRIVATE-IPC.md). **Not activated, deployed, or production-certified.** The existing Program Runtime main now registers an inert route and cleanup hook. No production binding provider or enablement is installed. The finite Python entry point has no listener, daemon, subscription registration, environment-variable lookup or ambient credential discovery. Importing the library does not open storage or transmit data.

This is a bounded continuation of the independently reviewed prototype in `.vrooli/evidence/local-work-bridge-20261106/event-bridge-prototype-20261107/`. The v2 collector remains authoritative at `scenarios/program-runtime/.vrooli/program-runtime/local-work-snapshot.{json,py}`. No collector or native work owner is replaced. Source code lives here rather than importing mutable research/evidence files at runtime.

## What the component does

1. `accept_native` verifies the actual native webhook's HMAC over exact bytes and both event identity headers, then, for in-scope events, commits only event identity, a payload digest and receipt time to SQLite before returning. Authenticated events outside the exact allowlist are explicitly ignored with 204 and no storage access; that status alone is not proof of queued work. Raw event data, titles, paths, prompts, credentials and error details never persist in its queue. The existing native fleet key is injected only by the future approved local host; it must never be copied to the cloud.
2. `qualify_event` requires a canonical event with the exact native event ID, source and type. The existing Events API supports `GET /api/v1/events?event_id=<exact ID>&limit=2`; the host resolver must require exactly one canonical envelope. Missing canonical retention is a durable gap. Webhook `delivered_at` is not an event occurrence time and is never substituted for one.
3. `collect_once` is a bounded host-injected cycle, not a running scheduler. A durable 300-second generation-fenced lease prevents concurrent workers from collecting the same work and manufacturing retry failures; a stale worker cannot overwrite the new owner. The managed host must impose a whole-cycle timeout below 300 seconds. It resolves at most 64 pending identities, observes the 60-second quiet / 300-second maximum coalescing window, and calls the existing v2 collector once only when selected events are due. Failures retain their events and persist backoff; five failures require explicit repair. The caller must not pass general shell commands or source-provided arguments as callbacks. The collector uses separately fixed, approved scope.
4. `prepare` freezes the strict minimal wake projection and SHA-256 batch identity atomically. Runtime success stays distinct from the collector's intentional partial domain state. Producer freshness is classified as of snapshot `finished_at`, not a later staging or retry time; the snapshot itself must still meet its age bound. Fresh retrieval does not freshen old producers. Unknown, unavailable, stale, truncated and permission states remain explicit. Permission holds survive subsequent clean reads. No new event means no new snapshot-driven wake. A distinct native event is not suppressed merely because a bounded sample looks unchanged; doing so could lose changes outside that sample.
5. `export_once` requires a currently enabled, owner-supplied runtime grant and an injected dedicated 32-byte signing key. Default grant and allowlist are disabled. It sends at most once per invocation, with the exact HTTPS origin/path, no proxy/cookie/session/redirect fallback, a 10-second HTTP timeout and 8 KiB response bound. Actual network transport is optional and was never invoked in qualification. Requests sign the fixed agreed v1 protocol; retries retain identical body bytes and batch ID while refreshing request timestamp/signature.
6. Dispatch leases, attempt count, next due time and transport receipt survive restart. A crash during dispatch is an uncertain outcome and retries the frozen request only after its lease. At most five attempts occur. Retry-After is persisted and respected; invalid or over-one-day advice holds. Redirects, permission failures, disabled endpoint, stale/invalid payloads, identity conflict and capacity limits hold instead of dropping data or silently switching routes. An acknowledgment means transport persistence only, never actual handler pickup, useful reconciliation, accepted work or native authority.

## Native contract and selected coverage

The source-code-confirmed candidate allowlist is exactly:

- `agent-manager` / `agent_manager.run.notification.v1`
- `agent-manager` / `agent_manager.run.decision_requested.v1`
- `agent-manager` / `agent_manager.run.decision_withdrawn.v1`

These are candidate scope, not registered subscriptions. A separate approval must authorize these exact sources/types. The first is terminal complete/failed run notification; the second is a needs-review request; the third withdraws a prior review request. None proves outcome acceptance. Publishing is best-effort and does not block the native run transition. The reviewed source explicitly says a missing publisher or publish failure can leave no event. This adapter therefore cannot claim complete reliable capture of all native activity.

Run start/progress, finite/standing team boards, Swarm local eventlog changes and research edits do not currently have verified durable event coverage in this allowlist. The v2 snapshot can sample them after a selected trigger but does not make them continuously covered. Prompt Manager heartbeat attempts and generic Program Runtime invocation receipts are deliberately excluded because they are noisy or could feed back. The prototype's `agent-manager.run.completed.v1` was synthetic and is not admitted by this candidate.

The native subscription guide's example has drifted from implementation. Actual source is `scenarios/vrooli-events/internal/subscription/webhook.go` plus `api/subscription_dispatch.go`: body keys `event_id`, `event_type`, `source_scenario`, `payload`, `delivered_at`; headers `X-Vrooli-Events-Signature`, `X-Vrooli-Events-Event-ID`, `X-Vrooli-Events-Idempotency-Key`. Signature is `sha256=` plus lowercase hex HMAC-SHA256 over raw body bytes. The inner payload is not necessarily the original event envelope and can be encoded protobuf data. Do not implement from the guide's camelCase example.

## Continuity, retention and privacy

SQLite uses full synchronous transactions and a private owner-only directory and regular file. New files are created mode 0600. Existing symlinks, hard links, shared files/directories, unrelated SQLite application IDs and changed policy/source epoch are rejected. The allowlist is immutable after construction. Queue metadata never treats maximum observed event ID, delivery time or a later event as proof of prior coverage.

Every new outbox starts with `unknown_checkpoint`; this cannot be silently cleared. Retention loss, replay limits, dropped events and source reset are durable holds. There is no automatic delete/prune, reset, policy migration, hold clearing, key rotation or recollection of already frozen batches. Capacity is bounded at 10,000 event identities and 64 events / 64 KiB per request. Reaching capacity requires a reviewed transition, not resetting the database. An event identity/body conflict globally stops preparation/export until reviewed. Source epoch is a local configuration guard, not a claim that the destination has verified a machine identity.

The outbound schema is unchanged `flywheel.local-work-wake.v1`, including `activation: not_approved` and `effect_authority: none`. Those are observations' authority labels, not the transport enable switch. It carries only identity/type/source/time and content digests, v2 collector provenance/digest/time and bounded status/freshness/coverage summaries. Hashes expose equality and correlation and can permit guessing; they are not anonymization. Rich source content still requires a separate authorized source read. No local/cloud one-to-one work mapping is inferred.

- Supply and review the concrete approved binding provider for the implemented Program Runtime lifecycle and private receiving route. It must name the immutable prepared CPython 3.12 runtime/module bundle, private storage root, configuration/module/lock digests, fixed collector scope and credential authorities. A digest freshness check is not runtime provenance or protection against concurrent replacement. The provider must cooperate with cancellation and may not discover incidental credentials. Secure native key access stays in its existing authority.
- Review source durability gaps. For genuinely comprehensive event capture, add a durable material-change publication seam owned by each native source, or explicitly qualify narrower terminal/review coverage. Do not replace missing source events with unlabelled periodic polling.
- Establish a reviewed starting checkpoint/baseline and explicit recovery/retention transitions. Confirm storage location, lifecycle shutdown/recovery, collection timeout, rate, concurrency and source reset semantics with that owner.
- Verify private Site access permits the dedicated route without reusing browser cookies, user OAuth/session tokens, the Events fleet key or general MCP credentials. Match the server-bound owner/source/type allowlist, signing key ID, expiry and exact destination.
- Obtain action-time approval before creating/configuring the dedicated credential, expanding persistent access, creating subscriptions, starting/installing the adapter, enabling/deploying ingress or sending any data. No such change occurred in this task.
- Then exercise named synthetic and real source changes through native event → durable queue → cloud receipt → existing Flywheel journal → actual handler pickup → useful many-to-many source-backed reconciliation → readback. Test interrupted delivery, duplicate/reordered events, outages, denied/revoked access, retained-event loss, stale producer evidence, pause/mute and key expiry. Two separated later authorized changes without manual pickup are the minimum recurring trial, not a completeness guarantee.

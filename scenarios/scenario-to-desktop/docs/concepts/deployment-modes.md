# Deployment Modes & Server Types

Use this to pick the scenario deployment mode before generating desktop builds.
It does not by itself prove that every resource dependency is portable. Resource
target selection, host requirements, degradation, and artifact delivery follow
the [resource deployment contract](../../../../docs/resources/deployment-contract.md).

## Deployment Modes
| Mode | Purpose | When to use | Bundling | Requires Proxy URL |
|------|---------|-------------|----------|--------------------|
| `bundled` **(Recommended)** | Desktop app with bundle-ready scenario services and selected resources | **Default when dependency readiness passes** | Yes | No |
| `external-server` (Thin Client) | Desktop shell talks to a running Vrooli server | When connecting multiple users to shared backend | No | Yes |
| `cloud-api` (stub) | Future: packaged cloud-friendly API generated by deployment-manager | Do not use yet | Planned | No |

## Server Types
| Server Type | What it does | Typical target | Notes |
|-------------|--------------|-----------------|-------|
| `bundled` | Runtime supervisor manages all services inside the app | **Recommended** - full offline capability | Most stable for end users |
| `external` | Points UI/API to an existing server URL (LAN or Cloudflare) | Thin clients | Requires running server |
| `static` | Ships only the built UI assets | Static-only scenarios | No API proxy; good for SPA utilities |
| `node` | Runs a bundled Node entrypoint | Node microservices | Ensure ports/env are configured |
| `executable` | Spawns a packaged binary | Go/Rust/other binaries | Health/port checks required |

## Quick Decisions
- **Desktop app for end users?** Use `deployment_mode=bundled` (default) - complete offline experience
- **Shared server backend?** Use `deployment_mode=external-server`, `server_type=external`, provide proxy URLs
- **UI-only utility?** `server_type=static` with a built `ui/dist`
- **Custom runtime?** `server_type=node|executable` with proper port and health configuration

## Bundled Mode (Recommended)

The bundled mode creates a complete offline desktop application:

```bash
# Create deployment profile
deployment-manager profile create my-profile my-scenario --tier 2

# Build bundled desktop app
deployment-manager deploy-desktop --profile my-profile
```

This currently handles:
- Bundle manifest generation with dependency swaps
- Cross-compilation/staging of scenario service binaries for target platforms
- Signed checksum verification and staging of resource artifacts selected by
  `deployment.profiles.desktop` into `resource-deployment-plan.json`
- Electron wrapper generation with runtime supervisor
- Platform installers (Windows/macOS/Linux)

Before a bundled build can claim portability, the deployment pipeline must also
resolve every required resource for the requested OS/architecture. The target
result is `ready`, `warning`, or `error`: a Docker Desktop requirement is a
warning/conditional path, a declared fallback may permit degradation, and an
unsupported required resource is a build error. Supply a signed Vrooli release
directory through `resource_artifact_root` when a required profile uses a
`bundled-*` mode; the bundle stage rejects source builds and unsigned or altered
artifact inputs.

## Thin Client Mode

Use thin client when users connect to the same server. Configure the external
server URL and deployment mode in the UI, then start the packaging pipeline:

```bash
scenario-to-desktop pipeline run "my-scenario"
```

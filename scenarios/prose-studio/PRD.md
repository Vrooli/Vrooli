## 🎯 Overview

- **Purpose**: Own the production path from a query plus a named writing style to a measured set of candidate outputs, plus the tooling to converge that set to one committed document. The permanent capability is a versioned style and profile system configurable entirely as data, two independent diversity mechanisms whose effect is measured rather than assumed, a selection layer that separates a deterministic quality floor from a choice made by rarity or coverage rather than taste, and long-form composition that builds a document from converged sections. It is the difference between asking a model for text and being able to ask for the same voice again in six weeks, know how varied the alternatives were, and prove which one shipped and why.
- **Primary users/verticals**: Other Vrooli scenarios first - content-desk drafting marketing copy against declared voice profiles, asset-studio and document-manager needing styled text, test-data-generator needing diverse synthetic corpora, signal-inbox and source-ledger needing summarization. Second, the human operator composing and converging a document directly. Third, any coding agent calling one bounded RPC and receiving a single decided result with a receipt.
- **Deployment surfaces**: Connect-RPC API as the primary contract, a generated CLI with full verb parity and JSON output on every verb, a React and Vite operator UI built around four surfaces, declared agent tools and widgets for conversational use, and a shared Go package for deterministic text metrics consumable with no runtime dependency on this scenario.
- **Value promise**: Makes varied, on-voice writing systematic instead of prompted. One style record yields consistent voice across every consumer that references it; a candidate set makes the alternatives visible and measurable instead of discarded silently; selection by rarity or coverage means the system does not quietly converge on the most typical phrasing; and because every style and profile is a data record owned by the scenario that uses it, a team changes its own voice by editing a file rather than by asking for a deploy.

## 🎯 Operational Targets

> Checkboxes auto-update from requirements sync; do not hand-edit them.

### 🔴 P0 – Must ship for viability

- [ ] OT-P0-001 | Style record and resolution | The system shall persist styles as versioned records carrying exemplars, directives, anti-patterns, lexicon, targets, and axis defaults; shall support single-parent extends with write-time cycle detection; shall merge by declared order without silently widening a target; and shall report a named resolution conflict identifying both contributing versions when merged targets have an empty intersection
- [ ] OT-P0-002 | Style version immutability | The system shall freeze a style version the moment a committed output references it, shall refuse mutation by name, and shall direct the caller to create a new version
- [ ] OT-P0-003 | Text conformance reporting | The system shall validate arbitrary text against a style and return targets met or missed plus anti-pattern hits located by span
- [ ] OT-P0-004 | Profile record and inspectable resolution | The system shall persist generation profiles as versioned records covering style references, sampler, constraints, selection policy, measurement tiers, budget, and gateway role, and shall return both the fully merged effective configuration and the exact instruction text that will be sent, before sending it
- [ ] OT-P0-005 | Introspectable kind registry | The system shall expose sampler strategy kinds, selection policy kinds, transform operations, and metrics through a registry returning each kind parameter schema, so a client renders a form for a kind it has never seen without a redeploy
- [ ] OT-P0-006 | Sampler strategies | The system shall ship a direct strategy and a verbalized-distribution strategy, carrying candidate count, probability threshold, and temperature stance as profile data rather than as code
- [ ] OT-P0-007 | Candidate provenance | The system shall record per candidate the profile version, style versions, strategy and parameters, provider, resolved model reference, that model declared context window, gateway role, temperature sent, temperature support, effective maximum output tokens and their source, token usage, and cost
- [ ] OT-P0-008 | Whole-set cost attribution | The system shall attribute the full cost of a round across the entire candidate set and never solely to the committed candidate
- [ ] OT-P0-009 | Uncalibrated hint containment | The system shall store the model verbalized ordering signal with a constant uncalibrated marker scoped as an ordinal within its own round, and shall enforce by static check that no selection policy or query reads, aggregates, averages, or thresholds it
- [ ] OT-P0-010 | Deterministic measurement at birth | The system shall compute the deterministic metric tier unconditionally when a candidate is created, per candidate and per set, covering compression ratio, self-repetition, lexical homogenization, distinct-n, burstiness, three readability grades, type-token ratio, and lexicon flags
- [ ] OT-P0-011 | Constraint gating that retains | The system shall evaluate hard constraints deterministically, mark violating candidates ineligible with a named reason, and retain them in the set rather than dropping them
- [ ] OT-P0-012 | Selection policies and defaults | The system shall ship first-eligible, uniform-random, rarest-above-threshold, least-redundant-continuation, coverage, and human-pick policies; shall default agent mode to rarest-above-threshold and human mode to coverage; and shall use first-eligible only as a measurement control
- [ ] OT-P0-013 | No taste-based ranking | The system shall ship no judge-based ranker at any priority, and an inferential judge may act only as a pass or fail gate
- [ ] OT-P0-014 | Session as append-only history | The system shall model a session as an append-only graph of rounds and candidates linked by derivation, mutating no record in place, and shall support generate, reroll, pin, unpin, reject, refine, commit, and abandon
- [ ] OT-P0-015 | Reroll with negative conditioning | The system shall regenerate only unpinned slots on reroll and shall condition explicitly on the pinned and rejected sets
- [ ] OT-P0-016 | Single-call agent path | The system shall expose a single-call generate verb returning one policy-decided result with candidates included only on request, implemented as a wrapper over the session path rather than as a second code path
- [ ] OT-P0-017 | Machine-generation disclosure | The system shall carry machine-generation provenance on every candidate at birth as a constant, and shall frame no target, verb, or interface copy in terms of a detector score
- [ ] OT-P0-018 | Selection recording without learning | The system shall record a selection event for every commit with measurements snapshotted at choice time and the considered candidates retained, and nothing in this version shall read it
- [ ] OT-P0-019 | Long-form composition level | The system shall take candidate sets at the outline level and the section level, shall not offer whole-document candidate sets, shall represent an outline as an ordinary candidate so outline variation reuses the sampling and selection stack, and shall give each section a full passage-level session
- [ ] OT-P0-020 | Section context and budget | The system shall resolve a section profile by inheritance from its document, shall assemble section context from the outline, the committed text of prior sections, the declared intents of following sections, and the resolved profile, shall cap accumulation through a declared context policy, and shall record a context snapshot per section naming what it carried and what was summarized
- [ ] OT-P0-021 | Feasibility before work | The system shall perform a static context-feasibility check at profile-validation time against the profile worst-case section, refusing a profile whose ceiling exceeds the resolved model declared context window, and shall perform a dynamic pre-call check per section
- [ ] OT-P0-022 | Document coherence and assembly | The system shall measure cross-section repetition and per-section style conformance, shall report style drift across a document, shall assemble a document as ordered text plus structure, and shall render to no presentation format
- [ ] OT-P0-023 | Gateway-only inference | The system shall route all inference through ai-gateway, naming no model, holding no credential, and calling no vendor directly, and shall derive and send maximum output tokens per request from profile data rather than relying on a role default
- [ ] OT-P0-024 | Comparability enforcement | The system shall treat two candidate sets as comparable only when their effective sampling keys and their effective maximum-output-token values and sources match, enforced in the measurement layer rather than by convention
- [ ] OT-P0-025 | Consumer-owned declarations | A consuming scenario shall declare styles, profiles, and axis spaces as version-controlled files in its own scenario folder with a namespaced key and an ownership marker, and the system shall register them by startup scan plus an explicit reindex verb requiring no integration code from that consumer
- [ ] OT-P0-026 | File-as-authority | The system shall treat a declaration file as authority and its database row as a projection, shall refuse API writes to a declared record naming the file, shall version a declared record by its file content hash, shall register a malformed declaration as invalid without preventing startup, shall refuse two declarations claiming one key rather than resolving last-writer-wins, and shall mark a deleted declaration unregistered while keeping historical provenance resolvable
- [ ] OT-P0-027 | Standalone declaration validator | The system shall expose the declaration validator over RPC and as a CLI verb so a consumer can check its declarations without invoking the test harness
- [ ] OT-P0-028 | Programmatic surface | The system shall expose Connect-RPC with full CLI verb parity and JSON output on every verb, and shall declare its tools and widgets with governance metadata so they are discoverable rather than merely present in code
- [ ] OT-P0-029 | Operator surfaces | The system shall ship a variation board, style library, document workspace, and declaration registry as production-quality UI with real loading, error, and empty states, shall show no per-card quality score, shall apply no default ordering by a quality proxy, shall state set diversity as one number with its basis named, shall make none-of-these a first-class action triggering a reroll with negative conditioning, and shall state the specific reason inline on every disabled control
- [ ] OT-P0-030 | Shared metrics package | The system shall publish its deterministic text metrics as a shared package created from the first commit, consumable without a runtime dependency on this scenario API
- [ ] OT-P0-031 | Document shape is declared, not constant | The system shall derive a document's section count from a declared composition policy or an explicit per-document override, and shall fix no section count in the outline prompt, the outline decoder, or the evaluation harness
- [ ] OT-P0-032 | Section length band and declared format | The system shall gate every section against both a floor and a ceiling derived from its outline target so a section that materially undershoots its target is ineligible, and shall apply the profile's declared section format rather than forcing a format that forbids headings, lists, or code
- [ ] OT-P0-033 | Sections see their committed predecessors | The system shall carry the committed text of prior sections into each section's prompt and its recorded context snapshot, shall state the continuity requirement alongside that text, and shall derive the prior-context token budget independently of the output cap
- [ ] OT-P0-034 | Continuation selection | The system shall select a section candidate by least redundancy against already-committed text and closeness to its outline target, shall not select a section by distance from its own siblings, and shall keep that selection a deterministic measurement rather than a judged ranking
- [ ] OT-P0-035 | Coherence failure causes work | The system shall regenerate the most redundant section under negative conditioning while a declared repair budget remains, shall rewrite that section in place rather than appending one, and shall report the honest failed verdict when the budget is exhausted
- [ ] OT-P0-036 | Semantic document coherence | The system shall measure semantic cross-section repetition over section embeddings alongside the lexical measure, and shall report the measurement as unavailable rather than as a pass when the embedding tier cannot be reached
- [ ] OT-P0-037 | Whole-document provenance | The system shall report the cost, tokens, providers, and models that an assembled document actually consumed across its outline, section, and repair requests
- [ ] OT-P0-038 | Long-form survives a single bad provider response | The system shall re-ask the provider for a failed long-form step within a declared attempt budget, shall not re-ask when the failure is a caller-side defect that would yield the same answer, shall drop a repeatedly undecodable candidate envelope to a direct draw on its final attempt, and shall degrade a failed summarising call to a recorded deterministic excerpt rather than discarding an otherwise complete document
- [ ] OT-P0-039 | Document discovery and reading | The system shall enumerate generated documents newest-first with a bounded, status-filterable listing, shall return one document with its prose, outline, coherence, and provenance by identifier, shall expose both over Connect-RPC and as CLI verbs with typed flags rather than a raw request payload, and shall render them for a reader rather than as a serialized message

### 🟠 P1 – Should have post-launch

- [ ] OT-P1-001 | Axis spaces and specified diversity | The system should ship axis space records, cell planning, axis-cell coverage binning, and a composite sampler that bins by axis cell then samples within a cell, so that set diversity is guaranteed by construction rather than only measured
- [ ] OT-P1-002 | Declaration conformance phase | The system should ship a test harness phase that validates a consuming scenario declarations when that scenario own suite runs, with a gated maturity ladder whose every rung declares a capability summary, whose every non-top rung declares its next unlock, and whose findings declare a clean requirement so a phase emitting nothing cannot report maximum maturity
- [ ] OT-P1-003 | Style learning from edits | The system should propose a new exemplar or anti-pattern from the difference between a generated candidate and the operator edited commit, for explicit confirmation, so the system learns the style without learning a preference ranking
- [ ] OT-P1-004 | Inferential measurement tier | The system should offer an optional judge-based conformance gate returning pass or fail against declared constraints, never a rank
- [ ] OT-P1-005 | Transform operations | The system should expose reading-level, elaboration, and simplification transforms as first-class typed operations with recorded provenance
- [ ] OT-P1-006 | Reasoning-first sampler | The system should ship a reasoning-first sampler variant for cases where candidate quality benefits from explicit deliberation before enumeration

### 🟢 P2 – Future / expansion

- [ ] OT-P2-001 | Configuration bandit | The system may learn over durable configurations such as profiles, strategies, threshold values, and style versions using a binary per-round signal of whether anything was committed, never a per-candidate preference, and constrained to configurations whose measured set diversity clears a floor
- [ ] OT-P2-002 | Outcome-driven scoring | The system may score candidates from measured external outcomes once publish or conversion telemetry exists, joined through a reserved outcome reference on the selection event
- [ ] OT-P2-003 | Semantic diversity metrics | The system may add embedding-based semantic diversity alongside the lexical tier once an embedding surface is available through ai-gateway
- [ ] OT-P2-004 | Whole-document variation | The system may offer document-level candidate sets once cost and review burden are understood from real section-level usage
- [ ] OT-P2-005 | Consumer axis-space migration | The system may accept an existing axis space from another scenario once that scenario chooses to migrate

## 🧱 Tech Direction Snapshot

- **Preferred stacks / frameworks**: Go API over Connect-RPC with generated proto contracts, Go CLI over cli-core primitives, React and TypeScript with Vite for the UI, adopting react-component-library primitives rather than hand-rolling. The candidate and session model is an append-only graph; convergence is a state machine over it.
- **Data + storage expectations**: SQLite in-process for styles, profiles, axis spaces, sessions, rounds, candidates, documents, sections, declarations, and selection events. No external storage resource. No credentials are stored here in any form. Declaration files are authority for consumer-owned records; their rows are projections.
- **Integration strategy**: ai-gateway for all inference through two prose roles that must exist first. content-desk, asset-studio, document-manager, and test-data-generator as consumers that declare their own profiles. search-hub registration for federated retrieval. scenario-dependency-analyzer for every third-party package. program-runtime reachability so a program can call generation as a bounded typed operation.
- **Non-goals / guardrails**: Does not render to any presentation format. Does not publish, schedule, or own account identity. Does not decide editorial content; consumers own the brief. Does not pursue detector evasion, and preserves machine-generation disclosure. Does not own visual identity or media. Does not perform live-traffic variant assignment. Does not rank candidates by taste under any circumstance. Does not train a preference model over candidates.

## 🤝 Dependencies & Launch Plan

- **Required resources**: SQLite in-process. No external resource dependency.
- **Scenario dependencies**: ai-gateway, hard, for all inference and for the two prose roles this scenario cannot ship without; content-desk as the first declaring consumer; search-hub for federated retrieval; react-component-library for UI primitives; scenario-dependency-analyzer for package governance; vrooli-events for run correlation.
- **Operational risks**: The central claim may not reproduce - the verbalized-distribution strategy may deliver little or no measured diversity gain on the models the gateway routes to, which is why specified diversity ships alongside it and why the comparison is a declared acceptance signal rather than an assumption. Local-model measurement is untrustworthy until ai-gateway sets a context ceiling, because prompt overflow currently truncates silently and the warning never reaches the caller, which would produce confident numbers from degraded input on exactly the measurement this scenario exists to produce. Long-form at P0 is a scope fork rather than an increment and inflates the target set accordingly. Operator attention is the throughput constraint on the human surface, and a candidate set increases what must be reviewed, which is why sets are taken at section level and why coverage rather than a ranked shortlist is the human default. The verbalized probability signal is uncalibrated and would corrupt selection if any code ever read it, which is why a static check enforces that none does.
- **Launch sequencing**: The shared metric package first, because every downstream comparison depends on deterministic numbers. Then the thinnest real flow - one style, one profile, one gateway call, one candidate with full provenance - to prove the transport before any set exists. Then candidate sets, gating, and selection. Then sessions and convergence. Then consumer declarations. Then long-form. Then the operator surfaces. Then one real blog post end to end from a declared consumer style file, followed by the acceptance measurement, whose result is recorded whichever way it comes out.

## 🎨 UX & Branding

- **Look & feel**: Vrooli Operational Console per the root design language - calm, dense, technical, slate neutrals with blue for primary commands and cyan for technical emphasis, with light, dark, and system modes first-class. The signature surface is the variation board: a grid of candidate cards, each showing its measurements as a feature vector rather than a score, with pinned and rejected states visible at a glance. The second is the document workspace, an outline rail with per-section status beside the active section variation view.
- **Accessibility**: WCAG AA contrast in both themes, visible focus states, 44px touch targets, no status conveyed by colour alone, reduced motion respected. Candidate cards are keyboard-traversable with pin and reject reachable without a pointer. Measurement chips carry text rather than colour alone, and every sparkline carries a text alternative stating the underlying numbers. On mobile the board becomes a stepwise panel sequence with preserved context rather than a shrunken grid.
- **Voice & messaging**: Precise and operational. A disabled control always states its reason inline - an unregistered profile, an infeasible context budget, an exhausted session budget - because a dead control with no explanation is a failure this surface exists to prevent. Diversity is always stated with its basis named, never as a bare number. No surface ever presents a quality score for a candidate, because a single number invites ranking while a feature vector invites reading.
- **Branding hooks**: Style records may carry a brand reference resolved through brand-manager; this scenario owns prose voice and never visual identity. Keep the seeded web app manifest, service worker, icons, relative install asset URLs, and safe-area tokens valid, replacing generic icons when final branding exists.

## 📎 Appendix

- Source research: Verbalized Sampling - How to Mitigate Mode Collapse and Unlock LLM Diversity (arXiv 2510.01171, ICML 2026). Identifies typicality bias in preference data as the data-level cause of mode collapse, and shows a distribution-level prompt recovers substantially more base-model diversity than direct prompting.
- Structural precedent, text lane: backdrop-studio, whose classified style catalog, style-version immutability on reference, inspectable plan returned without executing, disclosure derived from declared strategy, and axis sweep evaluated as a set are the patterns this scenario mirrors for prose.
- Structural precedent, candidate lane: asset-studio OT-P0-017 already establishes one job producing several candidates with the full cost attributed across the set rather than to the selected one, and OT-P0-012 already establishes disclosure metadata at birth. This scenario is the text sibling of both. The deliberate difference is selection: asset-studio requires an operator to choose, whereas this scenario adds policy-based choice by rarity or coverage so that an agent path exists which never routes through taste.
- Calibration caveat: model self-reported probabilities are documented as poorly calibrated, with confidence saturation and extreme value sparsity, which is why the verbalized signal is stored as an ordinal marked uncalibrated and is structurally barred from influencing selection.
- Prerequisite: this scenario cannot ship before ai-gateway exposes sampling control and two prose generation roles, which is tracked as separate gateway work.

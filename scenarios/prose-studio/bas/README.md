# BAS Automation

Store the scenario's declarative browser checks here. Keep cases focused on
the four product surfaces and reference stable selectors from
`ui/src/consts/selectors.ts`.

- `cases/<operational-target>/<surface>/` mirrors operational targets (rename folders as needed).
- `flows/` contains multi-surface user flows.
- `actions/` hosts fixtures referenced via `@fixture/<slug>`.
- `seeds/` includes optional setup scripts when deterministic data is required.

Each workflow JSON must include:

```json
{
  "metadata": {
    "description": "What the workflow validates",
    "requirement": "REQ-ID",
    "version": 1
  }
}
```

Reference selectors via `@selector/<key>` from `ui/src/consts/selectors.ts`.

The registry is generated by the scenario test lifecycle. Only
`bas/cases/**` are executed by the Playbooks phase; `flows/` and `actions/`
are reusable building blocks.

Performance capture is intentionally not part of this scenario's functional
automation surface. Add a dedicated, read-only observer flow only when a
measured Prose Studio performance target has been approved.

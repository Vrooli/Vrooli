# Mizar monetization: useful work from existing agent spend

Mizar's commercial hypothesis is that orchestration, recurring-friction analysis
and inspectable execution can help an operator obtain more useful outcomes from
existing agent time and spend. The value must be demonstrated for actual supported
workloads. Cost graphs and large token counts do not by themselves prove ROI.

## Paid-value hypothesis

A buyer may value a maintained operational layer that makes repeated agent work
reviewable, highlights recurring obstacles and supports a controlled improvement
process. The selected Vrooli offer determines which packaging, support, updates
and services are actually included. Do not invent an independent price, imply
all local functions require an account, or bundle Aquila by assertion.

The alternative is a collection of terminals, scripts and provider dashboards.
Demonstrate the operational job Mizar improves rather than selling another place
to launch the same agent. Aquila's [workspace positioning](../../../web-console/docs/business/GO-TO-MARKET.md)
explains the complementary daily interaction/review value.

## Billing and evidence boundaries

Keep an existing vendor subscription, provider API-key billing, local compute
cost and Vrooli-funded execution distinct. Authentication and quota eligibility
remain with their owners. A reusable profile or a fallback route does not pool
provider allowances or establish that the cheapest eligible option was selected.

Preserve charge basis and attribution. Provider-reported usage, an estimated token
price, observed duration, a Vrooli settlement and an external invoice are different
facts. Missing observations are unknown, not free or zero. Subscription capacity
utilization cannot be calculated accurately from API-cost estimates alone.

The invocation-efficiency report is a bounded read-only view of its durable
invocation projection. It excludes imported/interactive work from that cohort;
other reports cover other populations. Lifecycle completion is not proof of
usefulness. Previous-window comparisons can guide investigation but cannot by
themselves establish a causal reduction in spend.

See [Measures and operational stats](../reference/operational-stats.md) (including token
attribution) and
`../../.vrooli/program-runtime/efficiency-report.json` before deriving a claim.

## What would establish customer value

Start with a recurring costly failure or intervention. Record the population,
time window, classification/measurement version, missing data and outcome checks.
Make a bounded change, compare suitable workloads, then check whether useful
output improved without unacceptable regressions. Use actual billing evidence
for invoice claims and distinguish it from operational efficiency.

Acceptable positioning: "understand recurring friction and improve supported
agent workflows." A potential saving is a hypothesis until measured. Do not
promise guaranteed savings, autonomous universal optimization, complete subscription
quota visibility, or complete observation of external coding agents.

## Usage controls: what can and cannot be claimed

Agent Manager forecasts provider limits for Claude Code and Codex from observed
readings, and [usage modes](../../../../docs/configuration/usage-modes.md) let an
operator lower what new work runs on for a chosen period. Packaging and price remain
undecided.

Acceptable claim: "see when a limit will run out, what is using it, and change what
new work runs on in one action, with what the change could not reach reported."

Not yet supported by evidence:

- A percentage saved. Estimates rest on unfitted price ratios and modelled levers;
  acceptance A11 in the usage-intelligence effort has not been measured.
- That a cheaper model costs less per outcome. Headless runs record no independent
  acceptance evidence, so Learn mode cannot currently reach a verdict from them.
- Anything about what buyers pay for. All measurements so far come from one operator.

Commercial activation and meter ownership remain with Offer Desk, the
funding/credential authorities and the current product contracts.

Your answers needed before work starts

Thirteen decisions

P2-D1

What happens to the Findings page?

  • RecommendedReplace it with Usage › Friction (one list grouped by problem, with owner, cost, "Report bug" and "Dismiss"). /findings redirects there, and the generic-text generator and the never-used review fields are deleted.
  • AlternativeKeep a separate Findings page, but rewrite its titles and layout.
P2-D2

What happens to the Investigations page?

  • RecommendedTake it out of the main navigation; reach it from a run's "Investigate" button and from Health. Translate the raw status codes into words. Its back end stays.
  • AlternativeLeave it as is (debt stays), or retire the investigation feature entirely, which is a bigger change with unknown users.
P2-D3

Remove the 3,633 test-fixture runs, and fix the cause?

  • RecommendedYes. Fix the Web Console test (F-W2-1) so it writes to a temporary folder, and delete the imported fixture runs. This needs your deletion grant: rows in Agent Manager's database plus the fixture session folders in Web Console's state directory. The importer will also skip files Web Console marks as test output.
  • AlternativeHide them with a filter and leave the data.
P2-D4

Fold sub-agents under their parent run?

  • RecommendedYes. The Runs list shows "▸ 25 sub-agents" under the parent; a filter shows them flat.
  • AlternativeKeep them at top level.
P2-D5

Which usage notifications, and their defaults?

  • RecommendedKeep "runs out early" (on). Add "back on track" (on; it withdraws a stale warning), "may run out" (off) and a daily 8 AM digest (off). Every alert names the #1 action and opens /usage on that window. Alerts show in Agent Manager's own installed app.
  • AlternativeOnly improve the existing alert's text.
P2-D6

One source of truth for tokens

  • RecommendedAll token and quota numbers (Details, run pages, CLI stats) read the verified transcript ledger, and the old run-level token counters are deleted. History is already back-filled, so nothing is lost.
  • AlternativeKeep both and label the old one "estimated". I don't recommend this: two numbers that disagree 9× is the confusion we're removing.
P2-D7

Dollar cost for subscription work

  • RecommendedShow quota points for subscription runs and dollars only for runs billed per token. Remove "unknown 0.00 + subscription 0.00".
  • AlternativeShow an equivalent API price ("≈ $412 at list price") as a secondary figure.
P2-D8

Count imported operator sessions in run statistics?

  • RecommendedDefault the Details tab to Agent Manager runs. Tokens and quota count everything (that's your real usage), while success rate, throughput and run time count only runs Agent Manager started. A filter switches to "Operator sessions" or "Everything".
  • AlternativeCount everything everywhere, as today.
P2-D9

Should Agent Manager enforce limits, not only advise?

  • RecommendedNot in this pass. Finish trustworthy advice and alerts first, use A11 on Nov 5 to show the advice saves quota, then design enforcement (fan-out cap, auto-compact, quota-aware scheduling) as its own effort.
  • AlternativeAdd a fan-out budget setting for Agent Manager-launched runs now.
P2-D10

How much of the old Stats page stays under Details?

  • RecommendedKeep the summary tiles and the model and profile tables, and drop the roughly 6 panels that repeat "Where it went" (runner, tool, capability, cost distribution, run classes, fallback insights). Fallback insights become a Health item. The time window goes in the URL.
  • AlternativeKeep all 16 panels and fix only their numbers.
P2-D11

Consolidate REST and RPC duplicates in this pass?

  • RecommendedYes, after a search of every scenario for callers. Move Agent Manager's CLI and UI to RPC, then delete each REST twin that has no remaining outside caller. Any twin another scenario still uses is listed and left in place. This is the biggest single debt cut (−2k to −4k lines) and the riskiest.
  • AlternativeDelete only the routes that have no caller anywhere, and do the transport change as its own effort.
P2-D12

One naming rule for providers

  • RecommendedSubscriptions use the plan name ("Claude · weekly", "Codex · 5-hour"). Runners use the tool name ("Claude Code", "Codex", "OpenCode"). Usage shows tokens and requests; quota is always "pts" (1 pt = 1% of a window). The proto turns field becomes requests.
  • Alternative"Claude Code" everywhere, including window names.
P2-D13

Where do runner health checks live?

  • RecommendedOn the Health page only. The dashboard shows a one-line summary ("6 runners available · 1 model-policy warning") that links there, which removes a 174-line copy of the health check UI.
  • AlternativeKeep the full health card on the dashboard.
Code debt and complexity

What the code audit found

Two read-only audits covered the Go API and CLI and the React UI. Pass 1 removed about 4,000 lines from the old analytics code but added three new packages. The largest debt sits in parallel paths that compute the same thing differently: two stats engines, two token sources, REST and RPC routes for the same operation, three pricing paths, and four places that show friction.

156.0kAPI non-test lines (plus 136k test). CLI 16.3k. UI 29.9k.
76 / 382fields / methods on the one Orchestrator struct; createRun is 736 lines
55 of 104RPCs that Agent Manager's own CLI and UI never call; the CLI uses 103 REST calls against 32 RPC calls
4places friction is shown; 5 copies of the provider-name helper; 3 duration formats
21eslint errors in 8 UI test files (type-check passes)

Correctness first: why Details is 9× too high

Details sums each run's lifetime token total at the moment the run ends (invocationreadmodel/project.go:420). An imported session that began in August and ended today counts all of its August tokens in "this week". Two more defects add to it: 247 duplicate imported runs carrying 67 B tokens (most likely forked transcripts; unverified), and 4,917 imported runs with zero tokens counted as runs, which explains "68 runs/hr". "Average duration: sample size 0" is a separate bug: measures.go:303 never sets the denominator for run time, so the duration figure is always rejected as too small a sample. The same lifetime counters also feed the runner, profile, model, tool and cohort tables, cost, CLI run stats and the /stats/run-classes route.

How the work would run

Workstreams

The same model as pass 1: one orchestrator, sub-agents per workstream, effort docs updated first. Live checks happen in a browser, and every workstream ends with fewer lines than it started with. Waves A and B can run in parallel; C waits for A's corrected numbers.

# E3 — Capture Fidelity, Audio, and Performance

## Outcome
Provide dependable screenshots and screen recordings with explicit frame, audio, fidelity, and performance evidence, and reduce capture harm on active playback.

## Work
- Reproduce/trace the reported black top bar on supported transports; ensure full-frame unredacted output by default. Remove obsolete masking path or make any genuinely useful redaction explicit, bounded and testable per user direction.
- Audit screenshot dimensions/crop/rotation/insets and recording timestamps, frame drops, source versus encoded fps and duration. Fix verified causes and add deterministic regressions.
- Pair no-capture baseline and multiple capture methods on TV and phone. Report effective display and output FPS, frame count/drop rate, duration, capture latency and available CPU/memory/graphics indicators, plus observed playback impact. Explore hardware/external approaches only through owner-approved architecture; do not promote a method from one short sample.
- Keep optional `--require-audio` consent flow explicit and fail closed. With phone owner available, perform production consent capture; verify non-silent audio, duration and measurable A/V offset. Preserve unknown/unsupported/denied distinctions and cleanup evidence.
- Align common screenshot/recording/log/network capture contracts and transport-specific gaps.

## Proof

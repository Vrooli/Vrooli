## Matched capture and playback protocol

Run capture-off and capture-on observations against the same exact device identity, transport, app/content, display mode, network, and playback interval. Use at least three paired trials in alternating order (off/on, on/off, off/on); capture each for 30 seconds after a fixed 15-second settle. Record identity and OS, app/package/version, transport, trial order, timestamps, method, claim class, and any interruptions. Do not request audio consent for this video-only baseline.

For each trial, collect video frame count, measured duration and output FPS from the retained recording, then collect the typed `performance-state` immediately before and after the interval where supported. Compare playback `SurfaceFPS`, `SurfaceP95MS`, `SlowIntervals`, and `GraphicsFrames`/jank fields for the target package; keep unavailable/unsupported values as unknown with the adapter reason. Preserve the raw run/evidence refs. Report pairwise deltas and median across pairs, with no causal statement beyond that device/app/content/transport sample.

Existing fields: `RecordingArtifact` and the retained video reference expose method, frame count, duration and effective/output FPS; `performance-state` exposes Android graphics and SurfaceFlinger presentation measures. Missing for an accepted comprehensive baseline: source/display FPS tied to the capture interval, explicitly counted dropped source frames, capture-host CPU/RSS/network cost, and a structured before/during/after playback-impact record. Until added by their owning surfaces, label these `unmeasured`; do not derive drop counts from output FPS alone.

## AI control comparison protocol

Use a fixed set of assertion-bearing tasks and exact device/app/context identity. For each task compare (a) the current bounded vision/agent route and (b) the best available deterministic semantic/anchor/reusable-flow route. Restore the same observable starting state between paired trials and alternate route order; run at least five pairs per task when live-device authority and a stable state permit. Record terminal assertion result from independent device state, failed/wrong selections, action count, retries/fallbacks, wall-clock start/end, and run/evidence IDs. Report success rate plus median/p95 latency and action count per route; never drop failed attempts.

Existing agent records include goal verification, disposition, chapters, prompt/policy/plan hashes, and planned steps; flow records include terminal dispositions and assertions. They do not persist a consistent action count, end-to-end latency, model/token/cost measure, confidence calibration, or matched comparison cohort. Capture these in an external measurement sheet/run record until the owning telemetry schema is extended. Do not substitute chapter count for device action count or planner confidence for verified success.

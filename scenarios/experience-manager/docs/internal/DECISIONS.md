# Decisions — Experience Manager

This document records durable decisions and tradeoffs future agents
should not accidentally relitigate.

## Purpose Of This Document

Use this document when a choice:

- affects multiple files or future agents,
- rejects a plausible alternative,
- changes architecture, deployment, data, security, monetization, or
  testing direction,
- needs a revisit trigger.

Routine implementation log entries belong in [`PROGRESS.md`](PROGRESS.md).
Known unresolved issues belong in [`PROBLEMS.md`](PROBLEMS.md).

## Decision Log

| Date | Decision | Context | Consequences | Revisit Trigger |
|---|---|---|---|---|
| 2026-07-04 | Use the generated `react-vite` scenario documentation contract. | Scenario scaffold was generated from the template. | Docs start with stubs and maturity metadata in `docs/manifest.json`. | Revisit when scenario adopts a different template or doc contract. |
| 2026-07-04 | **Claim-based spec schema, not a descriptive layout schema.** The UX spec is a set of typed claims about perceivable outcomes ("exactly one action visually dominates"), never an exhaustive description of the page. | A descriptive schema is closed-world: its taxonomy becomes the ceiling on expressible UIs, and it rots on every layout iteration. Claims mirror how `requirements/` already works — state what must be true, not how it is built. | Novel UX (chat streams, canvases, ambient surfaces) costs nothing; only stated claims are ever validated. An optional non-normative `sketch` layer exists solely for wireframe rendering and BAS scaffolding. | If claim authoring proves too abstract for real pages during the spike gate. |
| 2026-07-04 | **Open-world semantics: the spec is a floor, never a census.** Anything unclaimed is free; nothing is flagged for being unmentioned. | The single most important anti-pigeonhole property — validation must never fight good UX that simply was not asserted. | Coverage checks measure spec depth (which pages/states have claims), never page contents beyond claims. | Never — this is doctrine. |
| 2026-07-04 | **Per-claim enforcement tiers: `machine` (gates), `manual` (attested with expiry), `aspirational` (advisory, never rejected), plus a free-form `custom` claim type that always parses.** | The spec language must be allowed to run ahead of the validator, or the UX shrinks to fit the checker. Business-health's manual-evidence ledger is the attestation precedent. | Vocabulary grows by promotion (aspirational → machine) as checks are built. CI gates only on machine-tier claims. | If the aspirational tier accumulates without any promotion path being exercised. |
| 2026-07-04 | **WAI-ARIA roles are the element vocabulary; no invented widget taxonomy.** | The accessibility tree emits ARIA roles, so spec↔structure reconciliation is apples-to-apples; ARIA is already open-world (roles + accessible names, not layout). | Custom roles allowed only as namespaced extensions where ARIA is insufficient. | If ARIA coverage proves inadequate for a real page class. |
| 2026-07-04 | **Intent/bindings split: stable claims separate from volatile grounding (element id → testid/selector/ARIA name).** | Kills the flap-on-restyle failure mode structurally: restyles and refactors touch bindings only, intent survives. Bindings are also the selector SSOT that `bas/` scaffolding reads. | Two sections (or files) per page spec; binding drift is an autofixable finding class. | Never — load-bearing for CI stability. |
| 2026-07-04 | **Spec depth is a maturity ladder (L0 identity → L1 priorities → L2 grounded claims → L3 state coverage → L4 journey membership), not a gate.** | An experimental page at L1 is compliant; depth is tracked as debt, not demanded up front. Mirrors business-health's ladder discipline. | Fleet sweep scores depth worst-first; no all-or-nothing authoring burden. | If fleet-wide depth stagnates at L0/L1. |
| 2026-07-04 | **Spec lives in a root `experience/` folder (index + pages/ + journeys/), mirroring `requirements/`.** Rejected: `bas/` (contract-vs-evidence inversion; workflow-health governs that tree), `docs/` (machine data, wrong validator), `ui/` (implementation workspace; intent must survive rewrites). | The filesystem itself shows the two-track thesis: PRD roof → `requirements/` (business) + `experience/` (experience), with `bas/` as evidence producer for both. | Template will scaffold `experience/` at generation (rollout work, not an OT). | Never — placement is doctrine. |
| 2026-07-04 | **Artifact contract is JSON validated by `.vrooli/schemas/scenario-experience-spec.schema.json`; proto/Connect only for service endpoints.** | Repo convention: JSON schema for on-disk artifacts (`scenario-ui-manifest` precedent), proto for wire contracts. | Parser adds only what JSON schema cannot: cross-file references, coverage, tier/open-world semantics. | n/a |
| 2026-07-04 | **Spec parser is an internal package (`api/internal/spec`); no shared Go package.** | Duplicate-before-extract: experience-manager is the only consumer. (intent-go is legitimately shared — business-health + architecture-cartographer — so it is precedent for *when* to extract, not for starting shared.) | Cross-scenario access (e.g., workflow-health drift checks) goes through the CLI/API, wrap-not-use. | A second in-repo Go consumer actually appears. |
| 2026-07-04 | **experience-manager is a manager-class scenario owning the entire experience concern — authoring AND validation together.** Rejected: splitting authoring here and validation in ui-health. | prd-control-tower was deleted for exactly that split when business-health absorbed the business axis; brand-manager proves the manager-class shape (creative workshop + own validation rules + composes image-tools). | Mounts `ScenarioValidationService`; test-genie discovers the `experience` phase via `.vrooli/test-genie.json`. | Never — one concern, one home. |
| 2026-07-04 | **ui-health boundary: ui-health = built correctly (manifest, interop lint, standards, runtime render, pixel-regression); experience-manager = intended experience (spec registry, reconciliation, saliency, journeys, state coverage).** Gray zones assigned: static a11y lint stays ui-health; a11y-*tree*-as-oracle reconciliation is ours. Pixel thresholds/baseline diffs stay ui-health; perceptual/saliency judgment is ours. | Interop rules were once scattered across three scenarios before consolidating into ui-health — a crisp charter prevents recreating that scatter. | Both scenarios validate UIs without overlapping findings. | Any finding class both scenarios could plausibly emit. |
| 2026-07-04 | **workflow-health is NOT absorbed.** It stays the `bas/` asset-governance and safe-execution substrate; we consume it. The seam: our studio scaffolds `bas/cases` stubs from spec entries (routes→navigation, claims→assertions, bindings→selectors); workflow-health catalogs, safety-gates, and executes them. | Its charter (asset catalog, safety metadata, test-genie `workflow` phase, agent-runnable flows) has consumers beyond experience validation; merging would rebuild the rejected "specification-health mega-validator". Spec-first generation makes the two concerns cleaner, not more entangled. | Spec↔case reference integrity is checked in both directions; journey runtime coherence (P2) builds on workflow-health execution instead of a second harness. | Only if workflow-health's non-experience consumers never materialize. |
| 2026-07-04 | **BAS is the single capture engine; accessibility-tree capture per execution step is a prerequisite BAS feature.** | ui-health's `uiruntime` already drives BAS for screenshots; adding the a11y tree at the BAS level gives ui-health, workflow-health, and experience-manager the same evidence without duplicate harnesses. A tree-vs-pixels divergence is often literally an accessibility bug, so the capture pays twice. | Reconciliation (OT-P0-003) is blocked until BAS ships it; degraded behavior is skipped-never-failed. | n/a — file the BAS request before reconciliation work starts. |
| 2026-07-04 | **DESIGN.md is a styling/token contract (official Google DESIGN.md format + Vrooli UX-state extensions) — an input, not a parent artifact.** Its required UX-state contract (loading/error/empty/stale/partial/retry/disabled) seeds per-page state-coverage checks. | Earlier framing wrongly slotted DESIGN.md as the prose rung of the experience ladder; it is orthogonal (visual language, kit-governed) and its validation already has homes. | The two-track table roots both tracks in the PRD, not in DESIGN.md. | If design-canon enforcement work changes DESIGN.md's role. |
| 2026-07-04 | **v1 is zero-ML.** Contract + provider + reconciliation-against-a11y-tree + studio + dogfood. The perception tier (pixel parsing, UMSI-style saliency) is P2, advisory before gating, quarantined off the CI hot path; the perception engine's home (image-tools vs. own scenario) is deliberately undecided until then. | The deterministic INTENT↔STRUCTURE edge delivers the workshop-cheaply goal without a stochastic model near CI; prior art (OmniParser AGPL detector, UMSI weights) carries license/determinism questions that should not block v1. | Third-party surface fingerprinting and photo/receipt extraction stay out of scope until the perception tier exists. | P2 kickoff. |
| 2026-07-04 | **Importance ranking, never fabricated time-to-comprehend.** When saliency scoring arrives it reports what draws the eye in what order (deterministic learned model), not invented "seconds" numbers. | An importance heatmap is honest and reproducible; a seconds estimate would be pseudo-science dressed as measurement. | UI presents priority order and divergence from declared communication priorities. | Never. |
| 2026-07-04 | **`experience` phase launches with presence-keyed applicability, shadow-then-promote.** Spec absence is fleet-sweep debt, not a failed suite. | No scenario has an `experience/` folder yet; `applicability.default: applies` + gating would redden 100+ suites on day one. | Promotion to broader gating happens only after the fleet has specs. | Fleet spec coverage crossing a threshold worth gating on. |
| 2026-07-04 | **Wireframe-render-first for the workshop; AI-image render is an optional mode composing image-tools (`openrouter-image`).** The spec is the source of truth and the visual is derived — never lossily extracted from a picture in v1. | Deterministic spec→HTML→BAS-screenshot round-trips perfectly and needs no diffusion model; mockup→spec extraction requires the P2 perception tier. | The parked `ai-image-generation-foundation` backlog items should be re-pointed at image-tools rather than direct OpenAI integration. | P2 perception tier enables the mockup→spec direction. |
| 2026-07-04 | **Validation-run byproducts (screenshot + a11y-tree pairs) are captured with labels, not pre-filtered by aesthetics.** Filter later by label (a11y-tree reliability for perception training; validation verdict for quality judgment). | Every reconciliation run silently emits a labeled training example; the oracle-rich domain (our apps) can bootstrap the oracle-poor one (third-party extraction) if/when a clean-license perception model is trained. | Documentation note only for now — a training-data export endpoint is deliberately deferred. | When perception-model training actually starts. |

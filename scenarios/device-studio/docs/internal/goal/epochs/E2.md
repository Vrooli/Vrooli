# E2 — Save and replay an authentic photographic still

- Outcome: User imports authentic media and a calibrated plate, saves a compatible immutable still shot, previews, renders and exports PNG, restarts and reproduces it through UI/API/CLI.
- Kind: feature
- Started: 2026-10-20 (after E1 D7 acceptance)
- Estimate: 12 checked work units for the complete still journey, including admitted media/worker preparation; video is tracked in E2V
- Expected size: revised to 9500 net runtime lines including shared-operation/media/worker preparation; cap 11000. Original admission was estimate 5000/cap 7500; the pre-integration revision is explained below.
- Metric: import/save/render/reopen/replay/invalid-input/cancel journeys with retained output evidence
- Targets: current-host: required; other native platforms: unavailable
- Workers: native:/root/workspace_e1, native:/root/materials, native:/root/renderer_design (bounded assignments)
- Status: in-progress

## Modules and budgets

Use the pure composition core and validated device definitions as domain seams, not competing shot or byte owners. Implement per-domain media metadata, immutable shot revisions and durable local jobs only as needed for this complete journey; proto-first through owner generation. Blobstore owns bytes; every source/plate/mask and output is digest-bound. Decoder/encoder execution uses existing platform containment and governed tool profiles, never a private host installer. Use bound argv and safe staging. This epoch accepts still PNG/JPEG sources. Unsupported formats/rotations/color profiles explain limitations instead of silent conversion. Video decode/encode, source-clock mapping and screen-entry timing remain required in E2V.

The plate route supports fixed physical pose/camera and screen updates. Reject phone spin/hinge/parallax at compile time. Distinguish physical panel, app viewport, captured chrome, simulated chrome and hardware occlusion. Provide app-only and customizable phone status/home plus desktop/browser composition, with no duplicated captured bars. Pin every editable value and source dependency in the shot revision. Respect actual source resolution; historical v6 fixtures remain lower-resolution algorithm proofs, not the final still deliverable.

UI import -> project shot -> final-render look -> local job -> direct PNG export -> reopen is the scope. No customer-facing broken controls or template domain masquerading as product. Clear preview/final distinction, retained draft on errors, keyboard numeric calibration. Adopt shared RCL forms/states. Jobs survive browser disconnect, cancel owned descendants and reconcile restart truthfully. Do not silently retry an unknown external result; this slice uses no external provider calls.

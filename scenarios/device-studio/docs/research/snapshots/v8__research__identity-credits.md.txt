# Account identity, credits and Device Studio integration

Research date: 2026-10-19. Scope: the [accepted decisions](decisions.json), canonical identity contract, current Web Console, shared clients, LPBS and desktop template code. This is source-backed research, not a live sign-in, credit-spend, desktop certification or production change. The only executable probe used synthetic URLs and the actual checked-out TypeScript functions; it contacted no account or provider. Money policy and wallet/idempotency findings belong to the parallel [monetization report](monetization.md).

## Outcome

Device Studio should reuse Vrooli's **identity, credential authority, commerce and agent authorization owners**. It should not create a password database, a local credit wallet or its own account-to-entitlement mapping. Local editing/rendering and optional account-backed services are separate paths. A downloadable personal app must remain usable under its declared private local mode without forcing a cloud login. Optional Vrooli services require an explicit account connection and the trusted owner-managed paid-execution route.

The pieces exist, but they are not one complete reusable integration today. Web Console's browser sign-in is incompatible with current LPBS callback validation. The desktop template has both ordinary cloud sign-in and a separate scoped account-link flow. A scoped entitlement lease is not itself the consumer access token used by the current metered inference client. A complete reusable account settings page is also not established: `AccountSettingsSurface` is a catalogued null placeholder, while smaller shared components and Web Console's local account page are real code.

## Keep these identities and authorities separate

| Concern | Actual owner/meaning | Device Studio consequence |
|---|---|---|
| Local human/operator identity | `scenario-authenticator` or a configured external provider; personal private desktop uses the OS/app boundary declared by its mode | Verify canonical principals where required; enforce shot/project ownership and release rules in Device Studio. Cloud credit balance does not authorize local files or commands. |
| Cloud person/business account | LPBS currently hosts a compatibility consumer identity/session flow and owns business-account membership | Select the account explicitly when linking commerce. Do not equate an email with a local principal or another account. |
| Desktop supervisor access | App-private shell-to-runtime control token | Lifecycle/loopback control only; not a human login, cloud account or entitlement. |
| Provider credentials/BYOK | Credential authority; desktop encrypted platform storage for relevant client sessions | Keep secrets off renderer storage, URLs, shot recipes and agent prompts. A configured key is not Vrooli credit or free provider usage. |
| Features, plan and credits | LPBS signed entitlements plus its authoritative account/wallet/execution decisions | Read verified lease/UI projections; let the trusted billable-work owner reserve and settle. Never decrement a browser balance as authority. |
| Agent identity and operation grants | Agent Manager plus canonical `api-core` authentication/authorization evaluation | An AI button does not turn the human session into unrestricted agent authority. Bind work to an owner, project, scopes, expiry and the operation grants that the actual operation requires. |

These boundaries are explicit in [IDENTITY-AND-AUTHENTICATION.md:30](/home/matthalloran8/Vrooli/docs/concepts/IDENTITY-AND-AUTHENTICATION.md:30). The document distinguishes shipped/compatibility/target behavior; it must not be read as proof that every stated migration has completed. Web Console currently composes scenario-authenticator and managed Cloudflare identity at API ingress, independently of its optional LPBS subscription account. [main.go:1190](/home/matthalloran8/Vrooli/scenarios/web-console/api/main.go:1190).

## What Web Console actually does

### Account and credential storage

Web Console declares optional monetization (`requires_entitlement:false`), with `ai_credits` on the routed paid-inference path. Its local workspace is not gated by an account. The shared durable subscription credential is `identity=vrooli/lpbs-account`, `field=refresh-token`. `ConsumerSessionResolver` resolves that credential, POSTs it to LPBS `/api/v1/auth/refresh`, persists the rotated refresh value back through credential authority, and retains only the access token in its process memory. Refresh is serialized within a resolver and cached until 30 seconds before expiry; changing issuer/base URL clears the warm token. [monetization.json:5](/home/matthalloran8/Vrooli/scenarios/web-console/.vrooli/monetization.json:5), [subscription.go:18](/home/matthalloran8/Vrooli/packages/credentialclient-go/subscription.go:18), [subscription.go:70](/home/matthalloran8/Vrooli/packages/credentialclient-go/subscription.go:70).

Own-origin session endpoints expose GET/POST/DELETE `/api/v1/auth/subscription/session`; POST stores a refresh token and returns metadata, not its value. DELETE removes it and Web Console clears its resolver cache. The module performs loopback/same-origin checks; those checks do not establish a cloud identity or replace the deployment's ingress authentication. General BYOK provisioning is declaration-checked and metadata-only. [routes.go:71](/home/matthalloran8/Vrooli/scenarios/web-console/api/routes.go:71), [session.go:29](/home/matthalloran8/Vrooli/packages/monetization-go/session.go:29), [credentials.go:153](/home/matthalloran8/Vrooli/scenarios/web-console/api/credentials.go:153).

The UI's “configured” flag means a credential is present. It is not proof that a session is valid, a subscription active, or a wallet funded. Device Studio should display these as separate facts rather than presenting “connected” as all three.

### Browser sign-in: a verified contract mismatch

Current `startSignIn()` navigates to LPBS `/auth/login` with `redirect_uri=window.location.href`, `app=Aquila` and random state. It supplies no PKCE challenge. Its callback expects `access_token`, `refresh_token`, expiry and state in a URL fragment; it removes the fragment, POSTs refresh to the local API and stores access/expiry in `sessionStorage`. Access is not in `localStorage`, but it remains JavaScript-visible; this is not the canonical cookie/code target. [auth.ts:53](/home/matthalloran8/Vrooli/scenarios/web-console/ui/src/lib/auth.ts:53), [auth.ts:83](/home/matthalloran8/Vrooli/scenarios/web-console/ui/src/lib/auth.ts:83).

Current LPBS classifies any `redirect_uri` as a native-app flow and requires an allowed local callback plus S256 PKCE. Its browser website flow instead uses same-origin session cookies. The synthetic [identity-contract-probe](identity-contract-probe.json) transpiled both production files with installed TypeScript. A localhost Web Console callback produced “incomplete security check”; an HTTPS remote console callback produced “not on this computer”; a code-style callback was not recognized by Web Console. No live account was used, and no observed end-user outage is claimed. [signInContext.ts:43](/home/matthalloran8/Vrooli/scenarios/landing-page-business-suite/ui/src/surfaces/user-auth/lib/signInContext.ts:43), [user_auth.go:346](/home/matthalloran8/Vrooli/scenarios/landing-page-business-suite/api/handlers/administration/user_auth.go:346).

This is new relative to v7's rendering/integration findings. After checking 730 QA inbox records including closed entries for a matching PKCE/Web Console issue, I filed **`knw-1792451955790814674`**, `bug-inbox/code-defect/web-console-sign-in-callback-contract-conflicts-with`, through the [report-bug skill](/home/matthalloran8/Vrooli/scenarios/prompt-manager/store/skills/packs/core/report-bug/SKILL.md). [Published receipt](identity-bug-capture.json), [replay source](identity-contract-probe.cjs). Existing Web Console auth tests mock the account side and therefore do not test this owner-to-consumer seam. Repair the callback integration; do not relax LPBS's checks or copy the fragment-token behavior into Device Studio.

### Balance and execution

GET `/api/v1/auth/subscription/summary` resolves a shared session, reads LPBS `/api/v1/auth/me`, fetches/verifies the entitlement lease, and projects status, plan, credits and expiry. It uses the authenticated LPBS response's email as a compatibility identity, not a browser-supplied email. The returned credits are an account/lease snapshot, not authority to execute a new charge. Current summary reports `pending_sync:0`; the UI's pending badge is not proof of an implemented Device Studio usage queue. [credentials.go:341](/home/matthalloran8/Vrooli/scenarios/web-console/api/credentials.go:341), [monetization.go:42](/home/matthalloran8/Vrooli/scenarios/web-console/api/monetization.go:42).

Web Console's inference chain tries local Ollama, then the user's OpenRouter key, then Vrooli metered inference. Only the latter is intended to use Vrooli credits; BYOK may still incur the provider's own cost. The metered adapter forwards the consumer token to AI Gateway; AI Gateway forwards it, or resolves a shared credential when absent, to LPBS's trusted inference path. Its insufficient-credit condition is typed rather than treated as a transient provider failure. [provider.go:51](/home/matthalloran8/Vrooli/scenarios/web-console/api/internal/ai/provider.go:51), [provider.go:267](/home/matthalloran8/Vrooli/scenarios/web-console/api/internal/ai/provider.go:267), [metered.go:125](/home/matthalloran8/Vrooli/scenarios/ai-gateway/api/internal/providers/metered.go:125), [ai-gateway main.go:96](/home/matthalloran8/Vrooli/scenarios/ai-gateway/api/main.go:96).

That fallback order is implemented Web Console behavior, **not** Device Studio's approved spending policy. Device Studio must preserve the selected local/BYOK/Vrooli route and project cap. A failed local operation must not silently start external paid execution. The shared `Gate.Meter` explicitly says its local decision cannot reserve or spend Class A credits. Wallet ownership and exact reservation/settlement integration are covered by the money report. [gate.go:89](/home/matthalloran8/Vrooli/packages/monetization-go/gate.go:89).

## Downloadable desktop: two different flows

The canonical modes are `personal_local`, `local_multi_user`, `remote_vrooli` and `shared_provider`. They are explicit deployment choices, not automatic fallbacks when an authenticator is unavailable. `personal_local` defaults to private OS-user/app authority without human sign-in; cloud account linking is optional. Other modes need their declared identity provider and policy. Cross-platform architecture from the outset does not mean Windows/macOS/Linux packages, secure stores and callback transports have all been certified. [Identity modes:110](/home/matthalloran8/Vrooli/docs/concepts/IDENTITY-AND-AUTHENTICATION.md:110).

### Ordinary desktop cloud sign-in

The current template's `auth.signIn()` creates a PKCE verifier/state, starts a process-owned `127.0.0.1` ephemeral listener, opens the system browser, validates the returned code/state and POSTs `/api/v1/auth/token`. It stores the resulting website access/refresh session only through Electron `safeStorage` and schedules refresh. Token-bearing custom-scheme callbacks are rejected. This is materially stronger than Web Console's browser-fragment adapter, but it is still a website session, not a local identity or scoped desktop commerce link. [manager.ts:293](/home/matthalloran8/Vrooli/scenarios/scenario-to-desktop/templates/vanilla/auth/manager.ts:293), [main.ts:251](/home/matthalloran8/Vrooli/scenarios/scenario-to-desktop/templates/vanilla/main.ts:251), [manager.ts:481](/home/matthalloran8/Vrooli/scenarios/scenario-to-desktop/templates/vanilla/auth/manager.ts:481).

When encryption is unavailable, the manager deletes/refuses plaintext token persistence. Website tokens may exist in process memory for that session, but are not recovered from plaintext or from the credential authority. It can recover a signed entitlement lease from the authority separately. Successful safeStorage availability is not yet this report's proof of every OS keychain/profile mode. [manager.ts:63](/home/matthalloran8/Vrooli/scenarios/scenario-to-desktop/templates/vanilla/auth/manager.ts:63), [manager.ts:109](/home/matthalloran8/Vrooli/scenarios/scenario-to-desktop/templates/vanilla/auth/manager.ts:109).

Web Console currently calls `desktop.auth.signIn()` when that bridge exists. It does not invoke `connectDesktop()` from its account page. Do not describe its existing button as the scoped link flow. [Web Console auth.ts:83](/home/matthalloran8/Vrooli/scenarios/web-console/ui/src/lib/auth.ts:83).

### Explicit scoped commerce connection

The separate `auth.connectDesktop()` path requests consent with installation ID, resource, audience, scopes and PKCE. The LPBS browser selects a business account, issues a one-use code and returns it to the owned loopback listener. Redemption uses a verified local identity proof and stores the **signed entitlement lease**, not a copied website access/refresh session. The lease is sent through runtime credential authority under `vrooli/lpbs-account`, field **`entitlement-lease`**, a different field from the shared consumer refresh token. [manager.ts:336](/home/matthalloran8/Vrooli/scenarios/scenario-to-desktop/templates/vanilla/auth/manager.ts:336), [main.ts:1898](/home/matthalloran8/Vrooli/scenarios/scenario-to-desktop/templates/vanilla/main.ts:1898).

Implemented LPBS endpoints are:

- POST `/api/v1/desktop/links`: recent cloud authentication, selected-account membership and a scoped S256 request.
- POST `/api/v1/desktop/links/redeem`: verified human scenario-authenticator principal, one-use code/verifier and installation/resource checks; returns the link and signed lease.
- GET `/api/v1/desktop/links/local`: locally authenticated link status; revoked links are refused.
- DELETE `/api/v1/desktop/links/local`: local-side revoke. DELETE `/api/v1/desktop/links`: cloud-account-side revoke.

The issuance service defaults a code to two minutes and permits at most five. The signed lease binds principal, selected business account, installation, resource, audience, link and scopes; entitlements/credits are read for that account, not selected by matching another account's email. [handler.go:52](/home/matthalloran8/Vrooli/scenarios/landing-page-business-suite/api/handlers/desktoplink/handler.go:52), [service.go:37](/home/matthalloran8/Vrooli/scenarios/landing-page-business-suite/api/internal/desktoplink/service.go:37), [desktop_link_entitlement.go:12](/home/matthalloran8/Vrooli/scenarios/landing-page-business-suite/api/desktop_link_entitlement.go:12).

The local-proof implementation currently uses a Unix socket machine-principal exchange. It needs an enrolled default OS-principal/machine binding and a configured local provider; it does not infer a human principal merely from hostname. The authenticator resolves exactly that binding before issuing normal identity tokens. Personal local use must continue when this optional account connection cannot complete. Qualify the provider topology and OS-specific transport, especially Windows, rather than assuming Electron alone supplies it. [local-identity-proof.ts:26](/home/matthalloran8/Vrooli/scenarios/scenario-to-desktop/templates/vanilla/auth/local-identity-proof.ts:26), [service.go:427](/home/matthalloran8/Vrooli/scenarios/scenario-authenticator/api/internal/accounts/service.go:427).

**Important integration gap:** the current paid inference clients accept a consumer access token or resolve the `refresh-token` session. The scoped link flow produces an `ENTITLEMENT_LEASE`. I did not find an adapter in these traced clients that turns the local proof plus linked lease into selected-account paid execution. Do not pass that lease as an ordinary bearer token, copy cloud refresh credentials into the local principal, or silently charge the host's different shared account. Extend the trusted owner contract and qualify account-bound execution. This is an implementation seam, not evidence that the whole commerce flow is unavailable.

## Expiry, offline, logout and revocation

`entitlementclient.VerifyFor` checks RS256 signature/JWKS, lease type, hard `not_after` and supplied binding fields, including exact scope set. Empty expected fields deliberately skip those binding checks for older callers. Device Studio desktop code must supply the complete known binding; calling compatibility `Verify()` alone is insufficient. The manager's `getEntitlementLease()` returns bytes; fetching those bytes is not verification. [lease.go:67](/home/matthalloran8/Vrooli/packages/entitlementclient-go/lease.go:67), [lease.go:117](/home/matthalloran8/Vrooli/packages/entitlementclient-go/lease.go:117), [manager.ts:459](/home/matthalloran8/Vrooli/scenarios/scenario-to-desktop/templates/vanilla/auth/manager.ts:459).

| State | Implemented boundary | Device Studio behavior to implement/qualify |
|---|---|---|
| Signed out | Local private mode and local resources are distinct from subscription session | Keep edit/import/render and eligible local AI available; offer optional account connection for Vrooli services. |
| Valid cached lease, offline | Shared cache accepts only until signed expiry; it cannot mint new credit | Allow only the offline/local capacities declared by the product. Remote paid work waits or fails clearly; a displayed credit snapshot is not offline spending authority. |
| Expired lease/session | Browser access accessor drops a near-expired token; desktop tries refresh; shared resolver returns typed authority/session errors | Show reauthentication separately from provider outage. Preserve saved shots and job checkpoints. Do not extend the lease deadline or invent a grace balance. |
| Sign out in Web Console | Browser local token is cleared; local API removes shared refresh and clears its resolver | Explain the machine-shared connection scope. This deletion is not code proof that every other warm process token or remote session was revoked. |
| Desktop sign out | Auth manager clears memory/encrypted files and authority lease, then best-effort website logout if it had an access token | Local cleanup must succeed independently of network. Report remote logout/unlink outcome separately. |
| Unlink a scoped account | LPBS implements local/cloud revoke; a cached lease can remain usable until its signed expiry unless refreshed | Expose explicit “Disconnect this installation/account”; revoke through owner when online, immediately remove local lease, and distinguish pending remote revocation. Ordinary manager signOut does not itself call `/desktop/links/local`. |
| Credential authority unavailable | Shared client refuses credential resolution; local workspace is still a separate mode | Show “account/key unavailable”, not zero credits or invalid password. No fallback to secrets in recipes/browser storage. |

The offline lease rule is verified in [lease.go:238](/home/matthalloran8/Vrooli/packages/entitlementclient-go/lease.go:238); desktop cleanup and best-effort logout are in [manager.ts:194](/home/matthalloran8/Vrooli/scenarios/scenario-to-desktop/templates/vanilla/auth/manager.ts:194) and [manager.ts:418](/home/matthalloran8/Vrooli/scenarios/scenario-to-desktop/templates/vanilla/auth/manager.ts:418). These are source observations, not newly exercised live logout/revocation receipts.

## AI/agent disclosure and external-media consent

The operator explicitly requires disclosure **before** every AI/agent-initiating action, including nested autonomous work within its stated scope and budget. This is a Device Studio requirement to implement; current account components do not establish it.

- Name the initiating action accurately: **“Generate scene with AI”**, **“Create/refine model with agent”**, **“Analyze references with AI”**. Show the chosen local/BYOK/Vrooli route, accountable project/account, estimate/cap, and whether files or media leave the machine before submission.
- An agent action explains that it can search/import/build/refine candidates, execute bounded tooling and create candidate files. Show its allowed sources/workspace, budget/time ceiling, retained checkpoints and stop control. Launch the run with canonical owner/agent identity; do not lend the human cookie or refresh token to the worker. Nested work inside the disclosed envelope does not need a new modal for every tool call; expanding that envelope does.
- A deterministic **“Render shot”** action should say what it actually executes. It need not be labeled a new AI call merely because an input asset was generated earlier; provenance still identifies that asset. If it also starts an agent to repair/setup the shot, disclose that before launch.
- Real screenshots/recordings and screen-bearing renders stay local by default. External generation, critique and **remote agent vision** require explicit per-project opt-in. Selecting a cloud account, supplying a BYOK key or approving a spending cap is not that opt-in.
- Default external inputs are blank/redacted screens and public device/scene references. Show a reviewable upload manifest or preview with provider/destination and purpose. Apply the policy server-side to images, recordings, thumbnails, contact sheets and prompt text derived from media; do not make a checkbox the only enforcement point.
- Retain the actor, project-consent revision, data categories/digests, provider route, job/run IDs and actual/unknown cost. Preserve release disclosure through the existing Asset Studio owner; account sign-in must not silently publish an asset.

Technical scopes and operation grants remain separate from this disclosure and privacy consent. The canonical evaluator checks a human's capability or the actual approved agent/service operation grant, and owners still enforce object/release rules. Child delegation narrows scopes and cannot outlive its parent; interactive operation grants are not inherited as blanket child authority. [operation.go:25](/home/matthalloran8/Vrooli/packages/api-core/authn/operation.go:25), [attenuation.go:22](/home/matthalloran8/Vrooli/scenarios/agent-manager/api/internal/identity/attenuation.go:22).

## Recommended adoption and validation boundary

Adopt explicit modes from the start. For a private downloadable app, use local mode for core work and **`connectDesktop` for optional commerce linking**, once its local-proof/provider and selected-account paid-execution seam are qualified. Retain ordinary `signIn` only for products intentionally needing a website session; do not relabel it as a desktop entitlement link. For browser-hosted Device Studio, use the declared ingress identity and a same-origin code/cookie backend adapter through the canonical owners. That browser adapter needs implementation/qualification; neither the current fragment adapter nor a loopback-only native callback is a finished hosted-web solution.

Required evidence before claiming completion:

1. Browser code/state/replay/redirect and cookie behavior across actual owner endpoints, without exposing token values.
2. Desktop selected-account consent, one-use PKCE redemption, local-principal mapping, full lease binding and secure-store recovery on each supported platform.
3. Account-bound paid execution from the selected desktop link, plus insufficient credits, stale balance, retry/cancel and no duplicate charge; use the money owner's contract.
4. Signed-out/offline/expired/revoked states preserve local work, refuse unsupported paid work and accurately distinguish account, provider and credential failures.
5. Logout/unlink clears local data and reports remote revocation status; account switching never leaks cached entitlement or charges another account.
6. Disclosed nested agent jobs remain inside their owner/operation/budget/data envelope; external media has no egress before project opt-in, including critique and vision.
7. The shared account surface actually renders and works through browser/desktop adapters; catalog presence or mocked component tests are insufficient.

**Changed understanding:** a physical account UI and shared library names concealed meaningful differences between compatibility browser login, desktop website session and scoped account lease. **Verified:** exact source flows, shared credential fields, signature/binding code, typed credit projection/execution separation, component implementation state, and the synthetic callback mismatch. **Remaining:** real integration/packaged-platform qualification and the identified adapter work. No missing credential or authority blocks this research; no live login, token inspection, spend, provider call, install or production fix was performed.

# Device Studio: ownership and integration research

Research date: 2026-10-19. Scope: read-only production inspection, existing experiment evidence, bounded status/inventory/route-explanation checks, and official provider documentation. No generation, paid call, credential inspection, service start, install, suite, plan or implementation was performed. Scenario QA reports are the explicitly authorized reporting exception to the read-only production boundary.

**Recommendation:** Device Studio should own the device-specific catalog, qualification, presentation profiles, immutable shots, creation/refinement workflow, and render orchestration. Reuse BAS for capture, Image Tools for supported raster operations and image inference, Asset Studio for generic identity references and released-media metadata/disclosure, api-core for storage primitives, and platform-go/control-plane tool adapters for execution containment. Backdrop Studio supplies ambient artwork and composition assets, not authoritative physical device geometry. Start with the demonstrated photographic-plate strategy while a separately qualified 3D strategy matures. Several existing seams require real adapter work; none is a hidden prerequisite for importing a plate and rendering a private draft.

Labels below mean:

- **Verified code:** the cited production code implements the stated behavior; it was not necessarily executed in this investigation.
- **Verified runtime:** a bounded read-only command returned the stated result. Raw outputs are in [integration-probes.json](integration-probes.json).
- **Designed:** a documented target or proposed contract, not a callable implementation claim.
- **Recommendation:** the proposed technical choice based on that evidence.
- **Unverified:** evidence needed before the capability can be qualified. This does not establish that a credential, device, or capability is absent.

## 2. Asset identity, bytes and release: what the adapter must actually solve

**Verified code:** Asset Studio's generic identity is one of character/scene/product, with traits, reference images, conditioning references and revision/version state. Product validation currently requires `form` and `finish`; it does not define physical dimensions, joints, support contacts, screen masks or model qualification. [studio.go:29](/home/matthalloran8/Vrooli/scenarios/asset-studio/api/internal/studio/studio.go:29), [studio.go:49](/home/matthalloran8/Vrooli/scenarios/asset-studio/api/internal/studio/studio.go:49).

**Recommendation:** Device Studio owns an evidence-backed product/device definition and its physical variants, then pins an optional Asset Studio `product` identity/version for reusable appearance intent. A model realization, screen binding or shot references that definition by version/digest. Device dimensions and joints should not be duplicated into an independently mutable generic identity trait ledger. Device Studio may store its own domain records; that is different from inventing a second generic media release authority.

External media ingress exists. `IngestExternalAsset` stores supplied bytes through BlobStore, then creates an asset in `in_review`. It requires provenance, positive image dimensions, media type and alt text or a decorative claim. Model-backed disclosure requires a model and prompt; unknown model metadata from the chat's retained plate cannot honestly be invented to satisfy it. [connect_handler.go:412](/home/matthalloran8/Vrooli/scenarios/asset-studio/api/handlers/studio/connect_handler.go:412), [ingest.go:62](/home/matthalloran8/Vrooli/scenarios/asset-studio/api/internal/studio/ingest.go:62), [ingest.go:124](/home/matthalloran8/Vrooli/scenarios/asset-studio/api/internal/studio/ingest.go:124). Backdrop Studio supplies an actual example of calling ingress followed by release; its publisher does not establish that every intended policy was enforced. [assetstudio.go:70](/home/matthalloran8/Vrooli/scenarios/backdrop-studio/api/internal/release/assetstudio.go:70).

Three concrete integration limitations remain:

1. **No complete public byte-resolution contract in the inspected Asset Studio surface.** `AssetReference` carries ID/status/alt/disclosure/dimensions/MIME/derivation, but no URI, blob key, digest or download capability. `GetReleasedAssetReference` returns that same metadata. An inspected production-tree search found no `blobs.Get`/blob-download handler. [studio.proto:61](/home/matthalloran8/Vrooli/packages/proto/schemas/asset-studio/v1/studio/studio.proto:61), [connect_handler.go:480](/home/matthalloran8/Vrooli/scenarios/asset-studio/api/handlers/studio/connect_handler.go:480), [connect_handler.go:548](/home/matthalloran8/Vrooli/scenarios/asset-studio/api/handlers/studio/connect_handler.go:548). This is a bounded code-inspection finding, not a live fetch failure. Specify a producer-neutral artifact reference and a supported fetch/export edge before relying on Asset Studio IDs to deliver bytes.
2. **Ingress is still image-shaped.** The field is named `image` and validation requires positive pixel width/height. A movie has meaningful dimensions but needs duration/stream/frame-rate/codec semantics; a GLB/native scene does not have meaningful pixel dimensions at all. No inspected contract establishes model dependency closure, units or native-scene packages. [studio.proto:277](/home/matthalloran8/Vrooli/packages/proto/schemas/asset-studio/v1/studio/studio.proto:277), [ingest.go:72](/home/matthalloran8/Vrooli/scenarios/asset-studio/api/internal/studio/ingest.go:72). Keep device model/native-package artifacts in the Device Studio namespace and expose typed references. Extend generic registry admission deliberately if models/movies become first-class library records; do not fake pixel dimensions or flatten their manifests into alt text.
3. **The documented operator verdict is not a generic gate.** The ingress proto/comments say release needs an operator verdict. Ingested assets have no `IdentityVersionIDs`; `Release` checks verdicts only for entries in that list. Therefore identity-free external assets can satisfy current release checks without any verdict. [studio.proto:287](/home/matthalloran8/Vrooli/packages/proto/schemas/asset-studio/v1/studio/studio.proto:287), [ingest.go:92](/home/matthalloran8/Vrooli/scenarios/asset-studio/api/internal/studio/ingest.go:92), [studio.go:421](/home/matthalloran8/Vrooli/scenarios/asset-studio/api/internal/studio/studio.go:421). This is verified control flow, not a live release attempt. Device Studio must explicitly retain final-look acceptance, geometry qualification and rights checks; upstream release metadata is not evidence those passed.

The third item was filed through [report-bug SKILL.md](/home/matthalloran8/Vrooli/scenarios/prompt-manager/store/skills/packs/core/report-bug/SKILL.md): **`knw-1792449485196174451`**, topic `bug-inbox/code-defect/asset-studio-identity-free-external-release-omits-documented`, honesty flag `repro-not-attempted`. No repair was attempted.

**Recommendation:** private import, edit, replay and draft render work without Asset Studio being live. The saved shot pins its own immutable inputs and producer-owned references. Publishing a shared/released media record uses the canonical Asset Studio adapter when that contract is qualified. A failed registry handoff leaves `release-pending`/`release-failed`; it must not relabel the same draft as globally released or silently create an alternate disclosure authority. This split is a proposed Device Studio behavior, not a currently implemented guarantee.

## 4. Storage, durable jobs and execution are separate seams

**Verified shared storage primitives:** api-core `BlobStore` supports opaque bytes under caller keys with MIME metadata; `storage.ArtifactRef` names owner/domain/class/segments and deliberately contains no host path. Resolution enforces owner/namespace alignment. [blobstore.go:9](/home/matthalloran8/Vrooli/packages/api-core/blobstore/blobstore.go:9), [artifacts.go:10](/home/matthalloran8/Vrooli/packages/api-core/storage/artifacts.go:10). These primitives do not by themselves provide content addressing, immutable retention, cross-node transfer, dependency manifests or a release policy.

**Recommendation:** Device Studio owns its domain schemas/repositories and artifact manifests, with bytes through api-core storage in its own namespace. Use immutable artifact IDs/digests and explicit producer references, separate from mutable convenience aliases. A shot snapshot pins plate/model/native-package closure, source media, presentation profile, calibration, scene/render strategy and recipe. Keep source blobs with their producer unless a deliberate durable snapshot/import is made; record both identities rather than scraping another scenario's data directory. Asset Studio's current image dispatcher itself preserves Image Tools references without copying bytes. [dispatcher.go:173](/home/matthalloran8/Vrooli/scenarios/asset-studio/api/internal/studio/dispatcher.go:173).

**Verified producer jobs:** Image Tools owns persistence, progress, cancellation and GPU/CPU/network lanes for its operations. Client disconnect does not cancel server work; process restart marks interrupted jobs failed rather than pretending arbitrary backend work resumes. [manager.go:15](/home/matthalloran8/Vrooli/scenarios/image-tools/api/internal/jobs/manager.go:15), [manager.go:155](/home/matthalloran8/Vrooli/scenarios/image-tools/api/internal/jobs/manager.go:155), [manager.go:186](/home/matthalloran8/Vrooli/scenarios/image-tools/api/internal/jobs/manager.go:186). Asset Studio has its own render receipts/reconciliation and async dispatch. [connect_handler.go:290](/home/matthalloran8/Vrooli/scenarios/asset-studio/api/handlers/studio/connect_handler.go:290). These implementations are scenario-internal, not a verified universal renderer worker API.

**Recommendation:** Device Studio's durable parent job owns shot/creation stages and references producer child jobs. Keep the child's true receipt instead of synthesizing success or resetting source clocks on retry. Cancellation propagates to only owned child executions/scopes. Restart policy distinguishes replayable deterministic frame batches from non-idempotent paid generation; do not blindly resubmit a paid request after a lost acknowledgment. Device creation/refinement status is distinct from render status and final visual acceptance. Asset Studio's existing Agent Manager commissioner creates an ordinary untrusted proposal task; it does not start an autonomous model-construction run or approve output. [agent_manager.go:14](/home/matthalloran8/Vrooli/scenarios/asset-studio/api/handlers/studio/agent_manager.go:14).

**Verified execution primitives, not a ready Blender service:** `platform-go.ContainedCommand` offers a scope/process-tree ceiling, and managed HyperFrames uses it with owner cleanup and task-pressure checks. Linux is documented host-verified; macOS/Windows bodies have narrower compile/fixture evidence. [containment.go:16](/home/matthalloran8/Vrooli/packages/platform-go/containment.go:16), [containment.go:95](/home/matthalloran8/Vrooli/packages/platform-go/containment.go:95), [render.go:698](/home/matthalloran8/Vrooli/internal/tools/hyperframes/render.go:698). These do not provide a generic remote Blender worker, job scheduling, arbitrary-code filesystem/network isolation or portable GPU qualification. Image Tools' basic provider runners use `exec.CommandContext`, which is also not proof of that isolation. [providers.go:365](/home/matthalloran8/Vrooli/scenarios/image-tools/api/internal/ai/providers.go:365).

**Recommendation:** a control-plane-owned renderer/tool adapter must govern executable identity/provisioning and operation-owned process containment; Device Studio supplies the immutable job and consumes output/cleanup receipts. Reuse platform primitives and managed HyperFrames lessons, not the experiment's scratch `run_owned.py` as a standing service. Generated scene scripts remain untrusted inputs. A native Blender adapter, restricted working set, cancellation/descendant cleanup, memory/time/task limits and renderer/GPU qualification still require implementation/validation. Do not describe shared host scope observation as that renderer service.

## 5. Consumer contract and user flow

**Designed/recommended headless contract:** a caller should save an immutable shot revision, explain/validate its rendering strategy, request a preview, request a render, wait once, and retrieve a stable result package. The exact operation names and protobufs are not implemented by this research. The result should include independently downloadable PNG/MP4, source timing/fit and media geometry, content/recipe hashes, inherited rights/disclosure, final-look review status, technical validation and producer job links. GLB/native files are additional artifacts when that strategy supports them, not compulsory delivery for photographic plates.

Integrate at the shot boundary:

1. BAS supplies original media and measured capture facts. Its `CaptureArtifact.reference` explicitly warns consumers not to rely on the producer's local path. [capture.proto:177](/home/matthalloran8/Vrooli/packages/proto/schemas/browser-automation-studio/v1/capture/capture.proto:177).
2. Device Studio binds media to a physical display or photographic plane, applies a declared presentation profile, renders and retains the accepted strategy's limits. The current v6 proof shows this with an unchanged generated plate and deterministic screen replacement; it is not 3D hardware preservation. [v6 manifest](../../v6/laptop/manifest.json), [current domain design](../../v2/device-domain.md).
3. Launch-video selects the shot as product proof or a transition and assembles the final film. It must preserve authentic capture provenance, avoid unsupported device/native-runtime claims, and review the exact final MP4. [SKILL.md:273](/home/matthalloran8/Vrooli/scenarios/prompt-manager/store/skills/packs/core/launch-video/SKILL.md:273), [SKILL.md:402](/home/matthalloran8/Vrooli/scenarios/prompt-manager/store/skills/packs/core/launch-video/SKILL.md:402).

**Recommendation:** expose saved presets and meaningful controls, not a compulsory general 3D editor. Users choose imported/existing/generated assets, screen presentation and supported motion; the system explains incompatible requests before spending. Treat browser/system chrome in recordings as explicit source metadata so it is never added twice. Keep screenshots/videos/GLB downloads direct; working HTML navigation in a developer browser is not an artifact-viewer accessibility guarantee.

## 6. Operator choices worth surfacing

These are product/authority choices. Storage classes, RPC names, queue implementation, UI resampling and provider protocol adaptation are technical decisions to resolve in implementation, not multiple-choice homework for the operator.

| Decision | Recommended default | Alternatives and consequence |
|---|---|---|
| First appearance/release promise | Photographic scenes as the first accepted final-output workflow; 3D movement stays explicitly qualified/experimental until its look passes. | Ship both as equally production-ready, which current visual evidence does not support; or focus only on 3D and defer the demonstrated photographic value. |
| Behavior when the generic registry is unavailable | Allow private import/edit/render/replay; block only the requested shared release and show the exact pending handoff. | Require Asset Studio for every draft, increasing availability coupling; or independently release through a second ledger, creating conflicting authority. |
| Paid image generation | Explicit per-request or capped-session opt-in, estimated budget, actual/unknown cost reporting and a quality review before batch spend. Imported plates remain available. | Automatically escalate local failure to cloud under a preapproved cap; or prohibit cloud generation. An `available` role is not spending authority. |
| Reusable library sharing | Private candidates by default; operator-selected shared, reviewed scene/device/presentation versions. Keep rights and source records with the released version. | Automatically promote every successful technical render, which would repeat v5's confusion between checks and appearance acceptance; or keep all results private and lose shared reuse. |
| Fidelity claim for generated hardware | Label the strategy and supported motion envelope in editor/report metadata; never imply an exact named device/mesh when only a generated look is known. Keep film free of unnecessary production badges. | Require a measured 3D asset for all named hardware; this is stricter and reduces available photographic compositions. |

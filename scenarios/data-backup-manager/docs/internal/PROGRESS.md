| 2026-06-03 | matthalloran8 | done | **In-place snapshot for filesystem sources (perf/observability plan, Phase 3).** `sources/fs.go::Capture` now snapshots **directory** locators in place — `Artifact.Path` IS the live source path, `Bytes` is the logical tree size (new `treeSize` helper, symlink-safe), and nothing is copied to the stage dir — eliminating the read-source→write-/tmp→read-/tmp staging triple for the multi-GB trees (`data/`, `state/`, `projects/`, `sessions/`). **Single-file / single-symlink** locators (secrets.json, history.jsonl, config.toml — 4 of 16 targets) still stage under `fs/<basename>`, because a bare single-file kopia snapshot does not restore cleanly into a directory and the wrapping preserves the original filename across the round trip; they are tiny, so the copy is cheap. Deviation from the plan's "static `StageMode()` capability" contract decision: the staging choice depends on the locator shape (dir vs file), which a per-capturer static enum can't express, so the decision lives inside `fs.Capture` and the `Capturer` seam stays kind-neutral; the restore path is unchanged (kopia restores the snapshot-root's children into scratch — identical shape for in-place dirs and staged copies). **Security (release gate) PASSED:** empirically confirmed kopia stores symlinks as symlinks and never follows them (a restored link dangles once its target is removed); on the real harness, the in-place `state` snapshot restored to /tmp had **1104 `auth.json` symlinks, 0 real `auth.json` files, and 0 files matching the real credential content (4746-byte sha)** — the excluded `~/.codex/auth.json` credential is never dereferenced. **Validated:** unit tests (directory-in-place makes no copy + reports logical bytes; single-file still staged; symlink preservation through restore); real run 16/16 in ~8s with no `<stage>/fs` copy for directory kinds; full 274M `state` restore round-trips. Gates: `go build`, `go test ./internal/{sources,runs,restores}/`, `gofumpt` green. |

| 2026-06-03 | matthalloran8 | done | **Per-target kopia overhead — Phase 4 investigated & descoped (perf/observability plan).** Empirically confirmed `kopia snapshot create` applies `--override-source`/`--tags`/`--description` **globally** across multiple `--path`s, not per-path (two batched sources both got the colliding identity `dbm:/shared`).

# Decisions — Music Tools

This document records durable decisions and tradeoffs future agents
should not accidentally relitigate.

## Purpose Of This Document

Use this document when a choice:

- affects multiple files or future agents,
- rejects a plausible alternative,
- changes architecture, deployment, data, security, monetization, or
  testing direction,
- needs a revisit trigger.

Routine implementation log entries belong in [`PROGRESS.md`](PROGRESS.md).
Known unresolved issues belong in [`PROBLEMS.md`](PROBLEMS.md).

Model-level facts that back these decisions — identifiers, disk cost, VRAM,
licences — are in [`../reference/model-registry.md`](../reference/model-registry.md).

## Decision Log

| Date | Decision | Context | Consequences | Revisit Trigger |
|---|---|---|---|---|
| 2026-09-19 | **Keep turbo as the default after the controlled SFT comparison.** | The checksum-verified SFT artifact completed ten exact-brief/exact-seed music-tools jobs at 50 steps, CFG 7, and the `offload-dit` rung. Every job produced a 5.120-second WAV. Wall clock was 16.613–570.561 s (median 22.101 s), with the outlier reflecting capacity/reclaim contention. Proxy metrics were extracted for tempo, sub-bass, hi-hat energy, onset density, and RMS, but the retained analysis does not establish a listening-quality advantage over the turbo reference. | Turbo remains the production default: it has the established successful path, lower configured inference cost, and no grounded SFT quality advantage in this controlled evidence. SFT remains an available measured alternative when an operator accepts the extra 50-step/CFG and capacity tradeoff. The proxy table is evidence, not a quality verdict. | A retained apples-to-apples analysis implementation or a listening study shows a material SFT advantage on authored briefs, or a future host changes the timing/capacity tradeoff. |
| 2026-08-19 | Use the generated `react-vite` scenario documentation contract. | Scenario scaffold was generated from the template. | Docs start with stubs and maturity metadata in `docs/manifest.json`. | Revisit when scenario adopts a different template or doc contract. |
| 2026-08-19 | **ACE-Step 1.5 is the primary composition model, not MiniMax-Music3.** | MiniMax-Music3 is the stronger model on paper (11.1B, five-minute coherence) but needs ~22–24 GB VRAM and a 57.4 GB download. The reference host has a 16 GB card with ~9.9 GB free and 274 GB disk on a volume at 85%. ACE-Step is MIT, fits the free-VRAM tier, and ships the edit operations music work actually needs. | Composition targets a model that fits. The licence is unrestricted, so no attribution or revenue ceiling reaches the product. Quality ceiling is lower than the best available open model. | Revisit on a card with ≥24 GB VRAM, or if a legitimate quantised MiniMax-Music3 build appears. |
| 2026-08-19 | **Three isolated Python runtimes, two of them managed-service resources.** | The generation, music-information-retrieval, and embedding stacks pin mutually incompatible Python versions, torch builds, and NumPy majors. The shared sidecar provisioner (`pyenv-go`) syncs exactly one virtualenv per scenario. | `ace-step` and `music-mir` own their environments and lifecycles; only the compatible embedding stack runs in the in-scenario sidecar. Cross-runtime coordination is by job queue and filesystem, never shared imports. | Revisit if the upstream stacks converge, or if `pyenv-go` gains multi-environment support. |
| 2026-08-19 | Rejected extending the shared sidecar provisioner to hold multiple environments. | `pyenv-go` is a governed shared package; the isolation needed here is exactly what a separate resource already provides. | No change to a governed package is required to ship this scenario. | Revisit if a third scenario needs the same multi-environment shape. |
| 2026-08-19 | **No container runtime.** Resources acquire lockfile-pinned wheels and checksum-verified weights natively. | Existing GPU resources use compose overlays, but the desktop delivery tier cannot assume a container runtime is present. | Isolation is at the process and environment boundary. Install is slower and more platform-sensitive than pulling an image. | Revisit if native provisioning proves unreliable across target platforms. |
| 2026-08-19 | **Every GPU operation claims through the control-plane capacity broker.** | The card is shared with other Vrooli resources; `vrooli capacity` already provides claims, admission verdicts, degradation rungs, heartbeats, and reconciliation. | No private GPU queue. Operations declare ordered profile rungs so contention degrades quality rather than failing the job. The applied rung travels with the result. | Revisit only if the broker cannot express a needed policy. |
| 2026-08-19 | **Commercial-use lane is a first-class registry property, not a scenario-level assumption.** | Several of the strongest analysis models are non-commercial or share-alike, and at least one useful tool declares no licence at all. This scenario feeds a bundle intended to be sold. | Each model records its lane; a permissive-lane build refuses to resolve anything outside it. Unknown licences default to restricted. | Revisit when a restricted-lane model relicenses, or when commercial distribution begins. |
| 2026-08-19 | **Copyleft tools are invoked as separate processes, never linked in-process.** | Reference mastering's best open implementation is GPL-3.0. | Obligations do not reach the scenario binary. Costs a process hop on an operation that is already file-to-file. | Revisit if a permissively licensed equivalent reaches parity. |
| 2026-08-19 | **No entrypoint materialises stems for an entire library.** | Four stems for a 10,000-track library is roughly 1 TB even as FLAC, against 274 GB free. | Separation is on-demand with an LRU budget. The absence of a batch path is a design constraint, not a missing feature. | Revisit only alongside a storage tier sized for it. |
| 2026-08-19 | **Embeddings persist pooled or segment-level; frame-level requires explicit single-track opt-in.** | Frame-level output for one four-minute track is roughly four orders of magnitude larger than its pooled form. | The library-wide index stays small. Frame-level analysis is an interactive operation, never a batch product. | Revisit if a use case needs frame-level data at library scale. |
| 2026-08-19 | **Personal adapter training is a P2 target, not a shipping feature.** | Published guidance for the chosen generator states 16 GB minimum and roughly 17 GB typical during training. The reference card has 16 GB total and ~9.9 GB free. | Personalisation ships as a lightweight head over frozen embeddings, owned by the consumer scenario. Adapter training is documented but gated on hardware. | Revisit on a card with ≥24 GB VRAM, or if a materially cheaper adapter method is verified. |
| 2026-08-19 | **A dedicated separator is a hard dependency, not a quality upgrade.** | The generator's own documentation is internally inconsistent about which model variants support track separation, and the variant that fits the free-VRAM tier is the one most likely to lack it. | Stem separation is owned by `music-mir` and never assumed available from the composition runtime. | Revisit when upstream resolves the contradiction; the dependency stays regardless because it is also the better separator. |
| 2026-08-19 | **Lyric transcription lives here, not in `audio-tools`.** | General speech recognition performs poorly on sung vocals; the useful models are music-specific. | A music-specific transcription operation exists here. No general speech capability is added. | Revisit if `audio-tools` gains a singing-aware engine. |
| 2026-08-19 | **Tempo and key are estimated by vote across independent estimators, and disagreement is retained.** | Three independent estimators are available at no extra cost. Disagreement correlates with rubato, ambiguous tonality, and half/double-time ambiguity. | Estimates carry a confidence signal, and disagreement itself becomes an attribute consumers can use. | Revisit if a single estimator is shown to dominate. |
| 2026-09-18 | **Composition returns a set of takes, not a track. Selection is the quality mechanism.** | The 2026-09-18 spike measured what the operator accepted: no single generation was reliably usable, but a batch of ten contained several that were. A stock library track is itself chosen from a large pool, so comparing one generation against one curated winner is not a fair test. Prompt wording moved the result more than any model parameter. | The composition operation takes a brief and a count and produces N takes, every one retained with its own provenance. Callers select; the operation does not rank. Storage budgets must be sized for the discarded takes, not just the kept one. The style library (`OT-P0-007`, promoted from OT-P1-004) stops being a convenience and becomes the unit a batch is configured with. | Revisit if a model or a reranker makes single-shot generation reliable enough that surplus is waste. |
| 2026-09-18 | **The caption reaching the generator is the caption the caller wrote, unless the caller asked otherwise.** | The upstream planner LM rewrites the caption and invents metadata by default (`use_cot_caption`/`use_cot_metas` default true). Measured: an authored 144 BPM "cold, detuned, menacing" brief reached the model as 65 BPM "shimmering, melancholic, ethereal". Disabling it moved hi-hat band energy 19.1%→27.5% and onset density 6.2→9.6/s at a fixed seed. | Caption rewriting is opt-in, never a library default inherited silently. When a rewrite happens, the rewritten caption is part of the operation's report — a caller must be able to see what the model was actually asked. | Revisit if a planner is shown to improve results on authored briefs rather than regress them. |
| 2026-09-18 (reasoning narrowed same day) | **No hosted generation rung. The provider-chain seam is adopted; the remote rung is not built.** | **The decision rests on one argument: licence exposure.** Hosted music generation is where per-generation royalties and contested training-data provenance actually live, which is the exact problem this scenario exists to escape; routing there would re-import it. Music is the modality where that argument is strongest — it does not transfer from `image-tools`, which runs local→CPU→BYOK through `ai-gateway` freely. Two mechanical blockers remain true: the gateway's `RequestKind` enum has no audio member (verified — text, embedding, extraction, image, video, and nothing else), and no hosted music provider is wired in `resources/`. **A previously recorded supporting argument has been withdrawn:** that a hosted rung would oblige this scenario to declare meters and entitlement. It would not. `image-tools` calls the gateway as an ordinary registered provider and carries no `.vrooli/monetization.json`, no entitlement, and no quota logic; subscription and metering live entirely in `ai-gateway`. That argument was wrong and should not be reused. | Composition fails explicitly rather than falling back to a cloud provider. No meters here — but because there is no metered path, not because a hosted rung would create one. The chain *shape* (`tiered.CredentialProviderChain`) is adopted so a rung can be added without rework; it currently lives in `audio-tools/api/internal/ai/chains/tiered` and would need promoting to `packages/` before a second scenario uses it. If the rung is ever built, the shape to copy is `image-tools`' per-request tier ladder (`allow_byok`, `fallback_policy` ∈ `any`/`cloud_allowed`/`local_only`), not a configured lane. | Three triggers, any one sufficient. **(1)** A hosted music provider offers commercially clean terms for generated output. **(2)** A measured quality gap against local output is large enough to justify the licence exposure. **(3)** **Hardware reach** — see the row below. |
| 2026-09-18 | **Local-only composition means GPU owners only, and that is now a stated consequence rather than an unexamined one.** | There is no CPU rung for composition and there will not be one: generation on CPU is not a degraded rung, it is an eternity. `image-tools` can degrade to CPU and still serve a user with no GPU; this scenario cannot. The no-hosted-rung decision above was argued entirely on distribution liability and never engaged this, so "local-first" quietly meant "unavailable to anyone without a capable card". | The audience for any product built on composition is bounded by hardware. Consuming scenarios must handle composition being *structurally* unavailable, not merely busy. `resources/ace-step` declares no CPU rung, so the ladder is `full → offload-dit → refuse`. | Revisit — and reconsider the BYOK rung specifically — when an operator without a capable GPU is a real user rather than a hypothetical one. A BYOK rung is also a materially different licence risk from a Vrooli-hosted one, because the operator's own key and own provider terms apply; that distinction was never separated in the original decision and should be, if this is reopened. |
| 2026-09-18 | **This scenario owns batch mechanism and caller-declared inventory policy; it does not own taste.** | `PRD.md` names the pool's intended owner as a consuming scenario, but `music-library` is 100% generated scaffold — its only API domain is `notes`, the same state as this scenario. The real consumer today is an agent running a skill, which cannot own durable inventory. Deferring the pool to a consumer means deferring it indefinitely. | Maintaining N ready takes for a named style is in scope: it is configuration, not opinion. Recording *which* take a caller selected is in scope: it is a fact about an artifact. Inferring preference from picks and skips to tune future briefs is **out** of scope and stays the consumer's, with the selection provenance as the seam it reads. | Revisit when a consuming scenario reaches a maturity where it can hold the inventory, at which point this scenario keeps the batch operation and sheds the pool. |

| 2026-09-18 | **Most of this scenario's infrastructure is a port from `image-tools`, not a fresh design.** | A survey on 2026-09-18 found `image-tools` already ships working equivalents of most domains declared here: `looks` (a named style compiling to prompt plus parameters — compiler, schema, seed, store) is `styles`; `backends`, `jobrunner`, `jobs`, `models`, `storage`, `measures`, `pyenv`, and `sidecar` all have direct counterparts. Its job model is already lane-based (`gpu` serialized, `cpu` concurrent, `network` pooled) and durable, and its capacity broker already handles an advisory host. Designing these again would be waste, and would drift from a proven sibling. | The twelve-domain inventory in `DOMAINS.md` overstates how much is new. The genuinely novel surface is three things: composition-as-batch, the take pool, and the two resources. Everything else starts from the `image-tools` implementation and diverges only where a recorded decision says it must. | Revisit per-domain if a port proves a worse fit than a rewrite; record the reason when it does. |
| 2026-09-18 | **Takes are peers; there is no primary result.** | `image-tools` implements variations as one primary result plus indexed extras inside a single job. Inheriting that shape here would quietly reintroduce ranking, which the batch-of-takes decision above rejects — the whole point is that the scenario has no opinion about which take is better. | The composition batch returns N equal takes. No take is marked primary, ordered by quality, or pre-selected in any surface. This is a deliberate divergence from the sibling being ported, and is called out in `DATA.md` and `experience/pages/audition.json` so it is not "fixed" later by someone matching the sibling. | Revisit only alongside the batch-of-takes decision itself. |

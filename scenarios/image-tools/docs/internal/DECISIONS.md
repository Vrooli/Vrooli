# Decisions — Image Tools

This document records durable decisions and tradeoffs future agents
should not accidentally relitigate.


Use this document when a choice:

- affects multiple files or future agents,
- rejects a plausible alternative,
- changes architecture, deployment, data, security, monetization, or
  testing direction,
- needs a revisit trigger.

Routine implementation notes belong in [`PROGRESS.md`](PROGRESS.md).
Known unresolved issues belong in [`PROBLEMS.md`](PROBLEMS.md).

| 2026-11-21 | **Cloud fallback rule: local first; the cloud is used only inside a per-job and a rolling daily spend cap.** (`api/internal/ai/route*.go`, `internal/jobs` re-route, `ai.proto` fields 32-35.) (1) The cloud is used in three cases only: (a) the host has no usable GPU for `edit_instruct`, `image_to_image` or `text_to_image`, so the best local answer is a weak CPU model; (b) a job that has not started waited past its **wait budget** (queue plus capacity admission) and is re-routed once, before it starts; (c) the caller asked for it (`--byok`, a role, `--model openrouter-image`). The caller's `--fallback-policy local_only`, `--require-gpu`, `--force-cpu`, an explicit local `--model`, or a conditioning adapter always keep the job local. (2) Defaults, for this operator's host: ON, wait budget 10 min, $0.25 per job, $3 per rolling 24 h (`IMAGE_TOOLS_CLOUD_FALLBACK`, `_WAIT_BUDGET`, `_MAX_JOB_USD`, `_MAX_DAILY_USD`, `_COST_ESTIMATES`; a malformed value stops the service). Per request: `--max-wait` (`0` = wait locally without limit), `--max-cost` (`0` = no cloud spend), `--edit-style`; the daily cap is deployment-owned and not settable per request. (3) **Caps are enforced from recorded `cost_usd`**, read from the durable job table: finished jobs in the last 24 h (a succeeded job's `cost_usd`, a failed job's known per-attempt costs in its gateway evidence) plus the pinned estimate of every cloud job still in flight that was created earlier. No in-memory counter, so a restart cannot reset the day. The per-job cap compares a per-role cost *estimate* (`route.go`, identity 0.14, default edit 0.05, quality generate 0.14, default generate 0.05) because the true cost only exists afterwards; a result above the cap is flagged `route_cost_over_cap`. The check runs at submit (refusal: HTTP 402 `ErrSpendCap`, nothing queued), at the moment of a re-route, and again in admission, immediately before the one call that can bill. An unreadable ledger fails closed. (4) **Never run or billed twice.** The re-route is a `jobs.Rerouter` hook the scheduler offers to every local job that has not started running: jobs still queued, and jobs inside admission (waiting on host capacity or revalidating/downloading a model, which is where the long local waits happen; the 2026-11-21 live proof showed a 5 s budget could not fire until this was covered). A queued job is moved in place under the scheduler locks. A job inside admission is claimed under its entry lock, its admission is cancelled, its leases are released, and only then is it re-queued on the network lane with the new payload; `startRunning` refuses a claimed job under the same lock, so a job is either moved or run, never both. A cancelled model download restarts from the downloader's resume state rather than being finished first. The moved payload is marked `rerouted`, so it is never offered again; a running job is never moved; a user cancel still wins. (4b) **A refused cloud route falls back to local, and pauses the cloud.** If a re-routed job's cloud attempt is refused before any billing (HTTP 401/402/403/429/503 or a provider code such as `insufficient_credits`, `provider_unavailable`, or the gateway unreachable) or the caps fill before the call, the job is returned to its original local payload (kept in `route.local_payload`) through `jobs.RouteBackError`, never failed; meta: `route_reason=cloud_unavailable_fell_back_local`, `route_cloud_refusal`, `route_cloud_refused_at`. Any other cloud failure may have been billed and stays an honest failure. The refusal also starts a cooldown (`IMAGE_TOOLS_CLOUD_COOLDOWN`, 30 min, 0 = off) that blocks automatic cloud use (GPU-less preference, arming, re-route, admission of already re-routed jobs); it is derived from jobs whose meta carries `route_cloud_refused_at`, so it is durable and shared with no new store. A caller who demanded the cloud (`--byok`, a named role) is not paused and gets the honest error, which still records the refusal. Why: with credits exhausted, re-routing after the wait budget turned a slow job into a failed one (jobs 8e72e912, 843a539e). (5) **Role choice.** A caller's role wins. Generation: `image.generate.quality` under `--quality-policy quality`, else `image.generate.default`. Edits: an explicit `--edit-style` decides; otherwise a prompt that *restyles* the image (anime, manga, cartoon, illustration, cel-shaded, watercolor, oil painting, sketch, line art, pixel art, vector, 3D render, "in the style of", ...) is stylised and goes to `image.edit.default` (Seedream), and anything else is an identity-preserving edit and goes to `image.edit.identity` (Gemini); no signal means identity, because a lost likeness is harder to repair than a styled image. (6) **Everything is in the job meta**: `route_choice`, `route_reason` (`no_usable_gpu` / `no_local_model` / `wait_budget_exceeded` / `caller_requested_cloud`), `route_rerouted`, `route_waited_seconds`, `route_wait_budget_seconds`, `route_local_model/provider/tier` (the original local choice), `route_role` + `route_role_reason`, `route_max_cost_usd`, `route_estimated_cost_usd`, `route_daily_cap_usd`, plus the backend's `cost_usd`. Failed jobs keep the `route_*` keys. (7) **Identity preservation is on by default for `edit_instruct`**: " Preserve the subject's identity: keep its exact pose, face and distinguishing markings (and, unless the instruction restyles the image, its colors and proportions). Change only what the instruction asks for." is appended unless the prompt already says it; `--no-preserve-identity` sends the prompt verbatim; `effective_prompt`, `prompt_original` and `identity_preservation` (`applied` / `already_present` / `off`) are always in the meta. (8) **Release is a cleanup problem, not a work failure.** Every admission that holds ledger claims (AI, analysis, CPU support, quality) is `ReleaseRetryable`, including a refused or partial one; when the budget (2 min) is exhausted *after the work succeeded*, the job keeps its result and records `capacity_release=unconfirmed` plus the warning, because the claim's TTL reclaims it. A release that left a worker running or output files unverified (`ErrReleaseLeaksWork`), a non-retryable release, a failed run and a canceled job still fail. (9) `models select`, the model picker and `ai --explain` judge GPU fit by the rule jobs use (total VRAM when the capacity broker owns GPU admission, read from `Engine.CapacityManagedGPU`), not free VRAM. (10) NSFW/OCR analysis revalidates an installed `smoke_pending` / `build_not_ready` / `needs_backend` model through `modelstorage.EnsureInstalled`, exactly as the AI engine does. | Operator, 2026-11-21: "Keep local first. Let a caller set a waiting limit and a spending cap. Use the cloud for edits on machines without a GPU when spending is allowed. Gemini handles edits where keeping the subject's identity matters most; Seedream handles styled images." The 2026-11-21 showcase measured what each side costs: local FLUX.2 klein is excellent but jobs waited 4-30 min for host-RAM admission, on a GPU-less host the fallbacks (SD 1.5, InstructPix2Pix) lost the hat, tinted the image green and dropped markings, and Gemini cost $0.138 an edit. The wait budget is measured from `created_at` rather than from admission start because the operator-visible delay is the whole wait, and a job inside a long admission (a model download, a held host ledger) is cancelled and moved, because that wait is what the operator experiences. The ledger reads the job table rather than a counter because the job table is already the durable record of what ran and cost. Estimates are conservative ceilings until real runs calibrate them; the ledger uses recorded cost the moment a job finishes. The three failures at capacity release in the showcase (four succeeded cloud edits marked failed while the output sat in the blob store) were the contended fleet-wide capacity-admission lock, not a work failure. | Agent-authored; `internal/ai/route_test.go`, `internal/jobs/reroute_test.go`, `internal/jobs/scheduler_test.go`, handlers/models `gpu_fit_consistency_test.go`, analysis admission tests, CLI `generation_test.go`; live proof in `~/.vrooli/research/topics/image-tools-foundation/runs/showcase-20261121/outputs/routing-proof/`. | 2026-11-21 | **Model weights: auto-acquire on demand and adaptive offload by disk headroom** (`api/internal/modelstorage`). (1) A job whose selected model is enabled, passes `RequireLocalUsePermitted`, has a non-manual seed source, satisfies the load-smoke contract and has a ready native backend acquires missing weights through the existing Installer and shared disk admission during admission, before any RAM/CPU/GPU lease; the job message says `acquiring weights for <id>`. Manual, custom, imported and local-path entries never auto-acquire. Caller opt-out `AIParams.auto_acquire=false` / `--no-auto-acquire`; service switch `IMAGE_TOOLS_MODEL_AUTO_ACQUIRE` (on). (2) Headroom = free bytes on the models filesystem minus the 120 GiB floor every Image Tools disk admission requests. Ample ≥ 96 GiB keeps everything; between the 24 GiB reserve and ample the idle threshold shrinks geometrically from 30 d to 1 d (~5.5 d half-way); below the reserve (or reserve + a pending acquisition's peak) the highest-priority eligible models go until the target is restored. Priority = (idle h + 1) × bytes ÷ (bytes/throughput + 120 s). (3) Last use = max(latest successful durable job, install receipt time); a model with neither is `use_unknown` and protected. (4) Protections: shared use lease held, named by a non-terminal job, operator keep pin, installed < 1 h, not auto-reacquirable, BuildProfile export, use unknown. Every attempt writes a `model_offload_receipt`. (5) Periodic pass every 30 min, first pass 20 min after start, plus a pass before an acquisition that needs room. (6) A shared-disk admission denial while raw headroom covers the peak (other owners' reservations) requeues the job with capacity backoff instead of failing; `packages/capacity` exports `ErrDiskAdmissionDenied` for this. (7) An installed model whose lifecycle is `smoke_pending`, `build_not_ready` or `needs_backend` is revalidated by the job through the same Installer path as `models install` (no download when the weights validate); `smoke_failed`, `smoke_unsupported` and `env_not_provisioned` still refuse because a rerun cannot change them. (8) Disk peaks are realistic: model root 1.25× (one staged copy renamed on the same filesystem plus slack for approximate catalog sizes), temporaries ¼×, Hub cache min(size, 1 GiB) because `snapshot_download(local_dir=staging)` writes under staging; reinstalling weights that validate plans no peak at all. The fixed 25 GB owner ceiling now bounds only probed (undeclared) sizes; declared sizes are bounded by shared host admission against the 120 GiB floor, and lease growth by max(25 GB, 2× plan). | Operator, 2026-11-21: "it should ideally auto download if space available, and be intelligent enough to decide how frequently to offload based on available disk space." The floor is already the shared admission boundary, so headroom above it is the only space Image Tools can spend. The reserve fits a ~10 GiB model's install peak (2× artifact + temp + HF cache) without touching the floor; ample is four reserves, where idle weights cost nothing. Geometric interpolation makes each lost GiB tighten the threshold by the same factor instead of keeping weights until a cliff. The former 2× root + 1× Hub cache + ¼× temp plan charged 3.25× (25,025,000,001 bytes for the 7.7 GB instruct-pix2pix, 54.5 GB for the 16 GB FLUX.2-klein), so revalidations and every model above ~7.7 GB were refused by a fixed ceiling regardless of free disk. The fixed re-acquisition cost makes one large idle model preferable to many small ones, while idleness dominates between similar sizes.

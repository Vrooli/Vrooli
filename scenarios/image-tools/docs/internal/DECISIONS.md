# Decisions — Image Tools

This document records durable decisions and tradeoffs future agents
should not accidentally relitigate.

## Purpose Of This Document

Use this document when a choice:

- affects multiple files or future agents,
- rejects a plausible alternative,
- changes architecture, deployment, data, security, monetization, or
  testing direction,
- needs a revisit trigger.

Routine implementation notes belong in [`PROGRESS.md`](PROGRESS.md).
Known unresolved issues belong in [`PROBLEMS.md`](PROBLEMS.md).

## Decision Log

The decisions below were locked in the 2026-06-16 design workshop. All
are **Accepted** as of that date unless a later supersession is recorded.

| Date | Decision | Rationale | Status |
|---|---|---|---|
| 2026-06-16 | **Headless-completeness is a HARD tenet.** Every operation runs from the CLI with no UI and no ComfyUI. | The CLI is the canonical surface; the UI is an enhancer, not a gate. Other scenarios and agents compose image-tools programmatically. Acceptance is verified by running the full op set on a fresh GPU-less / ComfyUI-less machine. | Accepted |
| 2026-06-16 | **ComfyUI is an OPTIONAL plug-in backend, never required.** Every AI op must have ≥1 standalone (non-ComfyUI) backend. | ComfyUI is heavy and not present on most hosts. Requiring it would break the headless tenet and tiny-laptop deployments. It is accepted as a second provider only when already installed. | Accepted |
| 2026-06-16 | **Text→image generation lives IN image-tools** as a primitive `generate` verb, not in the future rich-media-studio. | Generation is a foundational image capability, not campaign orchestration. Placing it here keeps it reusable by every consumer. | Accepted |
| 2026-06-16 | **image-tools and rich-media-studio are SEPARATE scenarios.** | image-tools is the capability primitive (single image ops); rich-media-studio is campaign orchestration that consumes it. Mixing the two would couple a reusable primitive to a higher-level workflow. | Accepted |
| 2026-06-16 | **No-GPU fallback chain = Local-GPU → Local-CPU → BYOK cloud.** CPU fallback is supported even with no BYOK key, with an explicit time warning. | Guarantees every AI op works on any host. CPU fallback prevents a hard dependency on a paid key; the time warning sets expectations. | Accepted |
| 2026-06-16 | **Persistent storage via api-core storage/blobstore** by default (outside repo); save location overridable per request; outputs are user-owned. | Reuses the platform storage substrate rather than reinventing it. Per-request override and user ownership keep outputs portable (copy/move/delete anywhere). | Accepted |
| 2026-06-16 | **image-tools OWNS image→text (OCR / caption / alt-text); text-tools owns document→text.** | Clear, non-overlapping boundary prevents duplicate capability and conflicting models across the `*-tools` family. | Accepted |
| 2026-06-16 | **Palette extraction delegates to palette-gen.** | palette-gen already owns this capability; image-tools calls it instead of reimplementing, avoiding duplication. | Accepted |
| 2026-06-16 | **Hardware detection reads host facts through the root `vrooli` CLI** (`vrooli host inventory --json`) via the typed client `packages/vrooli-cli-go`, decoded behind the image-tools `CapabilityProbe` seam. **system-monitor is NOT modified.** | OS/hardware detection is already owned by the shared `internal/hostinventory` collector and surfaced by the root CLI's `cli/v1` host-inventory contract. Consuming it via `vrooli-cli-go` avoids forking detection logic or coupling image-tools to system-monitor; the only upstream change is extending the root CLI's typed subset (GPU/VRAM/CPU/os). Supersedes the original "via system-monitor probe" wording. | Accepted (revised 2026-06-17) |
| 2026-06-16 | **Model selection is driven by a declarative, schema/proto-validated model registry with hardware-fit.** Per-op defaults + user override; custom/fine-tuned local models supported. | A declarative registry makes selection auditable, testable, and extensible. Hardware-fit lets the same op pick the right model per host. Override and custom entries keep power users unblocked. | Accepted |
| 2026-06-16 | **Async jobs are durable + server-owned** (survive client disconnect) and follow the test-genie run-lifecycle philosophy: job-id + ETA up front, block-once wait, no polling. A GPU-serializing queue runs heavy jobs one at a time while cheap CPU ops run concurrently. | Client cancellation must not destroy in-flight work (mirrors the test-genie durable-run fix). Serializing GPU work prevents VRAM contention; concurrent CPU ops keep cheap work responsive. | Accepted |
| 2026-06-16 | **Face restoration is exposed as its own op.** | A face-restore model already ships for old-photo restoration; surfacing it directly gives users a first-class, composable operation. | Accepted |
| 2026-06-16 | **NSFW detection is both a standalone op and a configurable auto-scan** of generated output. Generation models carry capability labels (NSFW-capable, license/commercial-use, lineage, known-risks). No formal "copyright" label exists. | Safety must be usable directly and applied automatically to AI output. The industry has no standardized copyright label, so copyright/legal lineage risk is captured as free-text known-risks instead of a fabricated boolean. | Accepted |
| 2026-06-16 | **C2PA content credentials supported as opt-in, off by default.** | Provenance signing is valuable but adds a signing key and overhead; defaulting off keeps the common path lightweight and avoids surprising users. | Accepted |
| 2026-06-16 | **Webhook callbacks are MINIMAL: per-job signed URL + best-effort retry — NOT an event bus.** | Job-completion notification is a small, contained feature. A full pub/sub event bus would be disproportionate new infrastructure and attack surface. | Accepted |
| 2026-06-16 | **Image diff / visual-comparison is built as a general capability that test-genie can later ADOPT.** | Building it generically (successor, not overlap) lets test-genie consume one canonical visual-regression backend rather than maintaining a parallel one. | Accepted |
| 2026-06-16 | **NON-GOALS (explicitly rejected scope):** no face recognition / identity matching; no face-swap / deepfake / try-on; no video / motion content (→ rich-media-studio); no vector editing (SVG is raster import/export only). | These are ethically fraught, out of the single-image-primitive scope, or owned by another scenario. Recording them prevents scope creep and accidental relitigation. | Accepted |
| 2026-06-16 | **Model registry SEEDED with a CPU-capable, commercial-clean default + one quality tier per op** (49 entries / 26 ops). Seed: [`api/internal/models/registry.seed.json`](../../api/internal/models/registry.seed.json); catalog: [`reference/model-registry.md`](../reference/model-registry.md). | Gives the registry mechanism (OT-P0-006) a concrete, license-verified baseline. Every op works headless on CPU; quality tiers are opt-in. | Accepted |
| 2026-06-16 | **Stay GATE-FREE on generation licenses:** ship only no-cap licenses (SD 1.5 / SDXL OpenRAIL, Flux.1 schnell Apache). EXCLUDE Stability's $1M-revenue-gated SD 3.5 / SD-Turbo. | Avoids any revenue-tracking obligation or commercial-license exposure for downstream users of a monetizable scenario. | Accepted |
| 2026-06-16 | **Optional Python sidecar is ALLOWED for quality-tier models** (RestoreFormer++, SCUNet, Restormer, DDColor-large, RAM++, Marigold, Florence-2); never required. | Unlocks best-quality PyTorch-only models without breaking the headless / Go-native default tier. The CPU default for every op stays compiled-binary / ONNX / pure-Go. | Accepted |
| 2026-06-16 | **GFPGAN is EXCLUDED; RestoreFormer++ (Apache-2.0) is the sole face-restore backend.** | GFPGAN's "Apache" license embeds StyleGAN2 (NVIDIA non-commercial) + DFDNet (CC-BY-NC-SA) and its ncnn port is GPL — not commercial-safe. RestoreFormer++ is cleanly licensed. | Accepted |
| 2026-06-16 | **Registry carries an explicit BLOCKLIST of license-encumbered models** (CodeFormer, GFPGAN, bria-RMBG, FastSAM, Ultralytics-YOLO, YOLO-NAS, InsightFace, Surya, community-NC ESRGANs, MAT, Flux-dev/Fill, SD3.5/Turbo, Qwen-VL-3B, LLaVA, pyiqa, libpHash, tuotoo-qrcode, …). | These are the most-recommended models online and would be adopted by accident. Two rules: check *weights* license separately from *code*, and ONNX/GGUF export never strips AGPL or a non-commercial weight license. | Accepted |
| 2026-06-16 | **Model checksums are captured + pinned on first download — NEVER hand-written.** Seed ships empty `checksum.value` with `status: unverified-capture-on-download`. | A fabricated hash is false verification. Pinning on first real download gives genuine integrity checks thereafter. | Accepted |
| 2026-06-17 | **AI generation/enhancement ops are ASYNC (durable job Submit, GPU-serialized lane); analysis ops are SYNC (inline + jobs.Record).** | Generation/enhancement are heavy and must survive client disconnect + serialize GPU/VRAM; analysis returns small structured data in seconds, so a synchronous edge is simpler for callers while staying observable via recorded jobs. | Accepted |
| 2026-06-17 | **Backend `Available()` = the program resolves on PATH; model-weight presence is a SEPARATE engine-level gate.** | The selector chooses the model before a provider is picked, so a per-model availability check can't live on the provider interface. Splitting the two lets the engine emit a precise "model not installed — run `models install <id>`" hint (proven live as HTTP 409) instead of an opaque selection failure. | Accepted |
| 2026-06-17 | **The headless-completeness acceptance for AI ops is an ATTENDED run** (after Phase-4 model download); CI drives the full vertical with FAKE providers, and `probe` is the always-headless live proof. | The standalone backend binaries (sd, realesrgan, rembg, iopaint, tesseract) + multi-GB CPU models cannot be installed in CI. Arg-builders are unit-tested (assembly), execution is gated on availability, and the pure-Go probe is verified end-to-end — so correctness is real without faking a green that needs absent weights. | Accepted |
| 2026-06-17 | **N variations are produced by looping the single-output provider (seed+i) within one job;** the primary result ref is the first output, the rest are emitted in the job message. | Keeps the job model "one job → one primary image" (trivial common path, simple blob fetch + auto-scan) while still honoring `variations>1` deterministically. The Phase-4 UI variation picker consumes the emitted set. | Accepted |
| 2026-06-17 | **NSFW decision threshold is operator-tunable (default 0.5); the generation auto-scan hook DEGRADES to "not flagged" when the classifier is unavailable** (logged, never fails the job). | AdamCodd over-flags skin tones, so a fixed threshold is wrong; and an absent/optional safety classifier must not break generation. Standalone NSFW-op usage still surfaces the unavailability as an error. | Accepted |
| 2026-06-17 | **Deterministic ops (req 01) EXECUTE SYNCHRONOUSLY in the request and are RECORDED as terminal jobs** (`jobs.Manager.Record`) rather than submitted to the async queue. | They finish in milliseconds, so the durable queue's disconnect-survival buys nothing, while a queue round-trip adds latency. Recording keeps them uniformly observable in `jobs list` / the UI monitor. Heavy AI ops (Phase 3) use the async Submit + dispatcher path. | Accepted |
| 2026-06-17 | **Output encoding (format + quality) is a property of the OUTPUT, set via `?format=`/`?quality=` on the REST run edge — NOT a field on every op's typed params.** The CLI derives them from the `--out` extension; `convert`/`compress` still own an explicit `format` in their params (which wins). | Encoding is orthogonal to the transform: `--out result.webp` should yield WebP for `resize` just as for `convert`. Putting a `format` field on all 13 op messages would be noise; a single output override keeps the contract clean. | Accepted |
| 2026-06-17 | **Image codecs are pure-Go / WASM (no cgo):** stdlib (png/jpeg/gif), `golang.org/x/image` (tiff/bmp/webp-decode), `disintegration/imaging` (transforms), `gen2brain/{webp,avif,heic}` (WASM via wazero), `srwiley/oksvg`+`rasterx` (SVG raster), `dsoprea/go-exif/v3` (EXIF). | Honors the headless + cross-platform tenet — cgo libheif/libaom would break tiny-laptop and Windows installs. WASM codecs run anywhere Go runs. User-approved dependency set (2026-06-17). | Accepted |
| 2026-06-17 | **HEIC is decode-in / convert-out only (no HEIC encode); SVG is raster import only (never an output format).** | The HEVC encoder is patent-encumbered and not bundled; SVG is vector. Both are common INPUTS worth accepting; neither is needed as an output. SVG rasterization is bounded by `MaxSVGRasterDimension` (the vector analogue of the decompression-bomb guard). | Accepted |
| 2026-06-17 | **The first real domains are `jobs` (durable-job lifecycle) and `models` (registry read + enable/disable), replacing the template `notes` reference end-to-end.** Job *submission* is op-specific and lands per-operation from Phase 2; `jobs` exposes only the shared lifecycle verbs (get/wait/list/cancel/watch). | These are the two surfaces the spine can expose with zero image ops, satisfying Phase 1's "boots healthy with zero ops". Submission belongs with the ops that define each payload shape. | Accepted |
| 2026-06-17 | **`internal/jobrunner.Dispatcher` is the seam between the single durable-job Manager Runner and per-operation execution.** Operation domains register a handler keyed by op name; an unregistered op fails with `ErrNoRunner`. | The Manager runs one Runner; ops need many. A keyed dispatcher is the forward-correct fan-out, not throwaway scaffolding — Phase 1 registers nothing (no op can run yet), Phase 2 ops plug in here. | Accepted |
| 2026-06-17 | **`common.proto` (op envelopes / image-ref / dimensions) is DEFERRED to Phase 2; no `/measures` substrate is mounted until the first op declares a measure.** | Greenfield forbids dead code. Those messages and the measures serve-registry have no consumer until image operations exist; defining them now would ship unused scaffolding. | Accepted |
| 2026-06-17 | **Model enabled-state is overlaid in SQLite (`model_state` table); the seed JSON stays read-only.** A model with no row uses its seed default; toggling writes exactly one row. | Keeps the license-verified seed immutable and auditable while letting operators opt quality tiers in/out durably. Effective enabled = overlay ?? seed, used identically by the selector and the wire shape so they never disagree. | Accepted |
| 2026-06-17 | **ComfyUI is wired as an OPTIONAL `dependencies.resources` entry and ffmpeg as an OPTIONAL `hostTools` entry; neither is ever required.** No "model-runtime" resource is declared — AI model download/runtime is managed internally by the model registry, not as a Vrooli resource. | Matches the headless tenet (every op has a standalone non-ComfyUI backend; deterministic ops use pure-Go imaging, ffmpeg only for AVIF/HEIC). Declaring a non-existent resource would fail validation. | Accepted |
| 2026-06-17 | **Ingest guard bounds (decompression-bomb defense):** encoded payload ≤ 64 MiB; decoded raster ≤ 128 MP; each side ≤ 30000 px. Checked from the image header (`image.DecodeConfig`) BEFORE decoding pixels; unrecognized formats pass on the byte cap and are caught by the later decode. Bounds are configurable per `Guard`. | A tiny encoded file can declare an enormous raster (a ~1 KB PNG → tens of GB decoded). The byte cap bounds the encoded payload; the MP/dimension caps bound the allocation, enforced before any large alloc. Defaults are generous enough for real photography while blocking bombs. | Accepted |
| 2026-06-17 | **Commercial-clean gate is "no outright `commercial_use:no`; `conditional` allowed only when disabled-by-default + annotated."** (Relaxes the earlier "every seeded model is `yes`" wording.) | The seed legitimately carries one `conditional` quality tier (`marigold-normals-v1-1`) that ships disabled with a bundle-time-verify note. The gate must block non-commercial models while permitting an opt-in, flagged conditional entry — so a careless enable can't ship something license-encumbered. Enforced in `internal/models` `validateSeedInvariants`. | Accepted |
| 2026-06-17 | **`birefnet-general` (MIT, CPU-capable) seeded `enabled:true`.** It is the declared default for `background_replace` but was the lone op-default shipped `enabled:false`, leaving that op with no enabled CPU default. | The headless tenet requires every op to have an enabled CPU-capable default. `enabled` means "active default for the op," not "auto-downloaded" (bytes are pulled opt-in on first use), so enabling a clean, CPU-capable model carries no at-rest cost and restores tenet compliance. | Accepted |

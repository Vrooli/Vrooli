The multiplier

Versions fork; defects ride along

180 assets carry 559 versions and 827 published export entries — 606 pinned, 221 floating. Every version stays exported forever, and each new version starts as a copy of the last. So a defect isn't fixed by a version bump; it's duplicated by one.

Consumers pin every import. web-console imports 10 RCL assets and pins an explicit version on all 10. That is the correct defensive move given the above — but it means a library-side fix reaches zero consumers until each one bumps by hand. Remediation that doesn't retire superseded versions makes the surface bigger, not better.
Remediation

Four moves, in dependency order

These are ordered because each one depends on the last. The headline: do not fix 92 assets. Fix two seams and close two gates.

1
Fix the seam, not the sites
Wire sizeStyles to the --control-height-* tokens that already exist, and delete min-height/min-width: var(--tap-target-min) from the [data-rcl-control] base sheet — that floor enforces nothing (every consumer needing density reaches for inline style, exactly as web-console did) while breaking every legitimate dense case. Keep the 44px WCAG intent as a dev-mode warning, warn-never-block. Separately, hoist the injected sheets to module scope behind one idempotent injector. Then make overflow:hidden safe by construction: move it onto an inner layer that holds the level meter and ring, so the voice control degrades like every sibling instead of cutting its glyph.
2 files → 92 style-injecting assets → 13 control descendants → deletes the web-console buttonStyle workaround
2
Promote the fix to a floor, not a contract
Floors are the only mechanism that reaches the 230 assets whose contracts assert nothing. Add content-not-clipped and a control-geometry floor to experience-manager/api/internal/reconcile/floor_checks.go, alongside the tap-target-size and horizontal-overflow floors already there. No new evaluator needs writing — content-not-clipped is implemented and idle.
1 file → every asset, including the 230 nobody will write a contract for → this bug becomes a build failure, not a bug report
3
Make correct the default, not the effort
82% vacuous is not 230 authors being lazy — it's a scaffold that emits an empty contract and a claim vocabulary nobody can be expected to hold in their head. Give each asset a kind (control · input · surface · overlay · shell) and have the scaffold emit a contract pre-populated with that kind's claim set. A control gets geometry, tap-target, padding and contrast claims by construction; the author edits or justifies, rather than starting from nothing. This is the move that answers "easier to set up assets correctly" — vacuous becomes the exception.
scaffold + 5 claim-set presets → every future asset → turns 20 idle evaluators into default coverage
4
Ratchet, don't sweep
Never attempt a 230-contract backfill; it will stall and the gate will stay yellow forever. Instead: vacuous_contract becomes an error for any new or modified asset, and a warning against an explicit, append-forbidden legacy allowlist that can only shrink. Pair it with an exports rule: a fix isn't done until the superseded versions leave package.json. The 82% then burns down as a side effect of ordinary work rather than as a project.
1 gate change + 1 allowlist → 559 versions stop growing → 827 exports start shrinking
What this changes about the library

Three rules worth adopting outright

One channel per property

The mic button sets background, border-color and color three times — inline style, injected sheet, and Tailwind classes — and the inline one always wins, making the other two dead. Every property should have exactly one owner: tokens for values, one sheet for rules, inline style reserved for what the caller owns.

A prop must mean what it says

size that only moves padding and density that only moves gap are the two traps that cost this whole investigation. If a prop can't deliver its name, either wire it or rename it — a misleading prop is more expensive than a missing one.

A contract that asserts nothing is worse than none

230 vacuous contracts read as coverage on every dashboard while checking nothing. ControlBase literally declares it owns "the size scale and density contract" and machine-checks neither. Either the claim is enforced or the purpose text should stop claiming it.

How these numbers were produced. Asset, version, export and evaluator counts are exact (find/jq over library/ and the published package.json). The 230 vacuous contracts, the live tap-target-size and horizontal-overflow failures come from the scenario's own most recent coverage/latest/experience.log. The 3-and-9 style-node counts and the rendered app-* class attribute were measured on a real render in the web-console test environment. The 92 / 11 / 12 asset counts are pattern-matched over source and may carry a small number of false positives — treat them as scale, not as a work list.

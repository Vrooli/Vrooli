03 / MODEL

Workspace, Page, Display, State.

This is the correction to the earlier single-page recommendation. A design-studio object is a Workspace. It contains multiple Pages. Each Page has multiple Displays (desktop, tablet, phone). Each Display has multiple States (props and/or UI state). A curated Template is a workspace snapshot that forks on use.

Level 1

Workspace

The authored object and the template unit. A flow is a workspace with ordered pages.

Harbor · onboarding
4 pages · 3 displays · 12 states
Level 2

Page

One screen or route. Realizes a page type from the catalog.

Profile · FormPage
3 displays · 3 states
Level 3

Display

One device frame for that page: desktop, tablet or phone.

Phone · 390 × 844
3 states
Level 4

State

A named prop/state variant of one display. Capturable and testable.

Validation error
email=invalid · error shown

Template = curated workspace snapshot

“Use template” forks the workspace into your own copy and keeps the origin. Curated workspaces are immutable, so a showcase cannot drift. A single-page template is just a workspace with one page; an onboarding template is a workspace with four pages.

This removes the separate studio_templates store. The shelf becomes a filtered view of workspaces: provenance=curated.

Page type = intent, not a rendering

A workspace page can declare realizes: templates.onboarding-page. The page type stays the requirement/blueprint: regions, states, capabilities. The page is the concrete composition. That link lets search answer “show me every onboarding page and the workspaces that realize it.”

States are first-class search and evidence targets: Harbor / Profile / Phone / Validation error is a stable address.

The current model maps cleanly. A DesignDocument is a Page. Its frames are Displays. Add a Workspace wrapper and a states collection; migrate studio_templates into curated workspaces. No existing composition is thrown away.

06 / SEARCH

What the new model does to search.

The omnibox from the search options stays. The result kinds change: a workspace, page, display and state are now first-class results, not hidden inside a “design”.

QueryWhat comes firstThenThen
“onboarding flow”Harbor workspace · 4 pages · 12 displays · 12 statesPages: Welcome, Profile, Preferences, Done · each with state coverageOnboardingPage page type · OnboardingFlow pattern · assets · commands
“landing page”LandingPage page typeWorkspaces/templates: Marlow, Northwind, ApertureAssets used · commands
“validation error”Harbor / Profile / Phone / Validation error stateThe page and workspace containing itAssets in the state · capture action
“button”Button asset · 2.2.14Workspaces/pages where it appearsCommands: adopt, open, compare

States are addressable. A state result can answer “where is validation error designed?” and deep-link to Harbor / Profile / Phone / Validation error. That is only possible if the data model names the display and state, instead of treating a frame as an anonymous viewport.

07 / BUILD

How to get there without a rewrite.

The current studio already stores pages, displays and themes; it is one level short and one level wide. Add the workspace wrapper and states, then migrate the template shelf into it.

Workspace { id, name, provenance: authored|curated|imported, tags[], pages[], // the template unit }
Page { id, name, route?, realizes: pageTypeId?, displays[], order? } // DesignDocument today
Display { id, device: desktop|tablet|phone, width, height, states[] } // DesignFrame today
State { id, name, args, scenario?, status: designed|missing, captureId? } // new
1
Workspace wrapper + page rename.

Promote each existing design to a page inside a one-page workspace. Rename the UI concept without changing the stored composition. Existing routes keep working.

week 1–2
2
Multiple pages + flow order.

Add pages[] to the workspace, page reordering, and the flow view. An onboarding workspace can hold Welcome → Profile → Preferences → Done.

week 2–4
3
States per display.

Add named states with args and capture status. Search indexes them. The studio state switcher and the evidence panel are the same object.

week 3–5
4
Template = curated workspace.

Migrate studio_templates into workspaces with provenance=curated. Fork on use. Delete the separate CRUD and the duplicate search path.

week 4–6

What stays

The page composition, frames, theme, revision, conflict handling, assets, story/test/capture evidence and the studio interactions. This is an extension, not a second studio.

What changes

The object users open is a workspace, not a page. The template shelf is a view of workspaces. States become addressable and searchable. Design routes gain a workspace/page path; legacy routes redirect.

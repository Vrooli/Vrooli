# Overlay composition validation

Overlay acceptance is proved in a real browser against consumer-owned build artifacts. The preview route accepts `consumer=<scenario>` and reads that scenario's current `ui/dist/assets/*.css`, `ui/src/design-tokens.css`, and `ui/token-map.json`; it does not copy those files into the library.

## Coverage boundary

The bounded matrix covers Dialog, AlertDialog, Popover, Menu, CommandPalette, BottomSheet, FullPageDrawer, ResponsiveDialog, and ContextMenu in two consumer contexts:

- `web-console`, the production Tailwind consumer with overlay call sites.
- `browser-automation-studio`, a built non-Tailwind consumer that proves package styling does not depend on Tailwind scanning.

Each asset-consumer pair has a mobile workflow at 390×844 and a desktop workflow at 1440×900. Each workflow captures light and dark evidence. BAS viewport dimensions are execution-scoped, so the two paired workflow files form the required four-combination matrix instead of simulating a viewport with CSS.

## Evidence contract

Registered workflows live under `bas/cases/`; `bas/registry.json` is generated by Test Genie. Composition coverage is selected by declared story capabilities rather than component-specific workflow files. Each run records:

- light and dark screenshots;
- computed surface styles and resolved token values;
- accessible naming and interactive target geometry;
- the actual browser viewport and named consumer context;
- the workflow interaction trace and assertion result.

Test Genie owns run artifacts. Use the run identifier returned by `vrooli scenario test react-component-library` and inspect its evidence directory; do not copy evidence into another source of truth.

The catalog's self-hosting gate measures imports from the published library surface
against the implemented catalog assets. `catalog/self-hosting-policy.json` records the
reviewed floor (currently 35 of 228) and an explicit, reasoned exemption list. Raising
coverage is the normal path; lowering the floor requires a policy review and a written
reason. An empty exemption list is intentional for the current baseline.

The machine-tier capability producers in Experience Manager consume these browser facts for focus order, pointer independence, safe-area handling, reduced motion, responsive transformation, transition conformance, and layout-animation checks.

## Calibration

Negative controls live outside the green registry under `bas/calibration/`. They deliberately plant and detect: missing focus containment, undersized tap targets, 1:1 contrast, breakpoint state loss, double layer dismissal, missing accessible names, unresolved tokens, and identical light/dark rendering. Every calibration must fail at its named assertion. A setup error or a passing calibration invalidates the corresponding positive evidence.

## Local commands

Regenerate the registry from the scenario directory with `test-genie registry build`. Run the owned suite with `vrooli scenario test react-component-library`, then block once with `test-genie runs wait --json react-component-library <run-id>`. Calibration workflows are intentionally excluded from the green registry and run through Browser Automation Studio's ad-hoc workflow execution surface.

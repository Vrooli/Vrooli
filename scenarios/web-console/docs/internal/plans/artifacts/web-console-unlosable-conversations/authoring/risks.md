| Risk / hazard | Consequence | Prevention and mitigation | Proof required |
|---|---|---|---|
| Reconciliation mutates the only copy of a transcript | Irrecoverable user data loss | Immutable backup manifest, content hashes, dry-run classification, bounded batches, compensating rollback, and operator confirmation for destructive classes | Restore drill reproduces the pre-migration state byte-for-byte |
| A close/archive race creates another orphan | The repair perpetuates the incident | One lifecycle owner, transactions, idempotency keys, monotonic revisions, and concurrency/fault-injection tests | Repeated close/archive/restart schedules converge to one state and one receipt |
| Search becomes dependent on Agent Manager, Search Hub, or an LLM | Local history disappears during dependency degradation | Keep deterministic local identity/exact-text/time/state search in Web Console; publish outward asynchronously | Local recovery succeeds with every optional dependency unavailable |
| Reconciliation attaches a transcript to the wrong session | Silent semantic corruption | Prefer authoritative IDs and paths; use confidence classes; quarantine ambiguous candidates; never guess from topic similarity | Golden fixtures cover exact, ambiguous, and unresolvable cases |
| Raw provider files contain secrets or sensitive prompts | Search or telemetry leaks private content | Index metadata and bounded snippets only; preserve workspace/user scoping; redact logs; define retention and deletion propagation | Security tests prove cross-scope denial and log redaction |
| Proto/storage rollout creates mixed-version incompatibility | UI/CLI/API disagree or fail during deployment | Additive contracts first, generated clients, capability negotiation where necessary, and staged cutover | Mixed-version compatibility window is tested before old path removal |
| The active Agent Manager search plan overlaps this work | Duplicate indexing and divergent identity contracts | Treat that plan as a dependency; agree on source-record and tombstone contracts; keep Web Console lifecycle ownership local | Integration contract is documented and both plans' tests consume the same fixtures |
| Broad refactoring expands without bounds | Important continuity repair stalls | Phase gates, explicit change boundary, narrow validation after each seam, and logged scope decisions | Every out-of-bound change has a Plan Manager decision and rationale |
| New skills/program become alternate business-logic implementations | Drift and hidden authority | Skills carry judgment only; governed program invokes stable CLI/API; scenario remains authoritative | Structural review finds no private database mutation in skills/program |
| Counts improve by deleting evidence | Metrics look healthy while data is lost | Define success as classified/recoverable preservation, not merely zero orphans; record before/after content totals and hashes | Conservation report accounts for every event and artifact |
| Huge live datasets make startup migration unsafe | Availability regression or long locks | Out-of-band bounded reconciliation, resumable cursors, indexes created safely, no unbounded startup scan | Performance budget and restart-resume tests pass on production-shaped fixtures |
| Error handling remains best-effort | Users still believe data is safe when it is not | Typed errors, visible UI state, durable receipts, retry state, and health signals | Injected failures surface to UI/CLI and remain recoverable after restart |

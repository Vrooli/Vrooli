## Who is driving and what the timeline shows

- The viewer header reports the **current driver** from the provider’s confirmed lease for the selected target. While an agent drives, the operator sees a live screen and **Take control** where authorized. While the operator drives, the browser address bar, keyboard/pointer or device controls become available and the header offers **Release** or **Return to agent** when that agent can still resume. With an idle browser, show **Ready** and **Use browser**. Use **Control device** for an idle device. Keep the last confirmed driver visible through pending handoffs and disable input when the current lease is unknown, expired or revoked.
- Put a horizontal screenshot timeline **below that target’s screen**. Earlier evidence goes left, newer evidence goes right, and **Live** is the final item at the right edge. Keep Live easily reachable on phone from any scroll position. Give the selected item a timestamp, action and actor. When a run is identifiable, provide a link back to its conversation. Mark capture start, handoff and end so successive runs remain legible on one target’s timeline.
- Selecting a checkpoint replaces the live screen with the retained image and labels the surface **Reviewing** with the capture time and actor. The header separately reports who drives Live now. Review blocks target input and leaves the current lease and page untouched. New checkpoints append without moving the review selection. Returning to the rightmost **Live** item resumes current frames and recomputes input access against the current lease.
- Tie automatic captures to agent control and meaningful changes, with a bounded cadence. Keep the start of control, navigation or settled action checkpoints, and the last eligible capture before release. If a capture was withheld, expired or failed, show a metadata-only checkpoint with its availability. A disconnected or stopped target can still show authorized retained evidence. Its rightmost Live slot shows the provider’s actual offline state.

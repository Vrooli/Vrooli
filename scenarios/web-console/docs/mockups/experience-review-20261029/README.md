## Proposal intent and open questions

- Settings: align label, short explanation and choice; group related controls. Mobile switches from a horizontally scrolling category bar to an explicit category drill-in, and stacks controls below descriptions. This trades quick lateral category switching for a simpler focused page. Retain every existing category, all settings below the fold, resets, detailed descriptions, accessibility and keyboard behavior. Static mockups do not specify all of them.
- Launcher: emphasize machine/group context and agent choice; use a single-column mobile list. This improves readability and tap area at the cost of vertical space; evaluate against the current compact two-column choices with real users. Retain group mode, agent versions/status, reorder, custom command entry, shortcut editing, appearance, session options, pending/error feedback and recovery. The compact footer in this image is an indication of placement only, not a functional specification.
- Both: use a restrained dark slate/teal vocabulary, coherent rows, boundaries and type hierarchy. Existing Aquila themes and visual decisions require reconciliation; this is not approval of a global palette change. Selected states must remain distinguishable without color alone, and contrast/focus/scroll/keyboard/long-content need actual verification.

Desktop and phone captures are representative, not comprehensive coverage of all pages, states or themes. The operator has not yet accepted this revision.

## Agent launcher study — proposed, 2026-10-29

The operator likes the existing new-session layout and requested a more coherent palette and simpler agent choices with usage context and a management view. [Open the desktop and phone study](agent-launcher-study.html). Values, installation status, versions and the update badge are illustrative, not observations. The earlier captures are the same baseline described above, not a new capture of the current build. The study keeps the two-column phone grid as an explicit revision of the earlier single-column idea. It preserves group mode, custom commands, shell, shortcut editing, installation and keyboard reorder. A management view is a proposal, not an implementation.

Agent Manager's UsageForecast contract exposes provider/pool/window, percentage presence, reset and observation times, but no account or machine identifier. Claude statusline and Codex event readings exist; the design cannot assume they apply to another selected machine or account. Web Console already has target readiness, versions, profile-backed order, and governed capability installation. Hide/show preferences and current/latest version comparison require further design and implementation. Agent Manager unavailable, unmatched identity, missing, stale, standing-only, and error must not be presented as a zero reading. Install failures, in-progress and unsupported states remain visible in management. The capture is a static concept, not evidence of accessibility, interaction, responsive behavior of the real UI, or all themes.

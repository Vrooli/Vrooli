# Tech Tree Designer experience contract

Five page specifications use the existing route inventory (/, /graph, /ontology, /planning, /settings). Four journeys cover bottom-up design, top-down learning, revision-bound apply/recovery and degraded observation. Proposal review and recovery are target states on the planning surface; this does not claim those controls are implemented or prescribe final route decomposition.

All entries are **draft** and custom claims are **aspirational**. There are no invented selectors, test bindings or runtime setup hooks. This is deliberately a documentation-first contract. Schema validation is not UX proof, and advisory experience claims do not make the linked PRD requirements optional.

As implementation lands, ground elements and independently resolving regions in real components/stories, add deterministic state setup and browser cases, and promote only demonstrated claims to machine/manual tiers and active status. Preserve root DESIGN.md accessibility, responsive, i18n and state contracts. Validate actual keyboard use, textual graph alternatives, compact layouts, focus recovery and distinguishable loading/empty/partial/stale/error outcomes.

The acceptance narratives use Given/When/Then to describe intended outcomes, not executed tests. API/CLI parity and fresh-agent development qualification are covered in [TESTING](../docs/internal/TESTING.md), not falsely represented as browser journeys.

Run `experience-manager spec validate tech-tree-designer`. Follow the experience-spec-authoring skill before changing the schema or claiming conformance.

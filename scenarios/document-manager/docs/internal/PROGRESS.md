| 2026-08-07 | claude | done | **Designed the generation (write) spine end to end, and scaffolded none of it.** A design review asked whether document *generation* belongs here. It does, with a boundary that has to be stated precisely: **this scenario renders; it never authors.** Generation was genuinely unowned repo-wide — `chart-generator` owns charts, `graph-studio` diagrams, `asset-studio` media, `content-desk` copy, `brand-manager` tokens — and a search across `scenarios/`, `docs/` and `resources/` for pandoc, typst, gotenberg, unioffice, python-pptx, weasyprint, marp and reveal.js found **no render toolchain at all**. The organizing insight is that generation is the read spine mirrored, not a second architecture: **the spec is the authority and rendered bytes are a derivation of it**, exactly as bytes are authority and derivations are derived on the read side — which is why re-render-on-template-change and re-derive-on-parser-upgrade are the same verb shape, the same append-only version table, and the same diff report, and why a generated document is an ordinary corpus document rather than a new class. Three domains added (`templates`, `composition`, `render`), reusing `corpus`, `custody`, `anchors` and `intake` rather than duplicating them. Twelve decisions recorded in [`DECISIONS.md`](DECISIONS.md), of which the load-bearing ones are: renderers declare **fidelity** rather than formats (the write-side twin of the handler registry, with the same "no library is the architecture" reasoning the `anydoc` rows already record); authoring persists as **three layers** — sources / spec / bindings — so only bindings are discarded on a template switch and `refresh` is a genuinely different verb from `render`; **templates are corpus documents** whose presentation references `brand-manager` tokens and never literals, so a rebrand is a corpus-wide re-render rather than a corpus-wide template edit; **template edits are proposals and per-document overrides are direct**, because the two read identically in a chat window and differ only in blast radius; and the **agent chat is a client, not a domain** — every action is a public proto verb with CLI parity, asserted by an AST check, which is what makes an external agent loading the same skill exactly as capable as the in-UI panel. Two consequences fell out that were not designed for: the renderer already knows where it placed each element, so it emits its block→region alignment as a byproduct and **generated documents get durable `logical` anchors for free** — closing the read side's deepest technical risk on the write side by construction; and because chat routes through the same `gatewayreq` choke point under the document's privacy class, the residency wedge runs backwards as *"you can talk to your privileged documents and nothing leaves the machine."* New reference doc [`../reference/render-matrix.md`](../reference/render-matrix.md) (registered in `docs/manifest.json`, cross-linked from `format-matrix.md`) carries the fidelity vocabulary, target matrix and the six write-side terminal states. | 2026-08-07 | claude | done | **Specified the anchor URI — the contract between this scenario and the ledger — and reading the real proto corrected the premise.** The gap filed earlier the same day assumed the ledger's provenance was a single opaque string. It is not: `source-ledger/v1/journal.proto` defines `ImportProvenance{runtime, source_locator, content_hash}`, and `vrooli-memory`'s handler builds its dedupe key as the **byte-exact join** `runtime + ":" + source_locator + ":" + content_hash`, unique on `(scope, import_key)`. So the contract was derivable rather than inventable, and two things fell out that prose would have gotten wrong: `content_hash` must carry the **finding body's** hash, not the document's — the document is already inside the URI, and hashing it there would collapse every finding about a document into one entry — and **canonical form is a correctness requirement**, because nothing ever parses that key back apart, so a trailing zero or a reordered attribute makes two identical citations distinct and `DOC-P1-023` silently stops deduplicating. New reference doc [`../reference/anchor-uri.md`](../reference/anchor-uri.md) (registered in `docs/manifest.json`) specifies: the grammar `vrooli-anchor:<scheme-version>/<document>/<derivation>/<kind>/<coordinates>[?attrs]`; three coordinate grammars with the parser-dependence designed out (geometric normalized to the page box with a pinned **top-left origin**, since raw pt/px/twip units are a parser detail and an unpinned origin mirrors half of all citations plausibly; tabular by sheet **index** not name; logical by index path over the *normalized* model with Unicode scalar offsets over NFC text); ten canonicalization rules with **equality defined as byte equality**; six resolution outcomes and no seventh, in particular no best guess. Four decisions recorded in [`DECISIONS.md`](DECISIONS.md), the load-bearing ones being: **the derivation version is mandatory** — forced for `logical` since offsets are version-relative, and worth one integer for the others because a citation is a claim about a specific *reading* that stays checkable after a later version disagrees; **a URI carries content-addressed and intrinsic values only** — no database identity (a foreign key wearing a citation's clothes, meaningless once exported), no corpus identity (exactly the lock-in `DOC-P0-017` forbids), no content-derived token (a sheet named `Q3 Layoffs` leaks into a ledger whose access control may differ from the corpus's); and **a published URI is never rewritten** — `DOC-P1-020`'s "re-derivation propagation" appends a new entry rather than updating an old one, because the journal is append-only and the original citation stays true. Degradation became mechanical rather than a judgement call: a `logical` anchor marks the end of its intrinsically stable prefix with `!` (`7!2/1@120-260`), so an unaligned anchor truncates at the marker and returns `resolved-degraded` pointing at slide 7, or `unresolved` when there is no marker. One accepted property documented rather than solved: a content address permits **confirmation of possession**, and the per-corpus HMAC mitigation would defeat the portability `DOC-P0-017` requires. Funded by new **`OT-P0-028` / `DOC-P0-028`**; `DOC-P1-023`'s description synced to name the real composite key. Requirements now **79** (28 P0, 24 P1, 27 P2); `business-health validate` PASSED with zero findings. Still no product code. |

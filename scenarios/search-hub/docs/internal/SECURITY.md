# Security — Search Hub

This document records the scenario's security and privacy posture.
Update it before adding auth, user data, external APIs, payment flows,
secrets, or sensitive business data.

## Data Sensitivity

| Data | Sensitivity | Owner | Notes |
|---|---|---|---|
| Provider descriptors and routing metadata | internal | Search Hub registry | Stored in SQLite; no corpus content or vectors are stored by the registry. |
| Provider control tokens | secret | Credential authority | One generated credential contains the provider-token map. SQLite keeps provider IDs and non-secret minted witnesses; the retired `providers.control_token` column is empty after startup migration. |
| Query telemetry | internal | Search Hub metrics | Aggregated routing metadata; do not add query bodies or credentials to telemetry. |

## Auth And Authorization

Search Hub does not currently have end-user authentication. Provider control
operations are authorized by a random per-provider bearer token validated at
the provider API. Search Hub is the token minter and holder; the token is
returned during provider registration and presented only on token-gated
control calls. Authorization stays at the API/service layer.

## Secrets

| Secret | Source | Required? | Notes |
|---|---|---|---|
| Provider control-token set | Generated by Search Hub and written through credential authority | For provider control operations | Declared in `.vrooli/service.json` as `vrooli/search-hub:provider-control-token-set`. Uses the host native secure store or encrypted credential file. Missing or unreadable values fail closed. |

## Threat Model

| Risk | Impact | Mitigation | Status |
|---|---|---|---|
| Credential authority unavailable or token set lost | Provider registration and privileged control calls cannot authenticate. | Registry operations fail closed; per-provider DB witnesses prevent silent re-mint. Restore the credential authority recovery bundle. | mitigated |
| Legacy plaintext token values | Existing SQLite databases may contain tokens from the prior schema behavior. | Startup imports values into the declared credential-authority entry, then clears the legacy column in a transaction. Authority persistence happens first; a failed write leaves the original token recoverable and blocks startup migration. | migration |
| Unauthenticated administrative API | Local API mutations may be reachable to other local processes. | Deployment remains local-first; add an API-layer auth model before exposing Search Hub across a trust boundary. | deferred |

## Security Gaps

| Gap | Severity | Revisit Trigger |
|---|---|---|
| No end-user auth model | conditional | Required before exposing administrative or provider registry operations across a trust boundary. |

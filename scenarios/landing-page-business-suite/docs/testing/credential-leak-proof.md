# Paid credential leak proof

This LPBS-owned Test Genie phase exercises owner tests with deterministic synthetic canaries derived from credential identity metadata. It never reads credential authority values, and its provider response contains identity, field, scope, version-safe test result metadata, counts and scan findings only.

The runner starts fixed Go test commands with an allowlisted environment (`PATH`, Go cache/toolchain settings and no application credential variables), captures at most 32 KiB per command, scans the complete captured buffer, and refuses a result if output truncates or exceeds scanner limits. It does not retain command output. The scanner recognizes raw, Base64, URL, hex, JSON and HTML representations, line wrapping, punctuation normalization, and 20-byte fragments so truncated output still fails closed. Synthetic leak injection is tested for every inventory family before consumer suites run.

The current inventory is derived from private fields in `.vrooli/service.json`, their declared consumer scopes, external credential consumer rows, and LPBS-issued service principal identities. Public browser configuration is excluded. Google Play receipt verification now resolves an exact `google-play:receipt-verify` authority binding, declared in the manifest and exercised with a synthetic candidate. The OpenRouter metered-inference key is included as an external-owned consumer; LPBS does not claim its provider scope contract.

The phase executes twelve bounded subprocess suites: scanner/artifact CLI negative controls; Stripe, mail and payment-settings redaction/error handling; authority administration and S3 outage/redaction; subprocess environment and output-truncation guards; CLI admin-credential support; LPBS source/audience/scope authorization; LPBS versioned rotation, overlap, subprocess restart/reload, outage and recovery; scenario-to-cloud scoped handoff and confirmed-unissued fallback; scenario-to-cloud credential lifecycle canary scans of retained surfaces; scenario-to-desktop fallback; Deployment Manager scoped release and fallback; and Treasury accepted-receipt identity, downgrade refusal and restart/idempotent recovery. Each owner suite runs from its own Go module and its output is scanned before metadata is retained. Suite references identify the assertions whose passing receipts establish owner, target, audience/scope and version behavior; no canary or authority value is serialized. It returns `partial` even when these pass because Test Genie artifacts are generated outside the LPBS provider process; download the native phase artifacts and run `go run ./cmd/credential-leak-scan --manifest ../.vrooli/service.json --artifacts <downloaded-directory>` from `scenarios/landing-page-business-suite/api`. The reusable command scans file bytes and paths, returns metadata only, refuses symlinks and oversized files, and exits nonzero on any synthetic sentinel or scan failure. External release-authority signing material and unmanaged/foreign consumers still require separate owner proof.

No real provider call, credential resolution, rotation, Checkout, staging or production action is permitted by this phase.

# LPBS presentation asset owner handoff

Date: 2026-09-15

## Scope delivered

The bounded LPBS owner seam is in:

- `api/internal/presentationassets/types.go`
- `api/internal/presentationassets/cache.go`
- `api/internal/presentationassets/verifier.go`
- `api/internal/presentationassets/presentationassets_test.go`

No existing LPBS main, route, ConfigStore, UI, or proto file was changed. No
real Backdrop candidate was released or published.

`Verifier.VerifyPublication` has the read-only function shape expected by
`ConfigStore.SetPresentationStorage`:

```go
func(context.Context, presentation.Document) error
```

It validates the complete document first. It then calls the parent-owned
`presentation.PublicViews` helper, which enumerates canonical `/` and eligible
detail projections for every locale and excludes private/non-member not-found
routes. It unions only each result's `Assets` (including responsive
alternatives). Private, disabled, draft, or unpublished profile candidates
remain subject to structural document validation, but are not fetched, cached,
or exposed by this seam.

## Proof and delivery contract

For each reachable asset, the verifier:

1. Calls the generated typed Backdrop ReleaseService client (`GetReference`,
   returning `ReleasedBackdrop`) using the document release reference.
2. Requires owner release ID, candidate ID, surface, dimensions, reserved
   region geometry, positive passing contrast ratio/threshold, and the
   document's candidate/provider expectations to agree.
3. Applies the parent-supplied canonical surface/crop/focal/placement policy.
4. Resolves the owner endpoint only through the server-side resolver. The
   owner URI must be a relative path
   below `/api/v1/backdrops/`; absolute URLs, network-path URLs, traversal,
   query/fragment injection, and redirects are rejected.
5. Fetches the actual owner bytes and requires PNG MIME, actual dimensions,
   positive `Content-Length`, a matching `ETag`, matching
   `X-Content-SHA256`, and an immutable cache policy. The SHA-256 is computed
   from the bytes; caller-supplied legibility booleans are never proof.
6. Stores verified bytes once below the routed `ClassData` root at a
   content-hashed path, with reference-specific immutable proof records. Two
   releases may share identical bytes without overwriting release metadata.
   Secure-random rooted staging directories and atomic renames are used; proof
   conflicts compare the complete proof. Content and metadata reads are
   bounded and rechecked. A test-mode context without a valid storage lease
   fails closed; a leased test context cannot read or write live data.

`ResolveAsset` returns the generated URL and verified proof for draft/import
flows. Publication is stricter: the document `PublicURL`, descriptor,
provenance, region geometry, and measured contrast values must match that
generated proof.

The cache handler accepts only `GET` and `HEAD` for exact LPBS content-addressed
same-origin paths such as `/api/v1/presentation-assets/<sha256>.png`; query
strings and path suffixes are rejected. It emits `nosniff`, immutable public
headers, and private/no-store headers under a test lease.
The returned descriptor's URL is generated by the cache, never copied from
the presentation document or Backdrop.

## Parent wiring requirements

The parent composition root owns the following integration decisions:

1. Construct the generated typed Backdrop client and provide it as
   `Config.Owner`. Also pass the exact origin used to construct that client as
   `Config.OwnerClientOrigin`; the resolver result is checked against it before
   `GetReference` runs.
2. Implement `ResolveOwnerEndpoint` from the existing server-side api-core
   discovery/lifecycle seam. Do not make the endpoint a presentation setting,
   accept it from a request, or pass a document URL into the resolver.
3. Construct `NewCache(fileRoots, "/api/v1/presentation-assets/")` with the
   existing LPBS `filerouting.RoutedRoots` instance. Mount `cache.Handler()` at
   exactly that same-origin prefix.
4. Supply the canonical LPBS surface policy as `Config.SurfacePolicy`; a nil
   policy is intentionally rejected by `NewVerifier`.
5. Pass `verifier.VerifyPublication` to the existing ConfigStore publication
   verifier seam only after this owner capability and route are composed.

The verifier applies a bounded default owner request timeout of 15 seconds;
the parent may provide a shorter `Config.RequestTimeout`.

The cache handler and verifier must use the same public prefix. The parent
still owns route registration, client discovery, ConfigStore wiring, actual
approved asset selection, and LPBS asset joins. This package does not publish
or release candidates.

## Generated-proto proof fields

Backdrop's generated `ReleasedBackdrop` message now exposes the owner proof
needed by this seam in fields 16–18:

```proto
// backdrop-studio/v1/release/release.proto
message ReleasedBackdrop {
  // existing fields 1..15
  string job_id = 16;
  string mime_type = 17;
  string content_hash = 18;
}
```

Backdrop derives `job_id` only from render `Candidate.JobID` through
`CandidateEvidence.JobID` into the durable release record; it is not a
`ReleaseRequest` caller field. MIME and hash are derived from the released
bytes. The generated Go, TypeScript, Python, and manifest artifacts were
regenerated under artifact
`5d785a6c0816727ac4d459372d2dcac20b6fbc798b12b28c933628558efbdea7`.
`ResolveAsset` requires these fields to agree with the actual same-origin
response and carries the owner job ID into the proof. Publication compares
the document job reference, candidate reference, URL, descriptor, and every
measured-region field against that proof; a forged document job reference is
rejected.

The regression tests are isolated fixtures only. They do not release a real
candidate, mutate commercial/publication state, deploy, activate a team, or
spend on generation.

Before LPBS can publish a real profile, the parent must additionally prove an
approved Backdrop release whose owner byte endpoint returns the same bytes,
hash, MIME, dimensions, immutable headers, surface, crop/placement policy,
and measured regions. A CLI “legibility passed” result without those bytes is
not sufficient. The parent must also retain the captured root-cause evidence
and perform the same-origin request against the mounted LPBS route; a successful
owner/CLI response alone is not served-asset evidence. The parent still owns
typed client construction, discovered-origin equality, LPBS cache route mount,
ConfigStore verifier composition, canonical public asset joins, and approval
of any real candidate. Candidate render records remain process-memory backed,
so a candidate never released before a Backdrop restart is outside this repair.

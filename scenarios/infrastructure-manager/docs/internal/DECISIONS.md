# Decisions — Infrastructure Manager

This document records durable decisions and tradeoffs future agents
should not accidentally relitigate.

## Purpose Of This Document

Use this document when a choice:

- affects multiple files or future agents,
- rejects a plausible alternative,
- changes architecture, deployment, data, security, monetization, or
  testing direction,
- needs a revisit trigger.

Routine implementation log entries belong in [`PROGRESS.md`](PROGRESS.md).
Known unresolved issues belong in [`PROBLEMS.md`](PROBLEMS.md).

| 2026-08-20 | **The board's signal vocabulary is nine states, and the length of the list is the point.** `COVERED`, `PARTIAL`, `EXCURSION`, `UNMEASURABLE`, `UNAVAILABLE`, `NOT_APPLICABLE`, `UNAUTHORED`, `BLIND`, `SOURCE_DOWN`, closed in `ui/src/theme/instrument.ts`. | The Substrate Board plan named four semantic states. Implementation found four insufficient. The device-graph collector already distinguishes `measured` / `unmeasurable` / `unavailable` / `not_applicable`; the coverage model separately owns declared, dated blindness; the trust model separately owns an unreachable source; and the ladder returns cells for only 10 of the 40 (class, rung) pairs on this host, so most pairs have no authored cell at all. | Nine facts that are routinely collapsed elsewhere stay separate: a value was read; the host refused the read; the mechanism does not exist on this host; the rung is meaningless for this class; nobody has declared the question; nobody is watching, since this date; and the source did not answer. Each carries a distinct mark and short code as well as a colour, so the panel survives colour removal. `NOT_APPLICABLE`, `UNAUTHORED` and `SOURCE_DOWN` are excluded from both the numerator and denominator of every coverage figure, for three different stated reasons. | If a state is never authored by any source for two consecutive quarters, retire it rather than leaving it unexercised. If two states are ever found to be rendered identically anywhere, that is the defect this vocabulary exists to prevent, and the renderer is wrong rather than the vocabulary. |
| 2026-08-20 | **`UNAUTHORED` is a fact about the denominator, and is never rendered as blindness or as a source outage.** | The first wiring of the board mapped "the ladder returned no cell for this (class, rung)" to `SOURCE_DOWN`. That asserted an instrument fault that was not happening, and it inflated the headline: it reported 3 classes with no covered rung and 38 cells with no bar. | Corrected to `UNAUTHORED`, meaning the owner's space document declares no cell for that rung on that class — the question has not been asked. Watch the `UNAUTHORED` count as the direct measure of how much of the space is still undeclared. |

If per-device drill-down is ever needed, the ladder must first carry per-device records; today it carries counts. |

All of it is published by a 60s collector. | Declaring these `MISSING` would have counted five closable gaps as honest blindness — what COVERAGE-MODEL.md calls *unowned work wearing honesty's clothes* — and would have inflated the open-loop headline with work that is already half done. Their bars route to `instrumentation-gap` because the missing piece is a join, not a sensor. Closing them is not a line in `substrateSensors`: the device graph grades on a rung ladder and this projection reads ordered severities, so a join needs either an autoheal check that projects rungs onto a severity, or a second substrate source in the instrument that owns the unit mapping. | The cell set grew 8 to 13 from one sweep of one existing scenario, with no new sensor written. Treat that as the standing estimate of how under-declared the other ten spaces are, and re-run the same sweep against each before trusting any coverage ratio as a measure of the platform rather than of the denominator. |

Each was checked against a live host read taken the same day (`vrooli-autoheal status --json`), against the dead-deadband rule, and against whether its actuator routes the fault to the layer that can act. | Four bars cleared all three: the shared `severity <= 0` bar is a definitional floor rather than a transcription of the current reading, proven on the same read by `SB2` grading `CRITICAL` (kdump-captured kernel BUG) and `SB8` grading `WARNING` (watchdog installed but not enabled) against it. The host substrate is not a scenario and has no owner of its own, so the candidate owners were the layer whose sensors produce the numerator (`vrooli-autoheal`, which holds the check registry) and this instrument. | The denominator went to `vrooli-autoheal`. | 2026-08-17 | **Build the instrument as a new scenario rather than extending an existing one.** | The team's instrumentation roadmap, since retired, held "extend before creating; new scenarios are a last resort" as its first core principle, so this needed a real justification. No existing scenario can hold the board: `system-monitor` and `app-monitor` are *inside the plant* with their own uptime targets, so a board hosted there goes down with what it measures; `vrooli-autoheal` owns the check registry, so hosting there is deviation `D6`. | A new thin scenario is the only seat that is neither in the plant nor in the setpoint. | If a future scenario emerges that is neither supervised nor a setpoint owner and could host the board more cheaply. |
| 2026-08-17 | **Hold no roster; derive every set at read time.** | The team's retired instrumentation roadmap stated in its Gap 11 "No central capability-health scenario — that would recreate the roster this PoR forbids", and operating-model rule 6 forbids enumeration anywhere in the team's surfaces. | `coverage` owns no tables and `condition` caches no leg population. The supervised set is computed per read from the core-set closure ∪ load-bearing declarations. A cached roster would be an architectural defect, not an optimization. | Never, while rule 6 stands. If the derivation becomes too slow, the fix is a faster derivation, not a cache. |
| 2026-08-17 | **Store readings; never store a band verdict. Trust verdicts are the one exception and are stored.** | Diverges from `meta-optimization-manager`, which never stores a numerator so a stale board is structurally impossible. But reliability targets are inherently historical — "99.5% over 30d" cannot be computed from a live probe — and Gap 11 names the cost of not storing: an outage becomes indistinguishable from missing data after the fact. The band/trust split is the line that makes the rule enforceable: a band verdict describes the *target* and is recomputable against the current deadband, while a trust verdict describes the *observation* and is not — nothing can reconstruct after the fact whether a check was saturated at the moment of the read. | Band evaluation is recomputed at query time, so tightening a target re-grades its own history. Trust verdicts persist on the reading row. The invariant's intent survives: no conclusion is ever served that was not just computed. | If reading history is ever consumed as a conclusion rather than re-evaluated, the deviation has failed and storage must be reconsidered. If an integrity rule ever becomes retroactively computable, its verdict moves out of storage. |
| 2026-08-17 | **Trust is a first-class axis with its own model document.** | This instrument's inputs are alarms on live processes, not registry joins. The 2026-07-23 decomposition measured 4,624 critical events in 24h with ~92% from ghost and saturated checks — a board reporting that at face value would have called a healthy platform critically unhealthy. | `TRUST-MODEL.md` exists as a peer of the coverage and condition models; every reading carries a closed-vocabulary verdict; untrusted readings are excluded from aggregates and routed to the instrument rather than the plant. | If the fleet grows a shared sensor-integrity contract, collapse this into a pointer to it. |
| 2026-08-17 | **No actuation path, ever — the watchdog is a separate decision.** | The genuinely critical class (autoheal down, agent-manager unable to spawn, shared-package breaks blocking core starts) needs a seconds-clock response, but operating-model rule 3 is "supervise, don't operate" and an instrument that acts is a controller with a bad boundary. | That class is deferred to a watchdog tier with its own operator authorization, an enumerated action set, and claim-suppression with mandatory expiry. This scenario would only *supervise* it, as an eleventh projection (`OT-P2-002`). | Operator authorizes a watchdog tier. Even then, this scenario measures it and never becomes it. |

| 2026-08-19 | **Adopt the projection model: the platform's reliability is a cell grid, not a flat target list.** | Operator review compared this scenario against `meta-optimization-manager` and found the residue directly: `docs/meta-optimization/` has no `strategy/` and no `evidence/` folder, because the models live with the instrument. `docs/infra-health/` has both — the setpoint and the roadmap sat in the team plan of record only because the instrument did not exist. The flat 14-row sensor map also had no answer for the known `SKETCH` problem, since the obligation list the targets should derive from is exactly the projection grid. | Ten projections, each owned by the control layer holding its ground truth, each with a cell grid. Coverage becomes a real ratio with denominator-confidence. The instrumentation roadmap becomes the computed open-loop set rather than a hand-maintained list. `supervision` stops being a domain and becomes one projection among ten. | If the fleet adopts a shared reliability-space contract, collapse the projection definitions into pointers to it. |
| 2026-08-19 | **Split the denominator: owners author the space, this scenario holds the bar.** | `meta-optimization-manager` puts the whole denominator with the owner, which is right when the owner has no incentive to under-declare. Reliability deadbands are different — they are operator judgment, and an owner that sets the bar it is graded against is `D6` one layer down. Equally, an instrument that asserted autoheal's cell set would be a roster in all but name and would go stale on every autoheal change. | Each control layer authors `docs/spaces/<projection>-space.md` and exposes `space --projection <p> --json`, exactly as the four existing space owners already do for MoM. The bars live here. Owners define the space; the operator defines the bar; neither can move the other, and this scenario can move neither. | If reliability bars ever become genuinely owner-knowledge rather than operator judgment, the bar moves to the owner and this split collapses. |
| 2026-08-19 | **The setpoint is a checked-in file parsed per read — never a table, never API-writable.** | Supersedes the 2026-08-17 decision that kept the setpoint in the team plan of record. The operator directed that the model live with the instrument; the D6 concern that motivated the old location does not disappear by moving the file. The natural next step once the board is polished is an edit-the-deadband screen, which is precisely the failure mode. | No endpoint writes the setpoint, so there is no permission to get wrong and no code path to audit. Changing a bar is a reviewed diff, and git history plus `decision_ref` are two independent records of the same change. Rejected: DB-backed operator-editable targets — better UX, but D6 held by convention instead of by construction. | If an operator workflow ever genuinely requires in-board tuning, the answer is a proposal flow that emits a diff for review — never a direct write. |
| 2026-08-19 | **Domains mirror the axes: `coverage`, `condition`, `focus`.** | The original `targets`/`readings`/`supervision`/`focus` set was designed for the flat sensor map. Under the projection model `supervision` is one projection among ten, and keeping it as a domain would give one reliability dimension a structural privilege the other nine lack — making the eleventh projection harder to add than the second. | One-to-one mapping between model documents and domains, so a reader who knows the models knows where behaviour lives. Adding a projection requires zero new domains, zero new tables and zero new handlers. If adding one ever requires a code change here, the grid has been special-cased and the change should be reverted rather than extended. | Never, while projections remain data. A projection that genuinely cannot be expressed as cells is the signal to revisit. |
| 2026-08-19 | **Typed Connect-RPC through `api-core/discovery`, not CLI shell-out.** | `meta-optimization-manager` migrated off CLI reads and its `numeratorclient.go` records why verbatim: the previous substrate spawned the owner's CLI with a 30s timeout, so one slow or hung owner stalled the whole scoreboard. This scenario's sources include the very layers that are unhealthy during an incident, so a hanging read is the expected case, not the exotic one. | Typed clients per control layer, concurrent, bounded by a 10s per-source deadline, degrading to an honest `UNAVAILABLE`. `vrooli capacity` is the single legitimate CLI read because it is control-plane `internal/` and unreachable from a separate module by construction. | If the control plane exposes a typed local surface, that last CLI read moves to it. |

Gap 10 — two-direction `check reconcile` and shelve-with-expiry — is what makes `GHOST` and `SHELVED` computable. Shipping without it means launching with half the integrity vocabulary permanently uncomputable. | A real read-only Connect surface over autoheal's existing domains plus Measures declarations, the reconcile and shelve verbs, and `supervision-space.md` with its `space --projection` verb. Rejected: a minimal proto shim to satisfy the join, which would have locked in the shape autoheal has to live with. | None — this is a build decision, recorded so the scope is not trimmed back to a shim under time pressure. |

Authoring only what can be joined today would delete the five open-loop targets from the model instead of reporting them — which is exactly what `OT-P0-005` exists to prevent. | The open-loop set is real data from day one and the instrumentation roadmap falls out of it.

# Browser Automation Studio owner map

This map records the current canonical owners and the consumers that call them.
It is intended to make future consolidation reviewable without collapsing
distinct browser contracts behind a generic task API.

## BAS operation owners

| Operation | Canonical owner | Contract |

The unreferenced `api/internal/wire.BuildDependencies` graph was removed; generated build metadata still lists the source pending governed refresh. | Browser session lifecycle | `api/automation/session.Manager` and `api/services/live-capture.Service` | One manager owns session admission, page identity, driver operations and close. `live-capture.NewServiceWithManager` is the supported composition seam. |
| Sensitive driver session routes | `api/automation/session.Session` → `automation/driver.Client` → driver `routes/session-lease.ts` → `SessionManager.getSessionForLease` | Storage-state export, service-worker inspection/removal, and AI navigation/debug proxy routes carry the wrapper's exact execution ID and lease ID. | Recording stream and input authority | `record-mode.CreateRecordingSession` → broker `Session.OwnerIdentity` → WebSocket Hub recording grant → `GET /ws/sessions/{sessionID}` | Successful creation issues a random HttpOnly SameSite=Strict cookie scoped only to that session's websocket route and stores its exact execution/lease identity server-side. Generic workflow execution subscriptions remain a separate authorization gap. |
| Driver session-start response loss | `playwright-driver/src/routes/session-start.ts` → `SessionManager.closeSessionForLease` | A new session's start response disconnect closes the exact execution/lease, including disconnects while startup is in flight; repeated/reused sessions are preserved and callers do not blindly redispatch starts. |
| Desktop driver and browser selection | `scenario-to-desktop/runtime/assets/playwright.go` → `playwright-driver/src/config.ts`; `api/sidecar/supervisor` | Desktop emits the `BROWSER_EXECUTABLE_PATH` consumed by the TypeScript driver. Empty or stale selection is rejected instead of widening the operation to the full recording. |

| Browser event interception and retry context | `playwright-driver/src/recording/io/event-route.ts` and `event-context-cache.ts` | The route admits one browser observation ID, keeps Playwright-derived frame/page attribution stable across identical retries, and rejects the same ID with changed page payload. |
| Timeline admission and delivery | `playwright-driver/src/recording/io/buffer.ts` and `orchestration/pipeline-manager.ts` | Bounded buffer retains unacknowledged observations and delivers them through the active consumer. |

| Session-profile settings update | `api/handlers/session_profiles` → `api/services/session-profile.Service.UpdateProfileSettings` | Validates the complete requested settings before one repository update, so a mixed rename/browser-profile request cannot report failure after partially committing. |
| Workflow execution and cancellation | `api/services/workflow` plus the driver session lease | Owns execution state, cancellation and terminal result. `ExecutionsService.WaitForExecution` joins an exact local runner for at most 75s and returns its persisted terminal row; ending that observation never stops the runner. `StopExecution` remains the explicit stop owner and joins cleanup before acknowledgement. |
| Resume admission | `handlers/executions.ResumeExecution` → `services/workflow.ResumeExecution` → `ExecuteWorkflowAPIWithOptions` → `database.Repository.CreateExecution` and the SQLite `execution_resume_claims` table | The repository transaction is the cross-process admission authority for one active child per source checkpoint. A terminal child may be superseded for a later retry. A definite active-child rejection removes only the new unadmitted snapshot; uncertain DB failures retain their recovery receipt. |
| Saved-tab profile mutations | `handlers/recordings` → `session-profile.Repository.UpdateProfile` | Tab deletion renumbers retained opener references with tab order and clears a popup link when its opener is removed, so saved topology cannot silently attach to an unrelated tab. |
| Automation engine health probe | `api/services/workflow.WorkflowService.CheckAutomationHealth` | Resolves the engine through the factory injected by API composition and forwards the caller context to capability health. It is a non-session probe and does not create or own a browser session. Missing factory configuration fails closed. |
| AI vision navigation session routing | `api/services/vision.PlaywrightVisionNavigator` built after API composition with `WithPlaywrightSessionBroker(deps.SessionBroker)` | Routes navigate, abort and resume to the caller's exact BAS-owned session through the broker. Navigation IDs, signed caller/access fields, cancellation, bounded action history and recording callbacks remain owned by the navigator; production construction receives the broker at creation. |
| Execution viewer reconnect | `ui/src/domains/executions/hooks/useExecutionEvents.ts` and execution store | Re-subscribes active runs after socket reconnect and rehydrates persisted execution detail to recover a terminal event missed while disconnected. |
| Active execution timeline refresh | `ui/src/domains/executions/hooks/useExecutionEvents.ts` | The open run viewer owns a 1 Hz authoritative timeline reconciliation; the global AppShell listener processes dashboard and terminal lifecycle refreshes, not per-step timeline reads. |
| AI helper browser actions | `api/handlers/ai` ephemeral `AutomationRunner` | DOM extraction, preview screenshots, element analysis and AI analysis share one runner built with the API's broker-backed engine factory. Each call retains its own execution/workflow IDs, cancellation context, in-memory recorder and event sink. Owner and composition tests pass; live resource impact is unverified. |
| Execution live-frame rendering | `ui/src/domains/recording/capture/useFrameStream.ts` plus the execution preview canvases | Decodes and paints into a persistent canvas, with frame statistics batched at one-second cadence. Execution frames do not create a new base64 data URL or React state update per frame; the preview keeps its canvas mounted while run metadata loads. |
| Execution artifacts | `api/automation/execution-writer` | One writer owns artifact admission, checksums, manifest references and durable output. |
| Startup reconciliation | `api/services/recovery` → `api/automation/session` broker → Playwright driver `SessionManager` | Reconciles persisted executions and browser sessions after restart; it does not claim in-memory execution continuation. Production must inject `paths.ResolveRecordingsRoot`; there is no private default lock root. Execution recovery rechecks status under the artifact lock and reports a row completed by a concurrent worker as skipped. Session reconciliation carries the observed owner execution ID and lease ID into the authenticated force-close; the driver compares both against the current lease before closing, so a stale inventory result cannot close a reused session. |

## Program Runtime dynamic route map

Program Runtime resolves declared binding IDs from each contract through the kernel namespace; its Python attribute chains are dynamic dispatch, not ad-hoc HTTP calls. The production `RunDeclaredProgram` admission path now parses the supplied input object against the pinned schema, resolves only the contract's exact binding IDs into a restricted kernel namespace, derives exact destructive-operation grants from that contract, and carries the persisted accepted execution identity through runner admission. `TestOperatorPayloadAdmissionKeepsExactBASBindingScope` exercises that boundary using real checked-in contract/binding registries with fake reachability and execution adapters; it is not a live Program Runtime execution. `api/internal/tasks/learning.go` and `kernel/host/learn.py` normalize the historical `bas` learning-owner label to `browser-automation-studio`; this writes finding ownership and does not launch a browser.

Keep it distinct from BAS `capture-surface` (generic URL capture with durable screenshot/computed-DOM references) and RCL's API `BASCaptureExecutor` (component-test UX bundle, redaction and artifact integrity); replacing either would drop target, verification or evidence semantics. The source census test walks every checked-in scenario Program Runtime JSON contract with a BAS binding, pairs it with the same-stem Python source, and compares direct dynamic route calls against declared bindings; it asserts RCL and Portal remain present. A runtime-level probe now constructs the real Program Runtime `SessionKernel` from the checked-in `do-task` grants, executes a dynamically selected declared route, and proves a dynamically selected undeclared route is refused before the bridge. This proves the kernel namespace honors the submitted contract's route set; live submission admission, cancellation receipts and runtime plugin sources remain unverified. BAS-preservation tests and documentation are not runtime callers.

The BAS route-contract regression enumerates every BAS top-level Program Runtime Python program, pins declared BAS binding IDs/effects, checks literal calls and nested BAS child calls, and also inventories Portal's external `do-task` calls against its contract. The hidden-file/script caller inventory uses `rg --hidden` across Go, TypeScript/TSX, JavaScript/MJS, CLI, scenario-server, Python, shell, YAML and JSON, then classifies lexical matches against this owner map. These source checks cover the checked-in caller set; they do not prove runtime plugin absence or a live Program Runtime execution.

No execution writer, profile persistence, recovery, timeline, or caller owner was removed.

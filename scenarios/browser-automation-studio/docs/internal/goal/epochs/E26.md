## Modules and budgets

Admission census at 2026-10-07: `api/services/export/html_bundle.go` is 1,136 lines. Its inline `htmlTemplate` spans 526 lines; the Go `htmlPayload` types and presentation projection/build helpers occupy roughly 360 lines. The same scenario already builds `ui/src/export/composer.html` around the 573-line `ReplayExportPage`, which consumes generated `ReplaySpec` and the existing `ReplayPlayer`; Vite maps this page to `/export/composer.html`. `WriteHTMLBundle` also owns ZIP output and object-store screenshot copying, which are retained behavior. The initial conservative estimate removes about 886 presentation lines and allows roughly 286 lines for the packaging adapter, for −600 net runtime lines.

Design: keep ReplaySpec as the playback contract. Reuse the existing UI replay page and its built output for the standalone archive, inject a strict JSON ReplaySpec bootstrap, and package resolved replay assets alongside the page so it works without a live BAS API. Preserve replay timing, transitions, cursor and highlights, status/error handling, offline playback, archive filenames, object-store asset resolution, and the existing MP4/GIF composer capture route. Do not create a second HTML/CSS/JS playback implementation.

If the existing built page cannot be packaged with stable scenario build/runtime ownership, do not keep parallel renderers to pass the gate. Record the exact infrastructure or contract blocker and step back for coordinator disposition; do not weaken offline or behavior requirements.

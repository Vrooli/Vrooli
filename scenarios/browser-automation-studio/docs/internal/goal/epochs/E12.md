## Modules and budgets
- Driver live frame stream setup, transport manager/protocol, recording and execution session wiring, frame settings and teardown.
- API driver-frame ingestion, hub latest-frame ownership and viewer fanout/subscription, routes and relevant REST exception declarations.
- UI recording and execution preview subscriptions, rendering consumers, contracts and tests.
- Preserve frame source identity, recording lease/page admission, image metadata, input-to-preview behavior, quality/FPS controls, reconnect/cleanup and bounded backpressure. CDP screencast and screenshot polling may remain as capture mechanisms only if both publish over the same transport.
- Keep one-off screenshot, export and archive capture behavior when it is independent of live streaming.

## Deletion list
- Driver-to-hub live frame transport — exactly one production producer protocol and one API hub-ingress owner serve both recording and execution live streams. Retire the duplicate recording/execution binary ingress handlers in `api/handlers/record_mode.go` and `api/handlers/execution_frames.go` or reduce them to a single shared owner; there must be no second producer HTTP callback path.
- `POST /api/v1/executions/{executionId}/frames` and `Handler.ReceiveExecutionFrame` — absent as a live-frame producer ingress after the WebSocket transport owns execution frames; remove stale route registration and callback URL/config construction or prove any remaining call is unrelated to live preview.
- API hub frame delivery — one bounded latest-frame slot per active recording/execution stream; no per-frame history or unbounded buffering. Retain the newest valid frame for late subscribers and release it with stream/session teardown. Keep existing recording lease/page source validation and execution ownership checks.
- `ui/src/domains/recording/capture/useFrameStream.ts` and `ui/src/domains/executions/hooks/useExecutionFrameStream.ts` — one shared UI hook owns live frame subscription and decode/admission state for recording and execution previews; migrate every production consumer and remove duplicate subscriptions/decoder state. No preview consumer opens a direct driver socket or polls the screenshot endpoint as a second live transport.
- Recording `GET /api/v1/recordings/live/{sessionId}/frame` may remain only for independent one-shot screenshot consumers; it is not a live preview fallback or second producer stream. Preserve standalone screenshot, archive, and replay frame behavior.
- Driver capture, API hub subscription, and UI exports/config — remove stale transport-specific APIs, callback fields, route comments and endpoint declarations for retired live paths. Capture strategies may not create a second transport.

Ownership/call-site map: `runtime-config.ts` defines an in-memory override
registry, fallback lookup to `process.env` and metadata defaults, type parsing,
validation and change listeners. Production callers are limited to
`observability/route.ts` handlers for PUT/DELETE `/observability/config/:env_var`
and GET `/observability/config/runtime`; its `LOG_LEVEL` listener changes the
driver logger. `server.ts` registers these handlers. The BAS API's
`handlers/observability.go` proxies all three routes and
`handlers/observability/service.go` exposes Connect operations
`GetConfigRuntime`, `UpdateConfig`, and `ResetConfig`. A repo-wide `rg` across
API/UI production sources found no UI caller for those RPCs; the Connect
operations remain externally callable, so this is absence of an in-repo product
client, not proof about out-of-repo callers. There are no other production
imports of the runtime registry. `tests/unit/utils/logger.test.ts` is its only
other current import. Separately, driver `config.ts` reads process-start values into server,
browser, session, execution, recording, telemetry, logging, metrics,
frame-streaming, performance and history config; these remain process-level
unless E15 explicitly moves a value into session admission.

Current session contract: API `automation/session.Spec` resolves viewport,
reuse, saved profile revision, storage, recording/execution capabilities,
frame streaming, base URL, artifacts and fake media into
`driver.CreateSessionRequest` (`automation/session/manager.go:230-285`,
`automation/driver/types.go:134-179`). The driver receives the request at
`playwright-driver/src/routes/session-start.ts`, builds `SessionSpec`, and
`session/manager.ts` owns the resulting session and lease. Before E15, no
dedicated resolved-options object was carried with that lease.

Post-change admission path: the API now serializes those resolved fields under
`driver.SessionOptions` as `session_options`, alongside top-level execution and
workflow identity. Driver `session-start.ts` validates and maps that payload to
the owning `SessionSpec`; the manager stores it in the same state as owner and
lease IDs. Same-execution idempotent starts retain the current lease and its
options; after explicit release, a reused session receives the next admission's
options with a new lease. The focused regression checks preserve frame-stream
options through both cases.

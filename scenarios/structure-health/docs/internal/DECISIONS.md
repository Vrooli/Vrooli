# Decisions — Structure Health

This document records durable decisions and tradeoffs future agents
should not accidentally relitigate.

## Purpose Of This Document

Use this document when a choice:

- affects multiple files or future agents,
- rejects a plausible alternative,
- changes architecture, deployment, data, security, monetization, or
  testing direction,
- needs a revisit trigger.

Routine implementation log entries belong in [`PROGRESS.md`](PROGRESS.md).
Known unresolved issues belong in [`PROBLEMS.md`](PROBLEMS.md).

## Decision Log

| Date | Decision | Context | Consequences | Revisit Trigger |
|---|---|---|---|---|
| 2026-09-01 | `DEPLOYABILITY_INSTANCE_IDENTIFIER` runs on the **control-plane** target, never on a scenario. | The rule walked `<repo>/internal/deployability` while being evaluated in the scenario rule set, so all 124 scenario reports carried an identical set of errors located outside the scenario. No scenario could pass, and none could act on the finding. | Moved to `rules.EvaluateControlPlane`, called from the control-plane branch in `validation/service.go`, and registered in the catalog under `control-plane` (it was previously unregistered — undeclared enforcement). Scenario gate discriminates again. | Revisit if a rule genuinely needs to span targets; the answer is a repo-scope target, not a scenario-scope rule reaching upward. |
| 2026-09-01 | Every finding `rules.Evaluate` returns must be located inside the validated target. | The scope leak above was invisible because nothing asserted it. | `TestEvaluateFindingsStayInsideTarget` guards the whole scenario rule set, not just the rule that broke it. This is the durable fix; the move itself is the one-off. | Revisit only to widen the invariant, never to weaken it. |
| 2026-09-01 | The instance vocabulary excludes tools, and reads scenario names from `service.name`. | Including `internal/tools/*` put generic words — `go`, `git`, `docker`, `vrooli` — into the vocabulary, so every `exec("go", ...)` was a violation. Using the directory basename added non-scenarios such as `scenarios/scenarios`. | Precision went from 1 true positive in 18 findings to 1 in 1. A tool is an ambient binary this code invokes, not an object it deploys. | Revisit if a tool name ever becomes a deployability decision input. |
| 2026-09-01 | The rule skips `_test.go` and `cmd/`. | 15 of 18 findings were fixtures; a test must name a concrete object to exercise the resolver. `cmd/` is the wiring boundary, and the rule's own remediation names the *resolver*. | Decision code under `internal/deployability` is still fully scanned; `TestDeployabilityInstanceRuleSkipsCommandWiring` pins that a literal in `resolver.go` is still caught. | Revisit if wiring code starts carrying decisions rather than supplying names. |
| 2026-09-01 | `docs/reference/structure-rules.md` is generated by `cmd/gen-structure-rules`. | The file carried a `GENERATED FILE` marker but no generator existed, so it was hand-maintained and drifted; `SCENARIO_README_POLICY` had been missing from it before this change. | `--check` mode makes staleness a test-able condition instead of something only the catalog test notices indirectly. | Revisit if the catalog gains fields the document should render. |
| 2026-09-01 | An inline comparison on an `os.Getenv` line counts as validation. | `checkGoEnvValidation` scanned only lines *after* the read, so `os.Getenv("FLAG") == "1"` — where the raw value never escapes the expression — was reported as unvalidated. | Removes a class of false positive across the fleet. Unguarded reads are still reported; `TestGoUnguardedReadIsStillAViolation` pins that. | Revisit if the detector gains real dataflow analysis, which would supersede the heuristic. |
| 2026-06-20 | Use the generated `react-vite` scenario documentation contract. | Scenario scaffold was generated from the template. | Docs start with stubs and maturity metadata in `docs/manifest.json`. | Revisit when scenario adopts a different template or doc contract. |

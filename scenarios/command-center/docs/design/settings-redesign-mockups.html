Settings redesign — three directions

Same underlying engine and config catalogs. What differs is how much the surface hides the data model behind tasks, and how far the presentation is lifted to the board's design language. Audience assumed: both, progressive — guided for newcomers, full catalogs one click away for operators. Toggle desktop / mobile since mobile is a core complaint.

Option A — Task-first restructure Recommended

Reorganize around jobs-to-be-done. A guided entry screen ("Recolor the board", "Add a data source"…) routes into focused editors that show the room → composition → slots → signals → theme chain instead of assuming it. Raw six-catalog list survives as "Advanced". Best serves the progressive audience and the monetization/skill ramp.

Option B — Same structure, fix UX + styling Solid middle

Keep the six-catalog master–detail, but make it work: searchable/grouped pickers with coverage + "bound where", a relationship strip on the room editor, one global unsaved-changes bar, a persistent labeled preview, and a full board-grade reskin. Faster and lower-risk than A; still leaves the vocabulary front-and-center.

Option C — Styling + mobile only Cheapest

Leave the information architecture exactly as-is. Fix the mobile collapse (preview stays reachable), add a search box above the pill cloud, and reskin to the board's tokens. Quickest path to "not embarrassing", but the core "it exposes the data model, not tasks" problem is untouched.

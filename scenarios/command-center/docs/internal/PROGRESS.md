| 2026-09-15 | opencode | Weak-device scene tier | **The capability probe picked the full scene from core count alone, so a TV whose WebGL is emulated in software ran the heaviest scene and blocked the main thread for seconds.** Reproduced in headless Chromium (SwiftShader) at 3840×2160 with CPU throttling: forced `full` produced 2–8 s main-thread blocks, intermittently; the release-ladder beat is the heaviest (`funnel-cascade` redraws gradients and text every frame). `probeTier` now reads `WEBGL_debug_renderer_info` and sends a software/virtualised renderer to the composed still, sends few-core / ≤2 GB / >4 MP panels to `reduced`, the backing store is capped at 3 MP (a 4K panel at 2× was 33 MP), and `reduced` paints at 30 fps. | 2026-09-15 | opencode | Auto-scroll pass resilience | **Made the auto-scroll pass impossible to stall.** The step effect listed the stop count as a dependency, so any re-measure that changed it cleared the pending step timer; under geometry churn the timer could be cleared every frame and the pass never advanced (the failure behind the 90 s hold). The stop count is now read from a ref and is not a dependency, a watchdog forces the pass complete after the computed worst-case time, and the controller releases and skips a beat that sits well past its reading time (`beatDurations[i] + MAX_HOLD_MS + 30 s`), whatever is holding it. The counter line reserves its height while scrolling, and `sameGeometry` tolerates a pixel of churn. Regression `AutoScroll.test.tsx`. Live 300 s soak, 1280×720/cycle 60: max hold 3.3 s, no stall; reduced-motion and forced `still`/`reduced` tiers also clean. |
| 2026-09-15 | Codex | Beat-scoped Broadcast readings | Broadcast beats now declare their `readingIds`; RoomPage scopes hero, scene, supporting strip, counts, and reading-time calculations to the active group. Desktop supporting pages have an eight-tile safety ceiling in addition to measured-height fitting; UI, registry, and fit regressions pass. |
| 2026-09-15 | opencode | Auto-scroll geometry loop | **A panel beat held the room for the full 90 s because the auto-scroll never advanced.** Live trace: `AutoScroll`'s optional counter line appeared only when a row was wholly visible, and its presence shrank the viewport it was measured from — so `stops` flipped 3↔4 and the viewport 91↔104 every frame, clearing the step timer before it fired (`stop` stayed 0, `read` never became true). Fixed by reserving the counter line whenever the list is scrolling (a non-breaking space when no range is named), and by making `sameGeometry` tolerant of a pixel of churn. Regression `AutoScroll.test.tsx` (the counter line stays when no row is wholly visible). 180 s live run at 1280×560/cycle 60, the config that reproduced a 90 s hold, now shows no hold; 45 s at 1280×380/cycle 30 shows a single 0.5 s hold. |
| 2026-09-15 | opencode | Auto-scroll one pass + cycle scaling | **The Forge release-ladder details looped forever and held the beat.** `AutoScroll`'s step effect never checked its `read` flag, so after one pass it restarted from the top and scrolled for the rest of the beat (the nonstop flicker). Worse, the auto-scroll and strip-paging timings were fixed milliseconds while beat durations scale with `?cycle`, so at short cycles the pass outlasted the beat: the beat held every visit and the list restarted on each remount, never reaching `read`. Fixed: the step effect stops once read; `cycleScale` (`ui/src/lib/cycle.ts`) scales `AUTOSCROLL_TIMING` and `STRIP_PAGE_MS` by the same factor as beat reading time, exposed through `useCycleScale`. Live probe at 1280×560: cycle 20's max progress stall dropped 9.9 s → 4.0 s and one pass now completes per beat; cycle 30 8.4 s → 1.1 s; regression `AutoScroll.test.tsx` (rests at the top after a pass) and `cycle.test.ts` (`cycleScale`). |
| 2026-09-15 | opencode | Freeze hardening | **Two latent hangs removed while checking a reported tab freeze.** (1) `samples=hide` advanced to the next beat with `(beatIndex + 1) % beats.length`, so a room whose beats all have hidden heroes but where some supporting reading is measured looped forever and pegged the tab. `nextMeasuredBeat` (`ui/src/lib/hero.ts`) now jumps once to a beat with a measured hero and returns `-1` when none, so the room stops. (2) A scene draw could throw (`arc` with a negative radius from a negative scene clock), and the throw escaped the `requestAnimationFrame` loop, killing the scene. `AmbientCanvas` now clamps `t`/`dt` to non-negative, catches a failed draw and falls back to the composed still, and `drawGlow` ignores a non-positive radius. Regression tests: `hero.test.ts` (`nextMeasuredBeat`), `engine.test.ts` (`drawGlow`). Live soak: 120 s fuzz over all rooms, samples modes, viewports and key input with 0 page errors and a stable heap; forge `beat=3&samples=hide` settles on the measured beat instead of looping. |
| 2026-09-15 | opencode | Cycle rail clock | **The rail stuttered because the 250 ms state tick and the 250 ms CSS transition raced,** so the transition finished early and the edge stopped for 100–180 ms then jumped; a held beat also stopped short of the segment end and could sit there for many seconds with no distinguishing mark. The controller now drives progress from `requestAnimationFrame` through a pure `tickCycle` (`ui/src/lib/cycle.ts`): progress follows the wall clock every frame, holds wait at `beatEndProgress` (the segment's end), and the rail carries `data-held`. The CSS transition stays only as a 120 ms jank buffer, shorter than the frame cadence. Live probe at 1280×720: transform changes every ~16 ms during motion, holds sit at `scaleX(1.000)`, no reversals. Regression tests: `cycle.test.ts` (clock monotonicity, hold at segment end, bound release, room-end navigation) and `AmbientDisplayShell.test.tsx` (segment fills, held/paused labels). |

The operator kept 2× density and 60 fps, so only pixel-preserving changes were eligible. |

# F9 bounty case registry

`api/internal/bountycases` owns versioned, immutable case bundles. Startup loads
owner-managed JSON registrations from the scenario's `data/bounty-cases/registrations/`
directory into SQLite. A registration is append-only by `(caseId, bundleVersion)`;
the same file can be loaded again after restart, while a changed bundle must use
the next version. SQLite rejects row updates and deletes.

The storage root is the absolute `storage.Paths.DataDir/bounty-cases` path resolved
by the Client Rehearsal API. Each source, reference and evaluator root must resolve
to a separate existing directory beneath that root. An RPC caller supplies only
one case ID or exact HTTPS GitHub issue URL; callers cannot supply filesystem paths,
commits, evaluator data, Test Genie intents, or project IDs.

## Registration JSON

Each `*.json` file in `registrations/` decodes as `bountycases.CaseBundle` with
protojson lowerCamel field names. The trusted owner creates the file after it has
qualified the issue, winning PR, source/reference trees and frozen evaluator. For
example, the test fixture shape is:

```json
{
  "schemaVersion": 1,
  "bundleVersion": 1,
  "caseId": "example-issue-1",
  "project": "example-project",
  "repository": "owner/repository",
  "title": "Example bounty task",
  "task": "Implement the issue requirements.",
  "publicUrl": "https://github.com/owner/repository/issues/1",
  "issueNumber": 1,
  "pullRequestUrl": "https://github.com/owner/repository/pull/2",
  "pullRequestNumber": 2,
  "sourceCommit": "0123456789abcdef0123456789abcdef01234567",
  "referenceCommit": "89abcdef0123456789abcdef0123456789abcdef",
  "sourceProjectRoot": "/absolute/trusted/root/projects/example/source",
  "referenceProjectRoot": "/absolute/trusted/root/projects/example/reference",
  "frozenEvaluatorRoot": "/absolute/trusted/root/evaluators/example-v1",
  "frozenEvaluatorEntrypoint": "acceptance.cjs",
  "testGenieProjectId": "f9-example-issue-1-v1",
  "testGeniePlan": {
    "validationPurpose": "VALIDATION_PURPOSE_REGRESSION_CURRENT",
    "requiredStrength": "VALIDATION_STRENGTH_TARGETED",
    "phases": [],
    "evidencePolicy": {
      "requireBehavioralBefore": false,
      "requireSourceSnapshot": true,
      "allowAuthorizedDegradation": false,
      "requiredEvidenceKinds": ["test-genie-run"]
    },
    "deadlinePolicy": {
      "queueBudgetMilliseconds": 300000,
      "executionBudgetMilliseconds": 1200000,
      "maximumAttempts": 1
    }
  }
}
```

F9 replay plans require an empty `phases` array. Test Genie executes the one
sealed frozen evaluator inside Workspace Sandbox; attaching generic scenario
phases would cause Test Genie to reject the replay intent or run checks against
the wrong project identity.

The example uses placeholder paths and synthetic identity values; it is not a
qualifying replay case. The loader rejects unknown fields, non-JSON files over
1 MiB, symlinks and directories in the registration directory. Bundle digests
are generated by the owner code and need not be included in the registration
file.

## Content seals

`frozenEvaluatorDigest` is SHA-256 of the exact entrypoint file bytes.
`frozenEvaluatorBundleDigest` is SHA-256 of compact JSON for the sorted evaluator
manifest records `{relativePath,sha256,size}`. Paths use `/`, are relative and
clean, and the sort key is `relativePath`. File SHA-256 values are lowercase hex.
The bundle is limited to 128 files and 2 MiB total; symlinks and non-regular
files are rejected. The evaluator bundle ID is
`<caseId>@<bundleVersion>:<bundleDigest>`, where `bundleDigest` seals the full
case metadata and trusted roots, with the digest field blank while hashing.

The full case response is the omitted RPC
`BountyCaseService.ResolveBountyReplayCase`, intended only for the exact pinned
`program-runtime.bounty-replay` binding. It returns `case` with trusted roots,
source/reference commits, immutable Test Genie plan, evaluator digests and opaque
evaluator bundle ID. The Test Genie-only
`BountyCaseService.GetFrozenEvaluatorBundle` resolves that opaque ID to the bounded
relative-file manifest and never returns the evaluator host root. The general
Client Rehearsal CLI exposes neither RPC.

The case-resolve method's program-only binding is enforced by Program Runtime's
exact program-and-digest dispatcher. Client Rehearsal's Connect endpoint does not
authenticate a Program Runtime transport principal. The solver boundary therefore
depends on the approved Agent Manager solver profile's network-denied capability
and its isolated candidate checkout; this does not block arbitrary internal Connect
callers. The evaluator-byte RPC is likewise an internal owner endpoint, not a
general CLI method.

# Decisions — Audio Tools

This document records durable decisions and tradeoffs future agents
should not accidentally relitigate.

## Purpose Of This Document

Use this document when a choice:

- affects multiple files or future agents,
- rejects a plausible alternative,
- changes architecture, deployment, data, security, monetization, or
  testing direction,
- needs a revisit trigger.

Routine implementation notes belong in [`PROGRESS.md`](PROGRESS.md).
Known unresolved issues belong in [`PROBLEMS.md`](PROBLEMS.md).

| 2026-06-30 | Report STT experiment safety as first-class gates alongside WER, not as a blended score. | Phase 7 of `~/.vrooli/plans/audio-tools-stt-experiment-lab-dictation-studio-overhaul.md` needs to expose catastrophic failures that aggregate WER hides: committed-text retractions and contiguous dropped spans. | Eval/experiment reports now carry commit timelines, per-clip and per-row safety verdicts, dropped-span thresholds, length-bucket curves, and coarse stage attribution. `audio-tools experiment start --dropped-span-threshold N` stores the gate threshold in the reproducible recipe. Wall-clock commit/latency fields are labeled intra-experiment-only; compute proxies remain the cross-experiment truth. | Revisit when the Segmenter emits richer ingress/egress attribution payloads so lost words can be attributed more precisely than conservative strategy/egress buckets. |
| 2026-06-30 | Model target-speaker extraction and verification as hermetic experiment recipe dimensions, not live speaker-config mutations. | Phase 6 of `~/.vrooli/plans/audio-tools-stt-experiment-lab-dictation-studio-overhaul.md` needs the lab to compare extraction and verification on/off over the same mixed-speaker inputs. The production speaker adapters live in `handlers/stt` because they bridge pipeline clients to ingress/egress seams without import cycles. | `ExperimentRecipe.speaker` stores target profile, extraction, verification mode, threshold, fallback, and ablation intent. The worker builds per-run `pipeline.SpeakerConfig` snapshots and binds the same production extraction/verification adapters into eval's `Segmenter` path. Ablation conditions are emitted as named report rows and realized recipe conditions; the live speaker config cell is never read or written. | Revisit in Phase 7 when stage attribution and per-condition safety envelopes become first-class report fields instead of condition-suffixed strategy rows. |
| 2026-06-30 | Keep Phase 5 augmentation audio transient while persisting requested and realized condition metadata in the experiment recipe. | Phase 5 of `~/.vrooli/plans/audio-tools-stt-experiment-lab-dictation-studio-overhaul.md` adds pure-Go SNR mixing, generated noise beds, and Kokoro competing-voice overlays. The existing report shape aggregates clips per strategy; Phase 7 owns per-condition safety envelopes and curves. | `audio-tools experiment start` can request `--noise-types`, `--snr-db`, `--competing-voices`, and `--competing-text`. The worker evaluates clean plus augmented condition clips, records skipped competing-voice conditions when TTS/canonical decode is unavailable, and never stores generated audio in SQLite or git. The mixer is pure/sample-level and clips by saturation, not wrapping. | Revisit in Phase 7 when per-condition metrics need first-class persisted run cells instead of an aggregate report over all realized condition clips. |
| 2026-06-30 | Realize long-form experiment inputs as deterministic, stored recipes instead of ad hoc eval request expansion. | Phase 4 of `~/.vrooli/plans/audio-tools-stt-experiment-lab-dictation-studio-overhaul.md` adds seeded concatenation over corpus clips. The builder sorts a corpus snapshot, derives clip order from the stored seed, inserts zero-byte canonical PCM gaps, and writes `realized_clip_ids`, `realized_reference`, and `realized_duration_ms` back into the experiment recipe. | `audio-tools experiment start` can now create multi-clip long-form inputs with `--long-form`, `--target-duration-seconds`, `--gap-ms`, and `--tag-contains`. Re-running from the stored recipe has the exact clip order and assembled reference even if the corpus grows later. Audio bytes remain transient eval inputs, not SQLite or git content. | Revisit if Phase 5 augmentation needs to persist retained generated audio artifacts; use the experiment blob store rather than adding audio columns. |
| 2026-06-30 | Route STT experiment streaming rows through `Segmenter` with a hermetic per-run `StreamConfig`. | Phase 3 of `~/.vrooli/plans/audio-tools-stt-experiment-lab-dictation-studio-overhaul.md` eliminated the eval bypass where `handlers/eval/evalrun.go` constructed VAD/overlap strategies directly. The eval path now binds a single-provider eval chain to `internal/stt/segmenter`, forces the requested strategy through `StrategyPreference`, and exposes `overlap_max_window_ms` on `EvalStrategy`/experiment recipes. | Eval and experiment runs exercise the same ingress/selector/egress construction point as live STT. Speaker extraction/verification remain off until the speaker-dimension phase binds those adapters. Per-run overlap knobs are recipe/config snapshots and do not read or write the live `stt_stream_config` row. | Revisit if the Segmenter contract changes so replay sessions can no longer bind a provider/config snapshot without the live transport stack. |
| 2026-06-30 | Build Dictation Studio's STT experiment lab as a persisted async experiment surface, not as another synchronous EvalService extension. | Phase 0 of `~/.vrooli/plans/audio-tools-stt-experiment-lab-dictation-studio-overhaul.md` captured baseline run `20260630-032920-ec1c416a` under `git-control-tower` name `stt-experiment-lab` before code changes. Resource probe: `whisper` healthy, `kokoro` healthy, `speaker-verification` enabled but not installed. Prior records `rec-6d63b12dba4b1a50`, `rec-27ee541eece15584`, and `rec-2ce1b25847378a4b` pin the existing eval/corpus shape, config-writer boundary, and pre-existing baseline red status. | New experiment work should add a domain-owned SQLite/blob substrate plus async runner and API/CLI/UI surfaces. Experiments must snapshot stream/speaker config hermetically, never mutate the live `stt_stream_config` row or speaker config cell, and keep audio bytes in variant-isolated blob storage rather than SQLite or git. `EvalService.RunEval` can remain as an internal compute core during the transition, but new agent-facing flows should use the experiment surface. The dirty shared tree at baseline capture means regression diffs must be triaged against the recorded baseline rather than assumed clean. | Revisit only if a later phase proves the async experiment archetype cannot preserve caller-disconnect survival or if audio-tools adopts a different durable job substrate. |
| 2026-05-16 | Use the generated `react-vite` scenario documentation contract. | Scenario scaffold was generated from the template. | Docs start with stubs and maturity metadata in `docs/manifest.json`. | Revisit when scenario adopts a different template or doc contract. |
| 2026-05-16 | `handlers/health`: HTTP-only domain — `handler.go` is the canonical HTTP handler (no Connect surface); `module.go` + `endpoints.go` follow the rest of the convention. | Phase 3 handler-shape unification audit. Health uses `api-core/health` for the standardized envelope and registers a plain `http.HandlerFunc`; there is no Connect service definition, so no `connect_handler.go` exists. | Readers should not expect a `connect_handler.go` under `handlers/health/`. Module wiring continues to import `NewHandler` from `handler.go`. | Revisit if a `HealthService` proto ever lands and we mount it via Connect. |
| 2026-05-17 | Post-extraction cleanup. Rename CLI `voice` → `stt`; fold standalone `diagnose` CLI into `settings providers`; keep `internal/ai/*chain/` as canonical provider orchestrators with `internal/{stt,tts,summarize}/` as primitives; keep `internal/text/normalizer/` shared between TTS + summarize; declare audio domain scope as the ffmpeg-backed ops already wired in `api/internal/audio/` with anything else PROBLEMS-deferred. | 9-phase extraction from web-console left naming drift (`voice` CLI for STT proto), an undefined `diagnose` domain, and unclear ownership between `internal/ai/*chain` (provider routing) and `internal/{stt,tts,summarize}` (primitives). Inspection shows the chains layer is consumed by every handler and bootstrap; primitive layers host segmenter/strategy/cache/normalizer with no overlap. Summarize has two files: `summarizer.go` is the Ollama primitive, `summarization_service.go` is the orchestrator — complementary, not duplicate. Normalizer is imported by `handlers/tts/connect_handler.go` and `internal/summarize/summarization_service.go`, so it is genuinely shared. `cli/domains/diagnose` exposes a single `providers` subcommand built from `SettingsService.GetProviderConfig` + `TTSService.GetStatus`; folds cleanly under `settings`. | CLI surface changes: `audio-tools voice …` → `audio-tools stt …`; `audio-tools diagnose providers` → `audio-tools settings providers`. No proto changes. `internal/text/normalizer/doc.go` lists its two consumers. | Revisit if a third consumer of normalizer appears outside `tts`/`summarize` (consider promoting), or if `audio` domain gains a CLI/UI surface for additional ffmpeg ops (re-scope). |
| 2026-05-16 | Decouple streaming **strategy** from streaming **provider** in the STT pipeline. | The 5 PRD-committed BYOK starter adapters plus Local Whisper and Vrooli/LPBS span three distinct techniques (VAD-segment, overlap-and-agree, native passthrough). Fusing technique with provider — as the current `voice.Service` does for Local Whisper — would duplicate VAD logic across every batch-only adapter and leave no clean home for the local-only quality tier. The selector becomes one explicit decision boundary instead of conditionals scattered across providers. | Providers declare `ProviderTraits` capability bits; `StrategySelector` enforces a compatibility matrix and returns typed errors on forbidden pairs. Both transports (browser WS, Connect bidi) reach STT through the same `Segmenter` + `StrategySelector` pipeline, eliminating the "two parallel pipelines silently drift" risk. Full design in [`../domains/stt/streaming-pipeline.md`](../domains/stt/streaming-pipeline.md). | Revisit if a future provider class cannot fit the matrix, or if the strategy/provider axes prove to collapse to one in practice across every supported vendor. |

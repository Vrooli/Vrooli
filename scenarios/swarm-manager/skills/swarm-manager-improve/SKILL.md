## Practice focus: Swarm Manager improvement

Improve the Swarm Manager control plane from owner evidence while preserving the
operator-selected destination. `scenario-improvement-campaign` owns successive
authorized repairs; this skill selects the concern and its evidence. Product
targets remain in the Swarm PRD and approved development contract.

### 1. Focus and scope

The regulated plant is the operator loop across backlog, plans, goals,
development contracts, workflow execution, evidence and terminal decisions.
This skill may improve Swarm-owned implementation, tests, programs and docs
inside the active grant. It does not redefine a product target, approve work,
own Agent Manager execution, own Test Genie results, or make Audio Tools,
billing, credentials or deployment decisions.

### 2. Setpoint

| Required outcome | Owner source and check | Current interpretation |
|---|---|---|
| OT-P0-001 through OT-P0-014 | `scenarios/swarm-manager/PRD.md`, requirements module, focused owner tests | Preserve the published backlog, plan, goal, evidence, workflow and operator-decision contract; each row needs current owner evidence |
| OT-P0-015 adaptive plan continuity | ordinary plan execution, transition runner and development package tests | Check one accepted plan, campaign checkpoint, aggregate budget and cancellation identity across successive repairs and restart |
| OT-P0-016 evidence-bound acceptance | development evidence contract and registered owner resolvers | Missing, stale, failed, mismatched or unavailable evidence remains unmet; no local fixture is a product receipt |
| OT-P0-017 development review surface | API, CLI and UI development response | Check target, grant, budget, campaign, cancellation, blockers and human decision standing agree across surfaces |
| P1/P2 outcomes | PRD and owner requirements | Keep planned or future status until their owner evidence and authority exist |

The PRD checkboxes are intent metadata, not a passing sensor. A focused test is
evidence for its covered behavior; it does not certify unrelated targets.

### 3. Sensors

Use `swarm-manager backlog get`, `swarm-manager goals get` and
`swarm-manager development get` for current owner state. Use the declared
Swarm measures endpoints for count and rate questions. Use
`prompt-manager skill-set validate swarm-manager` and
`program-runtime library run program-runtime.skill-set-read` for structural
skill inventory only. Use `vrooli scenario test swarm-manager --phases <owner-phases>`
for server-owned validation and wait once with the returned run identity.

Read Agent Manager workflow status and Test Genie receipts through their owners.
Classify `unavailable`, stale, failed, refused and missing evidence separately;
do not turn a readable response or `status=ok` wrapper into acceptance.

### 4. Golden corpora

Swarm has no speech corpus. For a target such as Audio Tools, the target
scenario owns corpus consent, reference revision, held-out split, device and
provider identity. Swarm may retain the owner receipt and bind it to the
approved target, but cannot create a private substitute or alter the denominator.
For Swarm behavior, the protected corpus is the requirements and transition
fixture set; preserve negative controls for stale revision, missing evidence,
wrong owner and unauthorized terminal mutation.

### 5. Routes

| Observation | Route |
|---|---|
| Contract or target disagreement | `writing-standards`, the owning PRD/requirements owner, and an explicit operator amendment |
| Wrong work shape or next action | `scenario-work-ladder`, Swarm backlog/next-action owner, focused regression |
| Workflow identity or grant drift | transition runner and Agent Manager workflow contract owner |
| Missing or invalid receipt | evidence contract and the producer owner; retain unavailable until its resolver is configured |
| Skill declaration or program drift | `skill-set-authoring`, `skill-validation`, or `program-runtime` at the owning layer |
| Repeated friction in a Swarm operation | inspect measured owner usage first; promote a stable join to a bounded program or repair the scenario primitive |

An authorized development campaign may repair several in-scope findings under
one approval. Do not file one new backlog approval per repair. Request an
amendment when the target, allowed paths, effects, budget, provider or evidence
authority changes.

### 6. Anti-gaming

Apply D1, D2 and D3 and the skeptic test from
`prompt-manager skill read improvement-do-and-dont`: preserve requirement
assertions, known-issue ledgers and findings. Swarm-specific gaming includes
marking a workflow result as final acceptance, treating a harness completion as
owner evidence, widening an effect ceiling to fit a test, accepting the first
resolver by registry order, or displaying a blocker only in one operator
surface. Add a regression for any real false-positive rule change.

### 7. Evidence

Retain the work item, target revision, approval/workflow/grant/attempt
identities, campaign checkpoint, owner receipt references, build identity,
focused test or Test Genie run identity, and before/after result. Record the
remaining required outcomes and inaccessible producers. Use the active owner
log and shared Memory contract; do not create a second Swarm improvement ledger.

### 8. Stop rules

Stop when the scoped outcome has a passing owner regression and no changed
required obligation remains. Continue while useful authorized work remains.
Stop new effects on cancellation, exhausted aggregate budget, revoked authority,
or an unavailable required owner. Return a bounded partial checkpoint when
completion is not established. Declare the full Swarm target complete only when
all required outcomes have current valid evidence and the operator's configured
final disposition is recorded.

### Troubleshooting & Edge Cases

| Observation | Response |
|---|---|
| `skill-set` reports a missing role | Repair the canonical scenario declaration and source; do not add a waiver to hide an owed role |
| Program or binding is unavailable | Preserve the reason and use the named owner command only when its contract is equivalent; otherwise retain the gap |
| Test Genie run is still running | Use `test-genie runs wait --json <scenario> <run-id>` once; do not poll or rerun |
| Owner receipt cannot resolve | Keep acceptance unavailable and route resolver work to that owner |
| Target or grant changed | Reject the stale mutation and require a fresh typed approval or amendment |
| Campaign shows no progress | Retain the checkpoint and no-progress count; choose a new falsifiable intervention or return attention |

# Decisions — Scenario to Android

This document records durable decisions and tradeoffs future agents
should not accidentally relitigate.

## Purpose Of This Document

Use this document when a choice:

- affects multiple files or future agents,
- rejects a plausible alternative,
- changes architecture, deployment, data, security, monetization, or
  testing direction,
- needs a revisit trigger.

Routine implementation log entries belong in [`PROGRESS.md`](PROGRESS.md).
Known unresolved issues belong in [`PROBLEMS.md`](PROBLEMS.md).

## Decision Log

| Date | Decision | Context | Consequences | Revisit Trigger |
|---|---|---|---|---|
| 2026-08-11 | Use the generated `react-vite` scenario documentation contract. | Scenario scaffold was generated from the template. | Docs start with stubs and maturity metadata in `docs/manifest.json`. | Revisit when scenario adopts a different template or doc contract. |
| 2026-08-13 | `scenario-to-android` owns generated-app conformance chapters; `device-control` owns device capability self-tests. | The original Android plan fused a device strategy test with the behavior contract of an app generated by this ramp. | The ramp declares chapters and delegates every native verb to device-control; device-control can prove a strategy without a delivery fixture. | Revisit when a chapter cannot be expressed as ramp-declared steps over device-control or BAS verbs. |
| 2026-08-13 | Use Capacitor as the first shell in a pluggable shell-template family. | Existing Vrooli UIs are React/Vite web bundles and should be wrapped without source edits. | The ramp generates a Capacitor Android project; another shell may be added behind the same builder seam. | Revisit when WebView memory/startup cost materially degrades a supported target. |
| 2026-08-13 | Consume `packages/delivery-ramp-go` through exported seams; never reimplement its matrix, evidence, transport, or gate semantics. | Desktop already established a provider-neutral delivery spine. | Android supplies `Prober`, `Builder`, `Driver`, and `Distributor` adapters and contributes missing generic seams to the package when necessary. | Revisit when a platform need cannot be expressed through an exported spine contract. |
| 2026-08-13 | Delegate every device verb to device-control under a held lease. | Direct adb access would bypass authorization, audit, and device-specific capability probes. | This ramp owns orchestration only; device-control owns device operation and evidence capture. | Revisit when device-control no longer provides a typed verb for a required chapter. |
| 2026-08-13 | Browser Automation Studio owns web-content flows inside the generated WebView. | A scenario's existing BAS flow must replay unchanged across browser, desktop, and Android. | Android adds an attach target and engine; the ramp does not author a mobile-specific flow or duplicate selector execution. | Revisit when a target has no CDP-shaped web-content surface. |
| 2026-08-13 | USB is the default transport for release-relevant physical-device runs; wireless ADB is a recorded fallback. | Wireless pairing can expire across reboot and creates failures that resemble conformance failures. | Evidence records the transport and fallback reason; a wireless run is never silently presented as USB. | Revisit when fleet policy guarantees durable wireless pairing or another transport replaces USB. |
| 2026-08-13 | Model Play, verified sideload, and ADB internal as independent distribution channels. | Each channel has different identity, artifact, and verification requirements. | One channel's readiness cannot make a sibling channel available. | Revisit when Google or fleet distribution policy changes a channel's identity requirements. |
| 2026-08-13 | Produce debug-signed APKs and unsigned AABs only; never create an operator signing identity. | Evidence needs an installable APK, but production signing keys do not exist and must not leak into the ramp. | Release-signing rungs report unavailable with a next action; Gradle's debug keystore remains host-managed. | Revisit when an operator-managed signing identity is provisioned through secrets-manager. |

## Practice focus: Git Control Tower Improve

Regulate immutable regression evidence from capture through terminal diff.
Route repeated client compensation into Git Control Tower operations.

Required reading: `prompt-manager skill read improvement-do-and-dont`,
`prompt-manager skill read scenario-work-ladder`, and
`prompt-manager skill read git-control-tower`.

### Scope and setpoint

In scope: capture integrity, collection closure, diff terminality, wait
reattachment, and evidence provenance. Out of scope: weakening dirty-state
policy or treating missing evidence as no change.

| Row | Desired band |
|---|---|
| capture-terminal | Every accepted capture has typed standing. |
| collection-closure | Every collection preserves all declared members or names omissions. |
| diff-terminal | Every accepted diff terminates or remains explicitly active. |
| provenance | Every result names anchor and current identities. |
| wait-friction | Zero recurring polling or lost-handle fingerprints. |
| unsupported-claims | Independently adjudicated grounded claims remain above the declared floor. |
| scope-accuracy | Results cite the selected subject and do not broaden to latest/unrelated evidence. |
| stale-evidence | Revision changes remain visible and invalidate stale findings. |
| trailer-correctness | Suggested links resolve through owners or remain explicitly uncertain. |
| review-quality | Precision and known-defect recall are measured separately. |
| learning-capture | Failed, unavailable, and successful attempts have one outcome-linked record. |

Read bounded operation evidence and Agent Manager friction, classify the
highest gap with `scenario-work-ladder`, apply one coherent change, and repeat
the same reading. `git-control-tower.setpoint-read` accepts dated,
owner-linked observations and reports absent data as `partial`, never as a
healthy zero. A setpoint program remains deferred for any row without a
governed read binding; private CLI parsing is forbidden.

### Canonical decision order

1. Refuse unsafe authority or a quality/corpus-floor violation.
2. Route missing bindings and required telemetry to the owning scenario.
3. Preserve unavailable, unreliable, and sparse readings without estimation.
4. Repair the contract before conforming implementation to a wrong target.
5. Repair obligations and evidence before interpreting maturity scores.
6. Curate data only when the defect belongs to data.
7. Promote repeated mechanics into a program or scenario operation.
8. Remove duplicate upper-layer choreography only after comparable evidence.

### Anti-gaming gates

Do not lower a target, delete a hard case, suppress a finding, omit an
attempt, replace a failed receipt with a newer passing receipt, or claim a
trend from synthetic fixtures. A controlled repair requires two comparable
dated observations, unchanged quality floors, the exact changed artifact, and
an independent outcome or an explicit `unavailable` standing.

### Output expectations

Report each row as `in_band`, `out_of_band`, or `unavailable`, with the evidence
handle and owner. Never improve a reading by deleting operations or anchors.

### Troubleshooting & Edge Cases

- No bound standing reads: report the sensor unavailable and file the binding obligation.
- Sparse sample: enforce invariants without claiming a trend.

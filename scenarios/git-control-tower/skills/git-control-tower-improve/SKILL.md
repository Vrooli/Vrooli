## Practice focus: Git Control Tower Improve

Regulate immutable regression evidence from capture through terminal diff.
Route repeated client compensation into Git Control Tower operations.

Required reading: `prompt-manager skill read improvement-do-and-dont`,
`prompt-manager skill read scenario-work-ladder`, and
`prompt-manager skill read git-control-tower`.

### Scope and setpoint

In scope: capture integrity, collection closure, diff terminality, wait
reattachment, and evidence provenance. Out of scope: weakening dirty-state
policy or treating missing evidence as no change.

| Row | Desired band |
|---|---|
| capture-terminal | Every accepted capture has typed standing. |
| collection-closure | Every collection preserves all declared members or names omissions. |
| diff-terminal | Every accepted diff terminates or remains explicitly active. |
| provenance | Every result names anchor and current identities. |
| wait-friction | Zero recurring polling or lost-handle fingerprints. |

Read bounded operation evidence and Agent Manager friction, classify the
highest gap with `scenario-work-ladder`, apply one coherent change, and repeat
the same reading. A setpoint program remains deferred until baseline and
collection standing are governed read bindings; private CLI parsing is forbidden.

### Output expectations

Report each row as `in_band`, `out_of_band`, or `unavailable`, with the evidence
handle and owner. Never improve a reading by deleting operations or anchors.

### Troubleshooting & Edge Cases

- No bound standing reads: report the sensor unavailable and file the binding obligation.
- Sparse sample: enforce invariants without claiming a trend.

# Error Semantics & Recovery Paths

## Last Updated
2026-11-14

## Classification principle

Preserve the typed failure cause and any authoritative execution, work, and charge receipts. Missing evidence remains unknown. Recovery uses the durable job or request identity until the owner confirms whether work was accepted.

## Baseline and collection failures

| Flow | Failure Mode | Current Behavior | Desired Behavior |
|------|--------------|------------------|------------------|
| Baseline/collection finalizer | Client cancellation or detached-tail deadline | The durable snapshot intent remains pending; no baseline or false failed member is published. | Reattach once through the printed status command; the non-wait collection reconciliation path resumes terminal children from their durable Test Genie records. |
| Baseline/collection finalizer | Terminal Test Genie error | The individual intent records failure and the collection member becomes failed coverage. | Return truthful partial coverage so unaffected terminal members remain visible; failed coverage cannot become a clean collection diff. |
| Baseline commit | Two finalizers race for one durable run | Both may await the run, but terminal commit rechecks storage. | One owner-scoped pin and manifest persist; later finalizers return the stored anchor idempotently. |

## Staged message job failure contract

This table covers the durable Agent Manager drafting job and the worktree suggestion queue. A missing receipt means **unknown**, not zero. Job rows are authoritative for execution identity, measured work, charge, retryability, and category; the browser may only explain those receipts and offer the listed recovery.

| Failure source | Persisted job / work / charge / retry certainty | UI explanation and recovery | Regression evidence |
|---|---|---|---|
| Workspace Sandbox lifecycle admission refusal (`provider_admission_maintenance`) | `awaiting_provider`; execution start known false, tokens known zero, charge known zero; retryable. The saved input remains attached to the job. Legacy rows are projected as awaiting provider only when the same zero-work receipts prove refusal. | Queue card says provider admission is waiting and preserves the selection. It checks readiness and disables same-input retry unless readiness is known open; jobless admission-refusal recovery uses the same readiness gate. | `TestMaintenanceRefusalPersistsAwaitingProviderAndRequiresExplicitNewJobRetry`, `TestMaintenanceRetryRequiresKnownOpenProviderReadiness`, `TestLegacyMaintenanceFailureProjectsAwaitingProviderWithoutMutatingOrCharging`, `TestStagedMessageAgentProjectsMaintenanceRefusalAsDefinitiveNoStart`; UI `pauses a new queued-suggestion retry after a maintenance refusal until readiness is open`, `keeps a jobless lifecycle refusal behind the provider readiness gate`. |
| Agent Manager provider unavailable | If GCT has no provider adapter before dispatch, the job is `failed/provider_unavailable`; start is known false, tokens and charge are known zero, and retryable is true for a later new job. An owner-issued lifecycle refusal remains `provider_admission_maintenance` as above. | The queue reports that no request was dispatched and holds same-selection retry until Workspace Sandbox readiness is known open. | `TestProviderUnavailableBeforeDispatchPersistsKnownNoWork`; UI `gates a known pre-dispatch provider outage until readiness is open`. |
| Start acknowledgement lost / transport error after dispatch marker | `dispatching`, no execution ID, `dispatch_unconfirmed`; start, tokens, and charge remain unknown; retryable false. Reconciliation reuses the exact durable owner idempotency key; it must not send a new key. | Launch remains in confirmation/reconnect state. Reconnect checks the existing job; it does not tell the operator that no work occurred or offer a replacement while acceptance is uncertain. | `TestLostAdmissionAcknowledgementSurvivesLaterAuthenticationFailure`, `TestCancelledAmbiguousDispatchAdoptsHandleAndSettleFinishesCancellation`, `TestSettleRecoversDurableAdmissionWithoutDispatchingTwice`; UI `distinguishes a saved request from an agent launch when the owner handle is unknown`, `recovers an uncertain launch by reconnecting to the same request without redispatch`. |
| Authentication or policy refusal | Before dispatch, unauthenticated is `authentication_required` and policy denial is `policy_denied`; first dispatch auth is retryable, first policy refusal is not. Work and charge certainty are copied only from an owner receipt and are otherwise unknown. After a saved execution exists, both errors preserve that handle and remain nonterminal/reconnectable; no replacement is started. | The dialog gives the access or policy repair step and reconnects to the saved execution. It preserves the drafted message. | `TestClassifyDispatchErrorsByRecoveryAction`, `TestOwnerReadAuthenticationFailureDoesNotInventTerminalExecution`, `TestLostAdmissionAcknowledgementSurvivesLaterAuthenticationFailure`; UI `explains persisted authentication_required and policy_denied without implying the saved execution stopped`. |
| Owner budget exhaustion | Owner failure remains terminal with its owner error code and available execution/token/charge receipts; absent fields remain unknown. `retryable=false` blocks repeating the saved mode/input. | Failure reason is shown with measured token and charge values when known. The queue offers only a changed-mode new job (or a changed selection), not the same saved mode; retryable failures may start a new job using the same selection. The main composer also suppresses same-input retry and explains how to create a distinct job. | `TestStagedMessageBudgetFailureExplainsActualOwnerReason`, `TestBudgetFailurePersistsOwnerWorkAndChargeReceipts`; UI `offers a new job with changed mode, but not a repeat of the non-retryable saved mode`, `does not retry a non-retryable failure with the same saved input`, `offers a new suggestion for a durable terminal failure, not same-key retry`. |
| Cancellation | Cancellation remains `cancelling` until owner confirmation. A fenced cancellation before start is `cancelled_before_start` with known false start and known zero tokens/charge. If the owner reports completion after cancellation, result is discarded and terminal status is cancelled; owner receipts are retained. | UI distinguishes pending cancellation from cancelled, preserves the selection, and does not expose a discarded late result. Reconnect or background settlement continues the same job. | `TestCancellationRemainsPendingUntilOwnerConfirmationAndRejectsLateResult`, `TestCancelBeforeOwnerStartDoesNotDispatch`, `TestCancelFenceWinsAgainstBlockedStartBeforeOwnerAdmission`, `TestCancelledAmbiguousDispatchAdoptsHandleAndSettleFinishesCancellation`. |
| Invalid structured result | `failed` with `invalid_structured_output`; no result is persisted. Execution, work, and charge certainty come only from the owner's receipts; retryability is true because a new attempt may be useful. | Dialog says no valid suggestion completed, includes the bounded validation reason, and allows a new attempt only for the still-applicable saved selection. | `TestMalformedStructuredResultFailsWithoutTranscriptFallback`; UI `exposes failed and unknown owner states without inventing a suggestion`. |
| Owner result/evidence read failure | Same execution ID remains attached in its prior active state with `evidence_unavailable`; retryable. Start/tokens/charge are only known where the owner returned them. No second execution is dispatched. | UI says GCT is rereading the completed result and offers reconnect to the same job. | `TestEvidenceReadFailureKeepsJobRecoverableAndClearsOnReconnect`, `TestEvidenceReadFailureAtStartPersistsHandleAndWorkReceipt`; UI `shows a persisted active-job failure explanation with same-job recovery`, `surfaces a persisted active-job evidence error and reconnects to that same job`. |
| Saved execution is authoritatively missing | `stale` with `execution_missing` only for owner `NotFound`; prior known work and charge receipts stay intact. No replacement starts. Transport/auth failures do not imply stale. | Queue card marks the captured suggestion unusable and directs the operator to queue current files as a new selection. | `TestJobStatusMarksStaleOnlyOnOwnerNotFound`; UI `shows cancelled and stale as separate terminal states`, `retains an inapplicable result as stale`. |
| Worktree queue revision, path ownership, or payload conflict | Mutation returns conflict and leaves the durable queue unchanged; this is not an Agent Manager job and has no work/charge/retry receipt. The caller must reread the queue and resolve the changed selection. | Queue mutation error is shown; the browser must not remove or overwrite a same-ID replacement after a revision conflict. | `TestWorktreeQueuePersistenceOrderingReplayAndHeadConflicts`, `TestWorktreeQueueRejectsPathOwnershipConflictsTransactionally`; UI `does not remove a same-id replacement after a revision conflict` (`stageConfirmation.test.ts`). |
| Job or queue storage error | Storage errors are returned from the owning operation; they must not be converted into an empty/missing row, a terminal job, or known-zero work/charge. If the caller lost the response to job admission, it must resolve the saved request key against storage before deciding whether to submit again. | Show that saved state could not be confirmed and offer reconnect/read using the same request key. Never present an unconfirmed write as a successful queue/job update. | `TestQueuedSelectionCanReplaceOrphanedSuggestionJob` asserts storage failure is not treated as an orphan; `TestJobGetIsObservationalAndAdvanceDispatches` covers read/advance separation; UI `surfaces a persisted queue failure without attempting a job lookup`. |

The listed service and storage regressions are authoritative for the persisted contract. Retryability governs repeating the saved mode and input; choosing another mode creates a distinct job with changed input. A lifecycle refusal gates both paths until provider readiness is known open. Historical rows without the required receipts cannot be repaired by inference or backfilled as known-zero work.

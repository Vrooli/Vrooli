# Deployment Manager architecture and migration ledger

This ledger records the current ownership boundary for the commercial release
path. It is part of the handoff evidence and must be updated when a route or
owner changes.

| Former or parallel path | Current authority | Disposition | Evidence |
| --- | --- | --- | --- |
| Release status and platform standing in legacy JSON handlers | `api/releases` repository and release handlers | Retained as the canonical durable model; Connect and CLI adapters project it | `api/releases/types.go`, `api/releases/repo.go`, focused API and CLI suites |
| Generic `deploy`/`deploy-desktop` packaging routes used as a release shortcut | Typed `ReleasesService.Start` plus candidate, readiness, destination, and owner receipt contracts | Retained only as compatibility/local preparation surfaces; commercial publication requires a release-bound request and current authorization. The scenario-to-desktop owner skips its legacy profile approval gate for release-bound deploys, so it cannot create a competing approval path. | `api/deployments/orchestrator_release.go`, `api/deployments/orchestrator.go`, `cli/releases/commands.go`, `scenario-to-desktop/api/pipeline/stage_deploy.go`, `README.md` |
| Candidate, destination, and review fields copied into a release request | Immutable identity repository plus bound release record | Replaced by durable identity lookups and exact binding checks | `api/releases/identity_storage.go`, `identity_handler_test.go`, `contracts.proto` |
| Publication success inferred from release status | Publication receipt repository and owner receipts | Removed as a valid success path; health requires receipt-backed evidence | `api/releases/health.go`, `health_test.go`, owner suite receipts |
| Replaced readiness evidence discarded with the current evaluation | Current `readiness_evidence` projection plus append-only `readiness_evidence_history` | Replaced by transactional archival; current promotion standing is refreshed while prior evidence references remain auditable | `api/internal/readiness/repository.go`, `api/internal/readiness/schema.sql`, `repository_test.go` |
| Older target verdict wins over a later rerun | Evidence repository history and release gate | Replaced by newest-first verdict reads and latest matching target selection; prior attempts remain retrievable for audit | `api/internal/evidence/repository.go`, `api/deployments/approvals_repository.go`, `release_gate_evidence_test.go` |
| Recovery effects inferred from an HTTP response | Durable recovery receipt repository and owner recovery contracts | Replaced by producer-attributed, non-dry-run receipts | `api/releases/handlers.go`, `api/releases/types.go`, `api/deployments/orchestrator.go`, `api/deployments/cloud_client.go`, `api/deployments/lpbs_release_client.go` |
| REST release list/get/dossier/verify/start/reconcile/recover consumers | Typed Connect service for product operations, including durable operation standing and owner-attributed recovery receipts, with a narrow REST compatibility route for health | Production CLI uses typed list/get/dossier/operation/reverify/reconcile/recover/start; REST remains only for health, which has no typed RPC yet | `packages/proto/schemas/deployment-manager/v1/releases/contracts.proto`, `api/internal/transport/connect_handler.go`, `api/server/connect_routes.go`, `cli/releases/commands.go` |
| `release-observe` and `release-recover` governed programs | Deployment-manager handlers and owner adapters | Programs remain orchestration entry points; policy and durable state stay in deployment-manager or the named owner | `programs/release-observe`, `programs/release-recover`, recovery validation tests |
| Cloud deployment lifecycle | `scenario-to-cloud` owner through the deployment-manager cloud adapter | Retained as owner-owned effect and receipt boundary; deployment-manager stores the release binding and receipt | `scenario-to-cloud/api`, `api/deployments/cloud_client.go`, `api/deployments/orchestrator.go` |
| Native installed-client lifecycle | `scenario-to-desktop` owner through its update/recovery adapter | Retained as owner-owned effect and receipt boundary; deployment-manager does not emulate host repair | `scenario-to-desktop/api`, desktop owner suite |
| LPBS channel revision lifecycle | LPBS owner CAS and recovery endpoint | Retained as owner-owned channel effect; deployment-manager sends exact revision and stores the receipt | `landing-page-business-suite/api/internal/delivery`, LPBS owner suite |
| Commercial desktop publication with incomplete destination binding | Exact LPBS app key and remote profile, verified before the owner pipeline starts | Refused as a terminal deployment error; no owner upload is launched without the exact publication coordinates | `api/deployments/orchestrator_helpers.go`, `orchestrator_release_test.go` |
| Deployment Manager calls to retired scenario-to-desktop JSON pipeline and smoke-test routes | Typed scenario-to-desktop PipelineService and owner validation surfaces | Removed unused REST pipeline/smoke-test client methods and their stale tests; release publication and status polling use Connect | `api/deployments/desktop_client_pipeline.go`, `desktop_client_pipeline_test.go`, `scenario-to-desktop/api/main_test.go` |
| Deployment Manager CLI deploy and deployment-status calls to retired REST routes | Generated deployment-manager `DeploymentsService` client | Production CLI registration now routes deploy, deploy-desktop, and deployment status through typed Connect operations; REST construction remains only for compatibility fixtures and commands without typed contracts | `cli/domains/deployments/register.go`, `cli/deployments/commands.go`, `cli/deployments/deploy_desktop.go` |
| Deployment Manager approval CLI calls to retired profile/approval REST routes | Generated deployment-manager `ApprovalsService` client | Production CLI registration now routes list, get, create, decide, gate, and required-platform operations through typed Connect calls | `cli/domains/approvals/register.go`, `cli/approvals/commands.go` |
| Deployment Manager swap CLI calls to retired swap/profile REST routes | Generated deployment-manager `SwapsService` client | Production CLI registration now routes list, analyze, cascade, and apply-to-profile operations through typed Connect calls; unsupported legacy swap-info is refused with an actionable typed-surface message | `cli/domains/swaps/register.go`, `cli/swaps/commands.go` |
| Deployment Manager overview dependency and fitness CLI calls to retired REST routes | Generated deployment-manager `DependenciesService` and `FitnessService` clients | Production CLI registration now routes dependency analysis and fitness scoring through typed Connect calls; fitness payloads use protobuf-compatible JSON values | `cli/domains/overview/register.go`, `cli/overview/commands.go` |
| Profile update command still routed through the retired profile REST API | Generated deployment-manager `ProfilesService` client | The production `profile update` subcommand now uses the typed update operation and preserves explicit name, scenario, tier, and format validation | `cli/domains/profiles/register.go`, `cli/domains/profiles/connect.go` |
| Profile export command still routed through the retired profile REST API | Generated deployment-manager `ProfilesService` client | The production `profile export` subcommand now reads the exact typed profile and writes the canonical profile JSON or requested output file | `cli/domains/profiles/register.go`, `cli/domains/profiles/connect.go` |
| Profile import command still routed through the retired profile REST API | Generated deployment-manager `ProfilesService` client | The production `profile import` subcommand now reads canonical typed profile JSON and creates the profile through the typed service, with explicit name/scenario validation | `cli/domains/profiles/register.go`, `cli/domains/profiles/connect.go` |
| Legacy profile set, swap, analyze, save, diff, and rollback commands without typed RPCs | Generated `ProfilesService` contract and adjacent typed commands | Production registration refuses these retired paths with actionable replacements instead of calling unmounted REST routes | `cli/domains/profiles/register.go` |
| Deployment Manager CLI secrets, signing, and visual validation commands calling retired REST handlers | Owning secrets-manager/scenario-to-desktop services and typed release readiness/evidence operations | Production registration keeps the command names discoverable but returns an actionable retirement message instead of issuing requests to unmounted routes | `cli/domains/secrets/register.go`, `cli/domains/signing/register.go`, `cli/domains/validations/register.go` |
| Deployment Manager CLI build, logs, profile-validate, and cost-estimate commands calling retired REST handlers | Typed release preparation, operation standing, readiness/evidence, and destination review surfaces | Production registration keeps the command names discoverable but returns an actionable retirement message; typed deploy and the narrow bundle-export compatibility route remain available | `cli/domains/deployments/register.go`, `api/server/connect_routes.go` |
| Deployment Manager CLI bundle assemble and validate commands calling unmounted REST handlers | Narrow `bundle export` compatibility route used by scenario-to-desktop | Production registration refuses assemble and validate with typed-path guidance while preserving bundle export for the live owner consumer | `cli/domains/deployments/register.go`, `api/server/connect_routes.go`, `scenario-to-desktop/api/pipeline/manifest_generator.go` |
| Release-bound desktop deployment without an exact destination | Owner-derived update URL plus approved app/channel/target coordinates and durable candidate/review identity carried into the deploy stage, LPBS artifact metadata, and channel promotion request | Refused before artifact collection/upload when derivation fails, returns empty, disagrees with configured destination, contains an unapproved ready target, or omits candidate/destination/review identity; LPBS refuses to advance the channel when selected artifacts carry a different release identity; local packaging keeps its warning-compatible behavior | `scenario-to-desktop/api/pipeline/stage_deploy.go`, `stage_deploy_test.go`, `scenario-to-desktop/api/deploy/lpbs_client.go`, `landing-page-business-suite/api/internal/delivery/channel_revision.go`, `packages/proto/schemas/scenario-to-desktop/v1/pipeline/types.proto` |
| Per-command durable operation progress text | Generated `ReleasesService.GetOperation` plus shared `cli-core/operationstanding` renderer | Production CLI reattaches through typed transport and projects the same status, phase, error, and next action; no REST operation fallback remains | `cli/domains/releases/register.go`, `cli/releases/commands.go`, `packages/cli-core/operationstanding` |
| Host repair or device remediation inside deployment-manager | Control plane and named owner | No private host repair implementation is permitted in the scenario | `AGENTS.md` host-remediation rule and handler ownership review |
| Generic `Config` declarations in desktop owner domains colliding with the shared `boottest.Config` companion | `pipeline.PipelineConfig` and `smoketest.SmokeTestConfig` | Renamed and migrated all typed callers; serialized field names remain unchanged | Desktop unit run `20260909-005301-4f16daf7`; `go test ./...` in `scenario-to-desktop/api` |

The remaining compatibility routes are documented adapters. Release list/get,
operation standing, dossier, and health projections use the same verified read
capability as the typed transport. They do not create a second release
authority: the canonical release record, identity records, receipt ledgers,
health projection, and reviewer dossier remain owned by deployment-manager.

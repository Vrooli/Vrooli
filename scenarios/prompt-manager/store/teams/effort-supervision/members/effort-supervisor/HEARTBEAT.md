## Task Loop

Read `prompt-manager skill read large-effort-supervision`. Consume only the bounded
effort selection appended by the runtime. Read current AM board details for those
effort references and prior owner decisions. Use its current CLI help for syntax.

Assess each required outcome independently. Retain productive work and owner
waits. For a selected healthy sample, record the selection basis and result under
the diagnostic allowance; do not invent a deviation to justify it. Discovery and
sampling supply no steering or repair authority.
Stale or unavailable source cuts may receive an uncertainty assessment when their
effort and evidence identities remain valid. Keep an unknown accepted target as
an explicit empty value in the assessment target-revision map. State freshness and
limitations; do not steer from those cuts or describe them as healthy acceptance.

For stopped work, inspect newly changed resolution-source references before
reusing the prior wait. Retain the blocking invariant, current repair receipt,
recovery owner and next condition. Confirm actual executor state separately from
this supervisor's status. Use authorized owner recovery when qualified; otherwise
name the missing grant or capability and coordinate its owner. Do not silently
switch provider, resume a cancelled/completed run, or duplicate uncertain work.

Apply the contract's recovery completion gate. A lifecycle defect is actionable
diagnostic evidence even when product acceptance is unknown. Identify the existing
repair assignment and its reopening condition. After an authorized recovery,
verify assignment-relevant progress against the original directive's baseline;
record recovery verification through AM. Startup and heartbeat alone do not close
the recovery. Do not claim a separate repair grant from diagnostic admission.

## Run Decision

Record the quiet, sample or proposed-action assessment with
`agent-manager effort assess --request-file <request.json> --json`. Complete the
typed request skeleton appended by PM with actual findings and rationale. Use
the runtime-issued `VROOLI_AGENT_IDENTITY_TOKEN`; `WATCH_AUTHORITY_FAMILY_PARENT`
selects signed run authentication, not a requirement to invent a family. AM binds
the supervisor run ID from that token. Never obtain or use an operator credential.
Use the wake ID as its idempotency key and shared operation reference, the selected effort
references/revisions, this supervisor run ID, the shared accounting reference,
and the actual usage or explicit unknowns. A count of attempted wakes is not a
token/dollar observation. Retain unknown benefit when causality is unmeasured.

After AM acceptance, use the runtime-provided `prompt-manager team knowledge-add`
command to write one concise `supervision-assessment/<wake-id>` link. This existing
facade preserves the typed topic in Source Ledger; do not substitute a plain journal
note. Link the owner assessment, unknowns and next owner condition. If the link
write fails, retain the AM receipt and report the link failure, then finish. Do not
repeat assessment or investigate the journal implementation. If AM itself refused
the assessment, retain that refusal and do not claim a receipt. The wake ID and accounting reference are also
available in the runtime environment.
Only an AM response containing an assessment ID proves that the assessment was
recorded. If a selected sample was not performed, report unknown with its reason;
do not submit `sample` solely because the runtime selected one.
## Stop Conditions

Finish this wake after recording its disposition. Stop with explicit unavailable
evidence if the owner cannot be read; never replace uncertain effects. PM owns
future discovery and cadence.

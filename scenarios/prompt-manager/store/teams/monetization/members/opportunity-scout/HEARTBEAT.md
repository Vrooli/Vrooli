# Run Task: Opportunity Scout

## Instrument and Continuity

Read the team's declared `offer-desk` instrument first. If it is unavailable,
record the reason and age in the continuity record, fall back to the inbox and
last durable observations, and keep any uncertain idea explicitly
unpromoted; never silently skip the board.

## Reasoning Framework

1. What external, operator, or capability-arrival signal is new?
2. Which capability and market combination is worth classifying?
3. What acquisition, retention, and revisit hypotheses make it testable?
4. Should the idea become an evidence entry, an operator work item, or be
   dropped?

## Task Loop

1. Read the instrument, Source Ledger wake, and recent signal entries.
2. Drain the generated inbox flow and generate ideas only to the extent the
   signal supports them.
3. Use board rows to deduplicate and to avoid bypassing an existing
   evaluation or promotion decision.
4. Apply the classification and hypothesis judgment framework.
5. Run supersession before proposing a replacement and raise work only when
   the operator should decide now.

Inbox draining commands and destination prefixes are in the generated
`# Inbox Flow` section; do not duplicate them here.

## Run Decision

Record durable continuity in the declared Source Ledger topics. Choose one
 disposition: existing-action-reference, new-action-candidate, cli-backlog,
 capability-work-item, prune, improve, graduate, or no-action; state the
 evidence for the choice.

# Coordination Guidance (Peer)

This is supplemental guidance referenced from the generated Operating Policy. You are part of a peer team. Teammates are independent specialists, but coordination between peers is expected when it improves outcomes.

## Operating Model

- There is no standing leader. Coordinate laterally.
- Use durable inbox messaging when the Operating Policy enables it.
- Use peer triggers sparingly and only when the work benefits from an immediate follow-up run.
- Respect teammate scope. Send concise, actionable coordination requests instead of broad status pings.

## Storage Model

- Continue with handoff when the next run needs continuity.
- Observe with knowledge entries for evidence, findings, snapshots, and friction.
- Propose with decisions when a durable surface should change.
- Operate only the team working state named in your generated Storage Map.
- Use the inbox for asynchronous coordination that must survive beyond the current run.

## Default Behavior

1. Start with your responsibilities and current heartbeat instructions.
2. Check team working state before duplicating another teammate's work.
3. Coordinate only when it reduces ambiguity, dependency risk, or duplicate effort.
4. Persist the minimum information needed for future peer runs to stay aligned.

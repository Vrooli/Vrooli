# Decisions — Compute Manager

## Purpose Of This Document

The durable record of choices that were genuinely contested, why they went the
way they did, and what would make them worth revisiting. A decision belongs here
when reversing it later would be expensive, or when a reasonable engineer would
otherwise make the opposite choice.

Rows are written once. When a decision is overturned it moves to Superseded
Decisions with a pointer to its replacement, rather than being edited in place.

> **Status: designed, not implemented.** These decisions were taken during the
> design review that preceded generation. None of them has been tested against
> running code, and the Revisit Trigger column is where that is expected to show.

## Decision Log

| Date | Decision | Context | Consequences | Revisit Trigger |
|---|---|---|---|---|
| 2026-09-03 | **The reconciler never writes money.** A machine found missing at the provider produces a `destroyed_out_of_band` finding; the meter domain drains it and closes the usage window. Rejected: letting the sweep close the window itself. | The sweep already holds the safety property that a reconciler defect cannot destroy a running node. Closing a usage window settles credit, so a sweep that could do it would hold the power to settle a live customer's reservation on a bad read. | Settlement has exactly one owner. The cost is a bounded delay between discovering the machine is gone and releasing its hold, which is cheaper than the failure it prevents. | If the delay is measured and proves to matter more than the blast radius. |
| 2026-09-03 | **The intent row is written before the credit reservation, not after.** Rejected: reserving first so a refusal leaves no row. | Reserving first is tidier, but it opens a window where a crash between the reservation call and the first local write strands a credit hold that no local record points at. That is the intent-before-action failure applied to money instead of machines, and money is the half nobody notices. | A refusal leaves a cheap prunable `refused` intent. A crash anywhere in the sequence leaves a `reserving` intent the reconciler can find and release. `OT-P0-002` becomes literally true rather than nearly true. | If reservation acquisition becomes transactional with local state, the window closes and the ordering can be reconsidered. |
| 2026-09-03 | **The instance-side expiry timer is a renewing lease, not a copy of the lifetime.** Rejected: writing the full lifetime once at first boot; rejected: reaching into the machine to move it. | This scenario holds no execution channel into a running instance by design, so a timer written once could never be extended. The operator surface offers extension, so a fixed timer would let the control plane report success while the machine still died at the original moment. | The timer is a dead-man switch: absent a renewal it fires, so an unreachable control plane still drains the fleet, and an extension is a renewal the instance collects on its next outbound check. Costs one outbound check from the instance. | If an execution channel into instances becomes available for another reason, a directly settable timer would be simpler. |
| 2026-09-03 | **The bridge onboarding key is cached locally, and a cold cache turns the bridge dependency from a degrade into a refusal.** | The key must be embedded in first-boot configuration and cannot be retrofitted. An instance created without it can never be enrolled by the unattended path, so creating one during a bridge outage produces a machine that bills and can never be used. | The declared `degraded_behavior` for `vrooli-bridge` is qualified: enrollment queues while the cache is warm, and provisioning refuses while it is cold. This is the one place the scenario refuses for a reason unrelated to money. | If bridge publishes a key with a long enough validity that a cold cache stops being reachable in practice. |
| 2026-09-03 | Use the generated `react-vite` scenario documentation contract. | Scenario scaffold was generated from the template. | Docs start with stubs and maturity metadata in `docs/manifest.json`. | Revisit when scenario adopts a different template or doc contract. |
| 2026-09-03 | **This scenario owns capacity and cost, and nothing else.** Rejected: absorbing enrollment, deployment or exposure because they are adjacent. | Every neighbouring concern already has an owner. A scenario that acquires machines is tempted to also configure, expose and deploy to them, and would then compete with three existing scenarios. | Bridge owns trust and dispatch; tunnel-manager owns exposure; scenario-to-cloud and deployment-manager own deployment; the business suite owns money. This scenario is small on purpose and delegates four times in one provisioning flow. | If a neighbour proves unfit for a specific seam, revisit that seam alone, never the principle. |
| 2026-09-03 | **The object is an Instance, not a Machine.** | `vrooli-bridge` already owns a Machine, meaning durable operator intent for a node. A second Machine in the fleet would make every cross-scenario conversation ambiguous and invite joining by name. | One bridge Machine points at the Instance currently backing it, joined by pointer. The existing persistence in the cloud scenario already uses the word instance, so the vocabulary is consistent rather than novel. | Never. Renaming after the fact would break the pointer semantics this depends on. |
| 2026-09-03 | **The provider interface has four methods: create, describe, list, destroy.** Rejected: the existing ten-method interface with stop, snapshot and reset. | That interface was shaped by local virtual machines, where stopping is free. On five of the seven cloud providers surveyed, a stopped instance still bills at the full rate. | A pause control cannot be built without a deliberate contract change. `OT-P0-007` makes the prohibition a must-ship target and a structural test asserts no such method exists anywhere in the scenario. Snapshot and reset are absent for the same reason: both bill separately and outlive the instance. | If a provider appears whose stopped instances genuinely cost nothing, and a workload genuinely needs suspension rather than destruction. |
| 2026-09-03 | **Intent is written before the provider is called.** Rejected: recording the instance after a successful create, which is the obvious ordering. | A create that succeeds while its response is lost produces an instance the database has never heard of. This is the single largest source of unaccounted cloud spend in practice, and no amount of later polling recovers what was never recorded. | Every provisioning path carries one extra durable write before it can call out. Reconciliation can match an unaccounted instance back to its request. Retries reuse the original idempotency key rather than creating a second machine. | Never. This is the invariant the reconciler depends on. |
| 2026-09-03 | **Credit is reserved before the provider is called, and the business suite is the one dependency that fails closed.** Rejected: provisioning optimistically and settling afterwards. | Hosted compute is cost-bearing, and the paid-features contract names it verbatim as such. A machine that boots without a reservation is cost that grows hourly with no compensating action available afterwards. Refusing is recoverable; provisioning unmetered is not. | Capacity becomes unavailable when the business suite is down. That availability cost is accepted deliberately, and it is the only dependency in this scenario that refuses rather than degrades. | If a credible offline reservation mechanism exists that cannot be forged by the client. |
| 2026-09-03 | **Bridge degrades rather than blocks.** | Enrollment is what makes an instance useful, but it is not what makes it cost money. Blocking creation on the trust plane would make capacity unavailable for a reason unrelated to capacity. | An instance whose enrollment is queued is still created, metered and expiring, and is visibly flagged as not enrolled. The operator surface must therefore render an un-enrolled state rather than treating it as a failure. | If an un-enrolled instance proves to be more dangerous than an unavailable one. |
| 2026-09-03 | **No SSH implementation, ever. First touch delegates to bridge onboarding, and the instance trusts the bridge key from first boot.** Rejected: reusing either existing SSH package, and rejected: passing an owner password through this scenario. | An earlier draft assumed this scenario would be the third caller of the duplicated SSH package and would therefore trigger its extraction. Reading the bridge onboarding contract showed it already expects a caller to create the machine record and then hand it a host, and that its password field is optional when the host already trusts the bridge key. | This scenario contains no SSH code and no credential ever crosses a wire during enrollment. The shared SSH extraction loses its third caller and is no longer on this critical path. A new dependency appears instead: bridge must publish its onboarding public key. | If bridge changes its onboarding contract, or if a provider appears with no first-boot configuration mechanism. |
| 2026-09-03 | **Usage is measured from transitions this scenario caused, never from an observer loop.** | An observer that lists running instances and bills for what it sees stops billing the moment it dies, while the provider keeps charging. The failure is silent and biased towards under-billing. | Measurement derives from the running and destroyed timestamps written by the lifecycle. The reconciler compares against provider inventory but never feeds its result into a charge. | Never. The asymmetry is the whole argument. |
| 2026-09-03 | **The reconciler reports and never resolves, and it compares both directions.** Rejected: an auto-remediating sweep. | An automated sweep with a defect destroys running nodes, including a paying customer's. And most implementations compare only provider-to-local, which misses an instance destroyed out of band that continues to accrue usage locally. | Findings are rows an operator acts on. Marking precedes sweeping. The second direction is what closes a usage window nobody else would close. | If mark-and-sweep proves too slow at a fleet size that does not exist yet. |
| 2026-09-03 | **Expiry is enforced twice: by the sweeper and by a timer inside the instance.** | The sweeper cannot run when this scenario is down, and an unbounded instance costs money for as long as nobody notices. Provider spend alerts send mail; they do not stop anything. | Every instance carries a first-boot timer that powers it off at its expiry with no control-plane contact. The two enforcement points must agree on the same timestamp, which makes expiry immutable after creation unless explicitly extended. | If a workload genuinely needs to outlive its declared lifetime without an operator extending it. |
| 2026-09-03 | **Hetzner Cloud is the first adapter, chosen on contract terms before technical merit.** Rejected: DigitalOcean first despite its better API and per-second billing. | Only three of seven providers surveyed permit reselling at all. Hetzner's standard terms permit granting third parties use rights with no partner programme and no per-customer acceptance; DigitalOcean requires every end customer to individually accept its own terms, which is fatal to a white-label subscription. It also bills outbound traffic only, where Amazon's small-instance product counts inbound against the same allowance. | The first adapter is written against a provider that rounds a partial hour up to a full hour, so a minimum billable unit is required from the start rather than added later. Hetzner also raised prices sharply in mid-2026, so cost models carry a margin buffer. | If Hetzner's terms change, or if a second provider is needed before the resale product is real. |
| 2026-09-03 | **Provider billing data is a reconciliation signal and never a control.** | Provider cost APIs lag by hours to more than a day. A ceiling enforced from lagging data is not a ceiling. | Per-tenant limits are computed from this scenario's own meter. The provider statement is compared daily and raises an alarm on divergence, and its result never feeds a charge. | If a provider offers genuinely real-time, per-resource cost attribution. |
| 2026-09-03 | **A provider's general terms are not the whole contract; per-service annexes are checked separately.** | Scaleway's general terms are silent on reselling and read as permission. Its instance-specific conditions forbid it outright and explicitly override the general terms on conflict. Reading only the headline agreement produced the opposite answer. | Every provider evaluation records which documents were read and which one wins on conflict. Adding an adapter includes a terms review, not just an API review. | Never. This is a research method, not a technical choice. |

## Superseded Decisions

| Date | Superseded Decision | Replacement | Details |
|---|---|---|---|
| 2026-09-03 | This scenario would be the third caller of the duplicated SSH package and would trigger its extraction into a shared package. | No SSH implementation, ever; first touch delegates to bridge onboarding. | Held during design, before the bridge onboarding contract was read. That contract already expects a caller to create the machine record and hand it a host, and its password field is optional when the host trusts the bridge key. The extraction lost its trigger and left this scenario's critical path. |

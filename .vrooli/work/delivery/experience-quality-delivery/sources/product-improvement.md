### Evidence-led product improvement

Use this route for improving, redesigning or rebuilding an existing product, including a major rewrite. Start with the actual experience, make the proposed change reviewable, and carry the exact approved outcome through implementation and verification. This joins existing methods; it creates no second queue, universal folder schema or new execution authority. The installed improve-existing-product skill is a concise trigger/entry to this source and the linked capture, design and commissioning methods; it does not duplicate them. Project-local authority, original intent, current amendments and adopted versions remain governing.

#### Choose proportionate depth

A small clear fix may need only the observed problem/build/state, intended approved behavior, permitted action, verification and closeout in the existing record. It does not automatically require a dossier, new project, atlas or finite team. A substantial redesign/architectural change uses locally adopted design-product-dossier and its applicable product/business/system references; use craft-review-artifacts for the exact review surfaces and commission-useful-work for the handoff. Make consequential choices reviewable without inventing repeated approval rituals.

### Purpose-first project reorganization

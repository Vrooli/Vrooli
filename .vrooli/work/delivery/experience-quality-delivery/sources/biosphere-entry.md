### Normal work path

Use this path for substantial requests, returns and resumed work, including work begun in conversation. For a clear, authorized small task, do it directly and verify it without creating a proposal or extra record.

Keep three roles clear: Drive holds purpose, methods, sources and settled choices; Flywheel holds owner review and dated work observations; native tasks and project owners hold execution, admission and acceptance.

1. Ground the outcome. Use the project/source map to reach its current entry; read only sources and methods needed for this outcome. Preserve the owner’s requested result, scope, acceptance and real holds in its existing record. Reuse the current owner and unfinished work; a shared executor does not merge distinct goals.

2. Choose permission and runner before writes. Use the permission guide, steps 1–3, to select the supported environment and direct, bounded or durable route. Check exact approval, task scope, tool/native limits and required confirmation separately. Carry valid approval forward. Approval and task creation do not prove an action ran.

3. Record and dispatch. Create or reuse one Flywheel Work outcome for substantial work. Link its source, accountable owner and useful next action. Dispatch through the selected native route with that outcome ID; capture actual task/turn receipts. The coordinator verifies the single writer’s start or hold observation. An uncertain projection never justifies duplicate dispatch.

4. Handle review when needed. Use Flywheel’s operator route for source-ready choices, artifact feedback and necessary owner actions. Preserve exact question and source versions, then verify publication. Reconcile every saved answer with current authority before applying its authorized effects. Agent-fixable defects stay with their owner; settled scope needs no repeat approval.

5. Verify and close current state. Check the actual delivered outcome and affected artifacts against the original request, with independent review where needed. Before a return or wait, reconcile relevant task receipts and affected reading paths, update relevant Work, Run and Cursor state, and read back the owning record and Flywheel observation. Each residual needs an owner, next action and actual assignment, or an exact hold and resume event. The coordinator retains whole-outcome ownership.

6. Choose the next useful action. Recheck the owner’s current priority, released work, capacity and real pauses. When revenue is urgent, prefer a credible revenue-relevant outcome over optional process polish. Continue eligible work, publish a genuinely missing choice, or preserve a truthful wait. Name the actual event or supported mechanism that will resume it.

If blocked, use permission guide steps 4–5: distinguish tool/technical failure, denied action and uncertain effects. Try only permitted recovery. If those routes are exhausted, provide the self-contained owner-launch prompt and complete handoff; record incomplete automated delivery requiring owner intervention.

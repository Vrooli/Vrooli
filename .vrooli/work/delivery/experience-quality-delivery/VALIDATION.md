# Acceptance and qualification

This document defines proof for the target in docs/architecture/experience-quality.md. All product cases below are **planned, not executed by this preparation**. Scenario requirements/experience/workflow contracts must receive the accepted obligations at their owning seams before implementation. No fabricated test command, screenshot or reviewed verdict satisfies a row.

## Evidence classes

Keep source inspection, deterministic fixture, operated prototype, actual-build browser, physical device, human/agent visual review and commercial release standing separate. Each result retains candidate/source/recipe/profile/environment identities, exact selected tests and outputs, expected/observed behavior, limitations and acceptance owner. Raw recordings retain timing; edited marketing films do not prove responsiveness. A reviewer verdict is scoped; agent review never masquerades as a human attestation.

## End-to-end cases

### V01 — native discovery and independent use (EQ-01/03/18)

Given an executor without a Google connector or the author's conversation, when it starts at the ordinary native entry and requests a bounded existing-app audit, then it discovers the actual owner operation, retrieves complete required source/material versions, performs the permitted journey and returns a concise usable report/atlas/evidence route. Record discovery-to-result steps, failed attempts, manual translations and actual time/cost where measurable; do not estimate unobserved savings.

### V02 — cloud-only useful work (EQ-02/03)

Given local execution is unavailable, when Dot designs a new application or reviews a retained baseline and proposes an existing-product change, then it can complete useful cloud-native design/research/specification work using its normal sources and tools. It names runtime checks pending and preserves selected/candidate distinctions. An unavailable local image generator or collector does not remove ChatGPT's convenient image/design route or force a second subscription route.

### V03 — published source and package fallback (EQ-02/03/13)

Given current local source cannot be read, when the receiver follows an authorized published GitHub commit/path or a retained adopted package, then it verifies actual access, version and required bytes/references. An absent/inaccessible path gives an explicit source gap. Test older snapshot versus newer local changes and uncommitted local source: no fabricated remote link, silent revision upgrade, credential change or private publication. A source-only fallback does not claim live capture.

### V04 — reconnection and source conflict (EQ-02/03/13)

Given cloud work changed a selected specification while local runtime evidence or methods changed independently, when environments reconnect, then the agent reconciles authority by subject and retains owner edits, drafts, historical evidence and actual versions. Consequential conflict remains explicit until resolved. Test pin drift, missing references and superseded design assets; never overwrite to make hashes match.

### V05 — complete requested collection and review (EQ-04/05/06/08/09)

Given a bounded request including primary and secondary surfaces, when inventory and capture run, then each route/mode/dialog/drawer/menu and material normal/loading/empty/error/recovery case has a requested/observed disposition, actual entry/assertion/reset recipe and applicable device/theme/role/output extent. Assert that opening state A does not silently capture default state B. Include nested scrollers, below-fold unique content, long labels/code and representative dynamic data. A full-capture request stays open when required media is missing, even if every listed cell has a disposition.

Then an independent reader uses the atlas to find a specified state, inspect original-resolution desktop/mobile variants, follow an exact clip timestamp, read the associated finding/specification and return. Contact sheets alone fail readable-detail acceptance. Selected/proposed mockups cannot be labeled captured running product.

### V06 — action feedback and asynchronous recovery (EQ-07/14)

Given Web Console session creation can be delayed, fail, complete late or race a surface change, when the user invokes each supported launch entry, then the interface visibly acknowledges the action, protects against duplicate creation, shows honest pending/completion/error and remains usable. The indicator remains meaningful across launcher/tab/sidebar transitions. Exercise rapid repeat, cancel/dismiss, retry, target switch, reconnect and uncertain completion without losing draft/context or silently replaying side effects. Measure acknowledgement and completion separately against a justified product budget.

### V07 — stable composer and input (EQ-07/14/17)

Given content near one/multi-line wrapping thresholds at actual mobile widths, when typing, paste/delete, long tokens, voice insertion, expanded actions and keyboard/rotation occur, then settled geometry does not oscillate and the caret/draft remain usable. Retain normal-motion frames and height/width observations around transitions. Test repeated cycles and a physical-device overlay for any claimed iOS-specific repair. Preserve the existing low-overhead typing path; arbitrary sleeps and hidden animations cannot substitute for fixing a feedback loop.

### V08 — message position follows user intent (EQ-07/14)

Given the user is following the end or deliberately reading history, when streaming/appended messages, prepended history, virtual row measurements, reader open/close, pane switches and keyboard/viewport changes occur, then the expected follow/anchor policy is preserved. Test touch fling and new input interrupting programmatic motion. Assert user-visible anchor/focus and intended message position, not simply scrollTop equality or a single screenshot. Reuse existing invariants and unique regressions.

### V09 — overlays, focus and visual finish (EQ-07/09/14/17)

Given desktop/mobile and supported themes, when opening, editing, scrolling, dismissing and reopening each material overlay family, then gesture/scroll arbitration, nested controls, Escape/back/backdrop behavior, focus restoration, drafts and safe-area/keyboard layout match the selected contract. Review spacing, typography, density, hierarchy, icons, fields, boundaries and action treatment together at intended size. Reuse selected current visual references; propose genuinely new consequential direction explicitly. Accessibility and real-data adaptations remain documented and tested.

### V10 — durable operation and selective reuse (EQ-10/11/13)

Given a collection partially completes, loses an admission response, encounters an unavailable browser or restarts its owning service, when the client reattaches through the supported owner path, then it recovers the same operation and known artifacts without replaying unknown effects. Test missing/corrupt artifacts, profile/state/recipe/build changes and partial outputs: unaffected applicable evidence may be reused; affected evidence is invalidated. One blocking owner wait and bounded status replace polling. No filesystem path becomes a cross-scenario artifact identity.

### V11 — source and data independence (EQ-02/03/17)

Given selected materials have been received, when native work proceeds without Drive, then references and required originals remain usable. Given live workspace data is private, when fixtures/presentation capture are used, then they cannot mutate unrelated sessions or expose private data/credentials. Fixture evidence stays labeled and does not establish persistence/backend/account/device capabilities it did not exercise.

### V12 — release gate correctness (EQ-11/12/13/17)

Given an applicable customer-facing UI candidate, when Deployment Manager prepares readiness, then missing required surfaces, unverified state entry, stale/wrong-artifact evidence, skipped capture, synthetic-only live claims, unresolved material findings and expired review refuse required readiness with actionable owner reasons. An all-green static suite with runtime skipped remains insufficient. A valid exact-candidate collection, required behavioral receipts and appropriately scoped reviewed evidence can satisfy the criterion through the real owner policy. Test first release, comparable predecessor, unavailable predecessor, significant shared-component/theme changes, no-UI not-applicable and source/design/profile changes after review. Preserve existing waiver/approval actor rules and demonstrate no direct row-edit or alternate release path. Use isolated policy/owner fixtures; do not publish, charge or deploy.

### V13 — contrasting product reuse (EQ-15/16)

Given a selected form/table/list-heavy scenario with a reconciled owner, when the same capability performs a bounded collection and audit, then only product recipes/content vary. The core owner operations, artifact identity, atlas and findings are reused. New copied orchestration, second state storage or validators are a material finding. Do not expand to the whole fleet to demonstrate one honest second-product use.

### V14 — simplification, maintenance and final review (EQ-01/16/18)

Given completed implementation slices, when a fresh reviewer traces normal discovery through runtime evidence, atlas, repair and release decision, then current paths work and replaced owners/callers are retired with unique behavior/test protection preserved. Compare measured source/caller/manual-step/retry/cost baselines; report increases with justified gains rather than treating raw line reduction as correctness. Exercise recovery and selected fallbacks after relevant restart/version changes. Verify maintainer/runbook/learning/entry adoption. Run two fresh whole-boundary critique passes after relevant automated gates pass; resolve material findings and repeat affected checks. Neither two review counts nor a green suite independently proves owner satisfaction.

## Execution protocol

During delivery select relevant phases under docs/TESTING.md. Known owner entry points include `vrooli scenario test <scenario> --phases <selected-phases>` and the exact `test-genie runs wait --json <scenario> <run-id>` returned by admission. Current phase names and scope are checked at epoch admission; do not paste invented specialized commands into a gate. Focused regressions precede expanded validation. Retain selected test names/non-skipped assertions, typed receipts and actual visual/temporal evidence. Generated-artifact freshness failures go to the owning verifier before consumer diagnosis.

For each epoch the leader reruns its declared affected gates independently, reviews original evidence and records deletions/growth and source applicability. Product-wide closure requires EQ-01..EQ-18 traceability, applicable V01..V14 evidence and no material in-scope gap. Any explicitly unavailable external acceptance remains named with owner/return condition and cannot silently disappear from release requirements.

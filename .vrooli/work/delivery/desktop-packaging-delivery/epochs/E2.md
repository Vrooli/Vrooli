## Modules and budgets

1. **Shared contract — `packages/delivery-ramp-go`.** Add `PackagingStrategy`,
   a registry, stack-fact eligibility predicates and a `selection-policy.v1`
   evaluator. Keep the exported types ramp-neutral for later Android and iOS
   consumers; do not add desktop-only fields.
2. **Facts — `scenarios/code-facts`.** Add the `stack` fact family with per-
   component role, `build.kind`, directory, language, UI framework and bundler
   hints, and declared resources. Preserve evidence/provenance and unknown
   values rather than guessing.
3. **Desktop ramp — `scenarios/scenario-to-desktop`.** Resolve framework and
   strategy through the registry, use a per-strategy generator directory and
   `platforms/<strategy>/` output, record selection and reasons in every build
   record, support `--strategy`, and add `strategies list|explain <scenario>
   --json`. Register only `electron-sidecar`; the existing default build path
   must keep working.
4. **Profile pin — `scenarios/deployment-manager`.** Allow a deployment profile
   to pin an explicit strategy and pass that choice through the existing build
   request, while preserving override precedence and validation.
5. **Measurement contract — `scenarios/performance-health`.** Consume existing
   packaged evidence through its published contract when explaining available
   selection evidence; this epoch makes no performance-health code changes.
6. **Shared generated contracts — `packages/proto` (only if required).** Any
   schema change goes through `make generate SCENARIO=<owner>` and
   `make verify-committed-gen`; never hand-edit generated output.

Estimate: 30 work units from the approved QUEUE slice. Feature growth cap is

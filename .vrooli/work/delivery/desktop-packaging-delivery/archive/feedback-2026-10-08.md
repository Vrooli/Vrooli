### DPF-FB-011 — 2026-10-08T01:45Z — operator's Claude session — desktop apps leak escaped child processes (blocks honest measurement)

The operator asked the session to investigate host memory. Finding:
- 42 `opencode serve` processes from mid-September desktop AppImage runs
  outlived their apps by about 21 days: 2.2 GB RSS and 9.7 GB swap. The
  session stopped them after verifying every owning app was gone.
- Mechanism: the bundled web-console desktop app starts `opencode serve` with
  the host environment (`VROOLI_ROOT=/home/matthalloran8/Vrooli`, the host
  `HOME` and the host opencode binary). The host agent-policy runtime then
  places it in its own `vrooli-agent-opencode-*.scope`
  (`VROOLI_AGENT_SESSION`). That moves it out of the app's process tree, so
  app exit or smoke-test teardown never reaches it.
- This is the same host-environment leak as plan
  `trustworthy-bundled-desktop-apps-private-runtime-isolation` (bde99dd3),
  with a new consequence: process leaks.

Required for this goal. Fold it into F1 as a root-cause item, or into E1's
gate if F1 is about to close:
1. **Measured and smoke launches reap everything they started.** Every
   `packaged-launch.v1` capture and smoke run ends with zero surviving
   descendants. That includes processes that escaped into `vrooli-agent-*`
   scopes; attribute them by the launch's environment or session marker,
   not by parentage.
   - Add a post-launch assertion that fails the sample if anything survives.
   - E3's ~480-launch matrix must leak nothing; today it would leak about
     one process per launch.
2. **Bundled apps must not route their own child processes through the host
   agent-launch path.** A bundled app's helper processes stay inside the app's
   own process group or scope, so they die with it. Coordinate with plan
   bde99dd3 by recording a ledger note there. Do not fork its env-isolation
   design. The process-lifetime rule belongs in the desktop runtime
   supervisor and template, which this goal owns.

### Recording and execution traces

- **Recording:** the driver supplies a typed `TimelineEntry` receipt to `ReceiveRecordingAction`; the handler validates its action and page owner, redacts sensitive values, then calls `AddTimelineEntry`. `RecordTimelineEntry` normalizes session context and commits the proto through SQLite's atomic sequence/idempotency write. The handler broadcasts that same entry with `BroadcastTimelineEntry`. REST timeline reads serialize generated proto JSON and preserve page ownership as row metadata; `useTimeline` decodes the generated `TimelineEntrySchema`, retains timestamp/sequence order, and `RecordingSession` projects it to `TimelineItem` only at the view boundary. Page attribution, sequence, redaction and persistence/broadcast ordering are covered by `record_mode_integration_test.go`, `services/recording/service_test.go`, `services/recording/persistence/sqlite_test.go`, `handlers/record_mode_test.go`, and `ui/src/domains/recording/types/timeline-unified.test.ts`.
- **Execution:** `FileWriter.RecordStepOutcome` writes each result to `timeline.proto.json` as a generated `TimelineEntry` with timestamp, status, telemetry/artifact references, error, retry, assertion and extracted-data context. The execution WebSocket sink builds the same proto message shape from `StepOutcome`, then adds the envelope sequence/status/progress and broadcasts it. `GetExecutionTimelineProto` loads the persisted proto JSON and the executions API returns it directly; UI timeline handling decodes the generated message and projects it for display. Persistence and streaming regressions cover order, timestamps, telemetry, error/retry context and UI receipt; `automation/execution-writer/file_writer_test.go`, `automation/events/ws_sink_test.go`, `services/workflow/execution_results_test.go`, `handlers/executions/service_test.go`, and recording timeline UI tests are the supporting test files.

The writer trace uncovered and fixed missing `ExecutionId`, retry status, selector confidence/snapshot and context extracted-data fields in persisted entries. The unused in-memory `TimelineFrameData` and its second payload builder were also removed; the manifest already serializes from the proto timeline, with a regression forbidding a parallel `timeline_frames` result field. The focused writer regression and full API suite pass after the parity fix.

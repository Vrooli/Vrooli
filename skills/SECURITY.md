# Skills Security Policy

Skills published from this folder run with the **full permissions of the host agent**. A compromised skill compromises every user who installs it. The policy below is non-negotiable for anything published under the Vrooli name.

## Disclosure

Found a vulnerability in a published Vrooli skill?

- **Email:** security@vrooli.com (or whatever the project security contact resolves to — keep this current).
- **Do not** open a public GitHub issue for active vulnerabilities. Issues for skills with patched-and-released fixes are fine.
- **PGP / Sigstore key** for sensitive disclosures: TBD when project security contact is established. Until then, use email; we will respond within 72 hours.

We treat skill security findings with the same severity as any production security finding. The supply-chain blast radius (every installer, every host agent, every downstream agent run) makes this category higher-stakes than most application bugs.

## Publishing checklist (mandatory, every release)

Before any skill in this folder is published — to a curated registry, to skills.sh, to ClawHub, to anthropics/skills, anywhere external — all of the following must be true. CI enforces what it can; reviewers enforce the rest.

### Build-time

- [ ] **Cosign signature** attached to the OCI artifact. Keyless via Fulcio is acceptable; long-lived keys are not. See [docs/skills/publishing-guide.md](../docs/skills/publishing-guide.md).
- [ ] **SLSA Level 3 provenance attestation** generated by `slsa-github-generator` (or equivalent) and attached as an OCI referrer. Identifies the build commit, GitHub Action run, and source URL.
- [ ] **SBOM** (CycloneDX or SPDX format) generated by Syft and attached as an OCI referrer. Lists every dependency and transitive package.
- [ ] **Pinned install targets.** No `curl | bash` to mutable URLs. Every download in `scripts/install.sh` must specify a commit SHA or release tag plus a SHA-256 checksum.
- [ ] **Minimal `allowed-tools`** in YAML frontmatter. `Bash(*)`, `WebFetch(*)`, full filesystem access — none of these are acceptable defaults. Constrain to the smallest set the skill needs.
- [ ] **No remote URLs in SKILL.md body.** Network calls live in install scripts (which the user reads) or in the wrapped Vrooli CLI (which is signed separately). The SKILL.md itself reads-only; the body is reference material.
- [ ] **Hidden unicode sanitization.** CI must reject zero-width characters, bidi marks, and non-NFC-normalized text in SKILL.md and references.

### Scan-time

- [ ] **Snyk Agent Scan** clean of critical and high findings. Mediums require justification in the PR description.
- [ ] **Cisco Skill Scanner** clean of critical findings.
- [ ] **At least one additional scanner** of choice (SkillShield, ESET AI Skills Checker, agentic-skill-shield from a registry) clean.
- [ ] **OWASP Agentic Skills Top 10** mapping documented in the PR — for each item, why this skill is not vulnerable to it, or what mitigation is in place.

### Review-time

- [ ] **Two-reviewer requirement.** One reviewer must be on the security-aware reviewers list (see project members). Solo merges of skill changes are not permitted.
- [ ] **Scripts read line-by-line.** Every `scripts/*.sh` file diff is reviewed for shell injection, command substitution risks, and download chains. "LGTM after CI" is not acceptable for skill PRs.
- [ ] **References reviewed for prompt injection.** Reference markdown the agent will load is reviewed as carefully as the SKILL.md body.

### Post-publish

- [ ] **Listed in registry curation tier we control** (anthropics/skills curated marketplace as primary; self-published as secondary). Trust scores for self-published-only skills are lower.
- [ ] **Version is immutable.** Once published, never overwrite. Bumps go to a new version. This is the supply-chain rule, not a convenience.
- [ ] **Kill-switch documented.** A documented procedure to revoke or warn users about a compromised version (Cosign revocation, registry takedown, public advisory). Without this, a "we found malware in our skill" event becomes much worse than it needs to be.

## Vrooli-specific differentiators

Two assets we already have map cleanly to "trustworthy publisher":

- **Workspace-sandbox.** Where possible, install scripts should set up the wrapped capability to run *under* `workspace-sandbox` rather than directly in the agent's shell. This converts Vrooli's per-action accountability substrate into a publish-time trust signal. Most published skills go raw-shell; "runs under workspace-sandbox" is a real moat.
- **Wrap-not-use principle.** Skills wrap our CLI tools, which themselves wrap the actual sensitive operations. This gives us a clean place to enforce auth, scope, and audit logging at the CLI layer — not in the skill itself, where it would be easier to bypass.

When a skill takes advantage of these, **mention it in the SKILL.md description**. It is a real differentiator in a market where Snyk's Feb 2026 ToxicSkills audit found 13.4% of skills carry critical vulnerabilities.

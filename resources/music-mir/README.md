# Music MIR

`music-mir` is the local managed-service owner for analysis backends consumed by Music Tools. Music Tools owns durable jobs and result records; this resource owns model/runtime installation, inference adapters, and local scratch. Analysis is private: reference audio, stems, transcripts, clips, and derivatives are never published or redistributed.

The approved `yt-dlp` reference acquisition CLI belongs to the private MQ1 research run, not the MIR inference runtime. The resource does not download source tracks. Its model/config are selected by a pinned manifest; the weights are not present until an explicit resource data-group acquisition.

## Runtime contract (in progress)

The localhost API implements the synchronous inference side of Music Tools durable jobs: `GET /health`, `GET /v1/capabilities`, `POST /v1/analyze`, `POST /v1/separate`, and `POST /v1/cancel`. Music Tools owns job durability, cancellation, capacity admission, blob ownership, and result reads. This resource checks source SHA-256, requires the caller's canonical Music Tools blob root, confines inputs and outputs below that root, and writes four named stems only into `analysis/.staging/<request_id>`. A cancel request is acknowledged as drained only after active inference and model cleanup finish.

SubRoformer is the first configurable separator candidate. Its upstream checkpoint and config revisions, digest, size, four-stem contract, and source are recorded in `server/model-lock.json`. The model card gives no license for the checkpoint, so this manifest permits local personal analysis only. There is no commercial-output claim. Execution explicitly requires CUDA and fails closed when CUDA or the checkpoint is missing; it never silently falls back to CPU.

Analysis currently emits tempo/beat estimates, key candidates, an energy curve, stem-energy curves, explicitly low-confidence acoustic-cut candidates, and best-effort timestamped transcript segments from the existing local Whisper service. `MUSIC_MIR_WHISPER_URL` is configurable, but the resource accepts only loopback HTTP targets so private references cannot be sent to a remote service. Unavailable or malformed Whisper responses leave analysis available with an explicit transcript status. Transcript segments are hypotheses, not word-level alignment, and the service supplies no confidence. The result remains `partial`: these signals do not establish section names, hook meaning, or what the listener hears. Semantic captions and verified section labels remain unimplemented. The resource first uses the pinned `imageio-ffmpeg` 0.8.1 wheel containing FFmpeg, then an explicitly configured/system binary when that optional bundled route is absent. Its dependency is deliberately pinned to the upstream Python distribution version (`msst[bs_roformer]` 0.1.0); SubRoformer model/checkpoint release `v1.0.23` is a separate version and is not the Python package version. Scenario Dependency Analyzer now owns the first hashed resource lock; the lock bootstrap resolves dependency metadata only and does not install wheels. The [upstream v1.0.23 release](https://github.com/ZFTurbo/Music-Source-Separation-Training/releases/tag/v1.0.23) recommends at least 16 GB VRAM for this memory-intensive model, so the resource declares a conservative 16,000,000,000-byte CUDA claim (16 GB, not 16 GiB). The host’s current free VRAM is below that estimate; do not admit inference until the broker grants capacity and the model’s checkpoint rights remain suitable for local personal use.

Current support is Linux x86_64 only; other deployment targets remain unqualified. Model weights are pinned but not installed. Music Tools jobs own accelerator admission and serialize model inference; the resource closes its CUDA model before returning the job's HTTP response so no untracked VRAM residency remains after the capacity claim is released. Peak VRAM, throughput, and separation quality on the 11 acquired references have not been measured. `GET /health` only reports ready when the model config and checkpoint exist, and the resource manifest declares readiness/liveness checks for that endpoint. Dependency installation must use the Scenario Dependency Analyzer owner route; do not install dependencies with a raw package manager.

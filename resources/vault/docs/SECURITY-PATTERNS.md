# Vault Security Patterns

## Use The Resource CLI

Capabilities that explicitly require Vault semantics must use `resource-vault`; they should not call Vault HTTP APIs or the `vault` binary directly. Ordinary credentials use the control-plane credential authority.

```bash
resource-vault content set --path secret/capabilities/example/api/main --key value --value "$EXAMPLE_SECRET"
resource-vault content get --path secret/capabilities/example/api/main --key value --format raw
resource-vault content delete --path secret/capabilities/example/api/main
```

Use `--format raw` only when the caller needs the secret value. Do not log this output.

## Namespaces

Use capability-owned paths only for explicitly Vault-backed capabilities:

```text
secret/capabilities/<capability>/...
```

Example:

```text
secret/capabilities/<capability>/<scope>/<name>
```

Dynamic runtime paths must include their runtime identifier and must be generated by the owning Vault-backed capability. Do not create Vault paths for ordinary resource, integration, or backup credentials.

## Inventory Without Disclosure

Use the control plane for metadata-safe credential visibility:

```bash
vrooli credentials status --identity vrooli/twilio --field account-sid
```

These commands report presence and missing status without printing secret values.

## Runtime injection

Credential values are injected only into the process environment selected by a
manifest descriptor. They are not exported into an operator shell.

## Local Runtime Caveat

The default Vrooli runtime is durable local file storage, not in-memory dev mode. Bootstrap and unseal material are provider-controlled and are not written by the normal resource lifecycle.

Before external production use, add and validate TLS, operator-managed unseal or auto-unseal, scoped policies, audit logging, backup/restore, and HA design.

## Checklist

- [ ] Ordinary credential values are never printed or shell-exported.
- [ ] Resource code obtains ordinary credentials through the control plane.
- [ ] Required secrets are declared in `credentials.descriptors` in a manifest.
- [ ] Dynamic Vault paths include their runtime identifier.
- [ ] Ordinary backup passphrases remain in the credential authority and are not copied into Vault, files, config JSON, logs, command history, or scenario databases.

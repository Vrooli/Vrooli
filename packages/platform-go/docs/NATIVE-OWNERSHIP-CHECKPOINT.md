## Current architecture

One maintained RuntimeSupervisor runs as the actual non-elevated operator: a system UserName LaunchDaemon on Darwin, or a BootTrigger/S4U/LUA Task Scheduler task on Windows. Explicit elevated setup seals its executable and descriptor; ordinary runtime owns the existing operator state. There is no permanent root resource broker, dedicated vendor account, capability-SID confinement, private desktop or second actor roster. The trusted pinned vendor uses the same operator authority as Linux.

Legacy Linux omitted-Native JSON and opaque ServiceRef start matching remain unchanged. Native references use strict V2 platform/manager/account/boot/incarnation identity and value equality across independently decoded JSON. Darwin binds user/<uid>, exact role label, kernel root unique ID and ProcessOnly. Windows binds operator-job, actual SID, exact invocation Job and root birth. Unoperated native V1 candidates are rejected rather than represented as shipped compatibility.

Darwin services explicitly select native-advisory limits; no actual-user-wide NPROC quota is imposed or described as isolated containment. Windows native-process-limits means Job aggregate memory/CPU/process count, without a thread quota. Unsupported bounded native hard-limit contracts remain refused.

## Ownership and execution

Darwin uses exact per-role launchd labels in the actual user's boot-independent user domain. Typed native manager queries distinguish unknown from absence. Persisted DispatchPrepared separates domain preparation from the single admitted role bootstrap; uncertain submission is never replayed. Kernel root unique ID and exec generation bracket process observations. Stop/release recheck the full manager/root association after durable revocation before exact-label bootout; changed roots are refused. Native runtime reads the OS account home, independent of the normalized wrapper HOME/environment.

Darwin ProcessOnly admission is closed to the maintained immutable installed host and the fixed OpenRGB capsule entrypoint; generic arbitrary executables cannot claim it. The one early Seatbelt application combines process-fork denial with the concrete macUSPCIO constructor hazard denial. Read-only NoChildren checks run after application, after claim and for the serving image. No second sandbox_init or unrelated job-creation/HOME/process isolation requirement is claimed. Actual SDK/kernel behavior remains unqualified.

Windows persists intent before create-only registration of a UUID-exact on-demand S4U/LUA task, and durably marks RunIssued before its sole native Run. The task action is the existing maintained wrapper with its exact frozen capsule argv, rather than a relay. A typed, non-effecting capsule read supplies the intent to PrepareWindowsOwnedServiceSubmission; this verifies native task/action/birth/image/account/boot before the wrapper creates and joins its own named Job, retains image/Job handles and publishes post-flush custody. Only then can HID witnessing, suspended SDK child creation and durable claim proceed. The caller/scenario Job is no longer the wrapper's ancestor by submission design; actual Windows lifetime proof remains open. Vendor children receive their own image handle and Job membership, never a Job handle. The wrapper remains the native task action while waiting for the SDK.

Start does not compare legitimate root-sealed launcher copies with the ordinary caller executable pathname: immutable launcher bytes must match the approved installed maintained host. Arbitrary Windows service entrypoints are refused before effects. Lost registration/Run acknowledgement never authorizes duplicate submission. Retirement persists revocation before exact task disable/Stop(0), checks instances/queued state and the named Job/root, deletes the exact inactive task and confirms its absence before removing the ledger. No direct CreateProcess fallback, mutable global host configuration, retired SCM dispatcher or parent-containment weakening remains.

Strong installed-host, owned-root and Windows owned-child image APIs retain mapped image/file identity authority. Generic Windows pathname opening does not substitute for mapped-image proof. Actual argv/environment/cwd/security and host-wide listeners are observed; malformed/duplicate environment keys are rejected before conversion to maps. Frozen capsule material excludes only the dynamically derived native claim digest; the authenticated owner independently derives and commits the exact durable claim after observing wrapper/child identity and current generation.

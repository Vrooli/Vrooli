Start hereSix corrections to my earlier read

Investigating the actual seams changed six things I told you. Most are good news, and the pattern across all of them is the same: the mechanism exists, is well designed, and is not connected at one specific joint.

The mechanismWhere a portability fact comes from

Every claim the board makes traces back to a manifest. The resolver is a pure function over those manifests, the instrument aggregates and ranks, and four gates are supposed to check that the manifests are telling the truth. Drawing it makes the choke point obvious.

Finding 1 · the big oneA new package silently breaks 241 modules

You had the right instinct: this is a package-lifecycle problem, and the fix belongs where a package is tested, not in CI. Investigating it turned up something sharper than “the check is missing.” The check runs, passes, and reports success while doing nothing.

Joint 1 — plan and execute bypass the target resolver

Brokentest-genierouting, not modelling

workspace.go has two constructors: NewTarget for non-scenario targets — complete, with its own artifact root under the contract-owned runtime state — and NewWithOptions for scenarios, which rejects anything containing a colon. applicability resolves through targetmodel; plan reaches NewWithOptions instead. Every non-scenario target is blocked by this, not just packages — control-plane:internal, project:repo and docs:docs all enumerate and all fail here.

The keystone: tools and safeguards cannot express nuance

Root cause · defects G2 and G5 .vrooli/schemas infrastructure-manager

platform_status is absent from both tool.schema.json and safeguard.schema.json, and used by 0 of 67 tools and 0 of 29 safeguards. Resources have it. Scenario platform_capabilities have it. The 96 manifests that make up most of the grid can only write platforms: ["linux"].

That one array has to mean two different things — “not ported yet” and “not applicable here” — and the AND rule can only read it one way. It also means the middle rungs of the honesty ladder are structurally unreachable, so supported is the only thing a tool can say and qualified is the only thing the resolver can conclude.

Finding 12 · the one that decides the end stateConsolidation and debt retirement

Every fix above touches a file that already carries debt. The difference between finishing cleaner and finishing messier is whether those are treated as one edit or two — so here is what is already sitting in the exact files this work opens, and what each change should delete on its way through.

The consolidation that pays for itself three times

One enumerator already exists, and 62 files use it

repo-contract-go’s EnumerateTargets is the contract-backed authority — 298 targets across nine kinds, with the explicit comment that “adding a matching directory changes the result without changing this code.” 62 non-test files consume it. Seven hardcoded scenarios/*-style globs remain, and one of them is conformance.go, which carries three.

Point conformance.go at the contract instead of its own globs and four things happen at once:

  • Coverage goes from 3 scenarios to 121 — the feature we wanted anyway.
  • Three hardcoded globs are deleted, leaving four stragglers repo-wide.
  • templates/ is not a target kind, so template modules stop being discovered — which is the same root cause as the deps reconcile --all crash. Excluding non-target trees from the reconcile topology fixes both from one principle.
  • xbuild-known-failures.txt shrinks from 13 entries to roughly one (the go-cycles fixture module nested inside a scenario root), and possibly to zero if that fixture is expressible another way.

That file is worth a second look regardless: it lives in internal/deployability/testdata/ — a test-fixture directory — and its only reader is the Makefile. A production exclusion list parked in testdata and parsed by shell is exactly the sort of thing that survives because nobody can see it.

Delete, don’t keep both

make cross-compile and conformance.go are two implementations of one sweep with different discovery, different flags (-mod=mod against GOWORK=off) and different exclusion lists. The consolidation is only a win if the Makefile’s copy is deleted and the target becomes an invocation. Keeping both, with one delegating, is how you get a third behaviour.

One decision that gets much more expensive after the first package run

runs.proto says “scenario” 61 times: the runs ledger is keyed on a scenario string. The moment execute package:envkit-go works, package runs start being written into a field named scenario. Decide before that, not after — renaming a proto field is a refactor today and a stored-data migration once the ledger has rows in it. Either the field becomes target, or it is documented as the target expression and the name is accepted forever. Drifting into the second by not choosing is the outcome to avoid.

The related good news: targetmodel.Resolve accepting a bare slug (notes) alongside kind:id is a genuinely useful affordance, not debt. Its own comment calls it “legacy”, which invites a future tidy-up to delete it. Reword it as a documented alias so it survives.

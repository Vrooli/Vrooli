Scope agreement · rev 5 · supersedes rev 4 (2026-08-07) · measured 2026-08-18

Seven plans, not one. The single-effort shape is what failed last time.

Rev 4 scoped 59 items into one twelve-phase effort. That plan has sat in DRAFT with every phase TODO since 2026-08-13 and has never started — while eleven smaller, independently-scoped plans around it completed and closed roughly a third of its inventory anyway. The work got done; the container did not. This revision keeps the goals, re-measures the inventory down to 47 remaining items, and splits them into seven plans that each ship on their own. This is not a plan — it is the agreement about what we are trying to achieve, what is in and out, and what "done" means, so the plans that follow have nothing to rediscover.

The delta

What eleven days actually changed

Rev 4's central claim — "almost every mechanism you need is already built and switched off" — turned out to be right, and the mechanisms got switched on faster than the document expected. Three of its ten workstreams are effectively closed.

Retired since rev 4

  • WS-A, mostly. All nine non-compiling scenario modules build. vrooli-emulator gained its unsupported-platform file. The stray vault tool entry is gone.
  • WS-C, mostly. Required host tools cut from 19/19 to 10/19, so the opt-in layer is reachable. rasdaemon, mcelog, kdump-tools and Docker are no longer required. The node/pnpm asymmetry resolved itself — both are now optional.
  • WS-E, the hard part. The test-utility ownership plan completed on 2026-08-13: testkit-go was deliberately dissolved and the shared seams moved into api-core. Rev 4's advice to "flip scenario_adoptable" is obsolete.
  • WS-G1. The Mac mini is enrolled, heartbeating, and has run native setup, resource start and host inventory.
  • WS-B1, unexpectedly. packages/platform-go exists and is good — a complete seam with systemd, launchd and Windows SCM backends.

Goals

What we are trying to achieve

Rev 4's four goals carry forward with their status updated. A fifth is added, because the Bridge authorization model turned out to be a distinct concern rather than a detail of the Mac mini work.

G1
Be able to prove a platform claim partly met

A capability ledger now exists and is derived rather than asserted. But it has no evidence axis, so "implemented on macOS" and "proven on macOS hardware" are still the same word, and no test verdict records which OS produced it. The Mac mini is the instrument, not the milestone.

G2
One seam per platform concern, enforced not met

The seam exists and twelve control-plane packages use it. Six scenarios out of 123 do. Nothing prevents the 117th from writing syscall directly, which is why the branch count rose. The rule is the deliverable; the refactor is how you make the rule passable.

G3
Every declaration has one authority not met

Unchanged from rev 4 and demonstrated concretely: Postgres and Redis each hold three inconsistent answers about macOS support, in three different files, right now.

G4
A new developer inherits a floor, not a toolbox largely met

Ten required tools instead of nineteen; Docker optional; Linux-kernel RAS tooling no longer forced on a Mac. What remains is documenting why each surviving requirement is required.

G5
A node's authority is derived, never enumerated new

Adding or changing a scenario command must require no edit to Bridge and no edit to any node. The derivation already exists — 2,251 governed commands compress to 164 grantable scopes — but node grants are keyed on command names, so today every new command is a per-node edit, and a recent tightening left both live nodes able to execute nothing at all.

Boundaries

In scope, out of scope

In scope

  • The developer install path — curl | sh → setup → develop on Linux, macOS and Windows.
  • Control plane, packages, resources, tools, safeguards, templates.
  • Bridge node and agent authorization, end to end.
  • Making Postgres and Redis reachable on macOS by some deliberate route.
  • Consolidating validation into the existing health-scenario fleet.
  • The two Mac mini proofs: a coding agent through Web Console, and iOS simulator evidence.

Out of scope

  • The 52 scenarios with no cli/manifest.json. Owner decision, 2026-08-18. They contribute no scopes and are therefore not remotely invocable. Recorded as a known limit, not a defect.
  • Rewriting the 123 scenarios. They get fixed where broken and migrated where they duplicate shared code — not redesigned.
  • End-user distribution. scenario-to-desktop owns bundling and already has the signing infrastructure.
  • Regenerating scenario-to-ios. It was rebuilt this month; eight of nine plan phases are done. Inspect before deciding, and only after the simulator proof says whether a rewrite is needed at all.
  • New CI infrastructure. GitHub Actions shrinks; Test Genie owns the rest.
  • Signing the vrooli control-plane binary. curl | sh sets no quarantine attribute, so Gatekeeper never engages.

If you would rather run one effort than seven

Then keep P3 → P5 and P2 → P4 as hard internal gates, and accept that the whole thing starts when the largest phase can start. The reason to split is not size — it is that P1, P2, P6 and P7 have no dependency on anything, and folding them into a container that has not started in five days is how they stay undone. Seven plans also means seven completion gates, which is the mechanism that closed a third of rev 4's inventory while its own plan sat still.

Done

What finishing looks like

The effort is done when

  • A coding agent on the Mac mini answers through Web Console, and an iOS simulator screenshot taken on that machine is retrievable as a Bridge artifact.
  • Adding a scenario command requires no edit to Bridge and no edit to any node.
  • Every test verdict names the OS that produced it, and the macOS matrix rows have been promoted off recorded hardware evidence rather than cross-build results.
  • A bare runtime.GOOS comparison outside the seam fails validation, and the declared-exception count is monotonically falling.
  • vrooli setup --environment development completes on a Mac with nothing pre-installed.
  • Each platform claim has exactly one authority, and a claim that outruns its evidence fails a contract check.

Known limits we accept

  • 52 scenarios remain remotely uninvocable, by owner decision.
  • The Mac mini is Intel. macOS 26 is the last release supporting Intel, so this proving ground has a known expiry and Apple Silicon evidence remains separate and outstanding.
  • Darwin's cgo Keychain means a Mac must build its own credential path locally. One prebuilt-artifact mechanism will not cover both a Mac and a Raspberry Pi. H4
  • Two capabilities have no Windows equivalent and one has no macOS equivalent. Honest declaration is the deliverable, not parity.
  • Prebuilt artifacts pushed over Bridge for constrained targets stay out of this scope as an optimization. WS-H

The one rule, restated because it is now evidence

No consolidation ships without its enforcement rule in the same change. Rev 4 offered this as judgement. Eleven days later every measured consolidation that shipped without a rule is larger than it was, and every one with an owning plan and a completion gate is closed. Sequence the rules before the refactors and this effort converges; sequence them after and the next revision re-measures the same numbers.

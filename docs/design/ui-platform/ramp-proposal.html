Ramp proposal · needs approval

Eight spacing steps, eight text styles, and the contract that makes them portable

Every value below is rendered at its true size — judge the ramp, not a table of numbers. One structural change comes first, because without it these tokens would become a fourth dialect rather than a shared system.

00 — BlockerThe kits share no semantic contract

Before values: the three design kits have no utility names in common. This is not a ramp problem, but it decides whether ramps are worth adding.

KitSurfaceForegroundControl radius
vrooli-defaultbg-app-surfacetext-app-foregroundrounded-control
vrooli-command-displaybg-display-surfacetext-display-foreground— none —
vrooli-conversion-landingbg-landing-surface-primarytext-landing-text-primaryrounded-landing-control
What this means today

ControlBase writes bg-app-surface … rounded-control. Under vrooli-command-display neither utility exists, so the control renders with no surface and no radius. Meanwhile Button/component.json declares affinity: "compatible" with all three kits. That affinity field is currently unfalsifiable prose — nothing checks it, and it is wrong.

Proposal: one semantic contract, three sets of values. Every kit exposes the same utility names — app-surface, app-foreground, rounded-control, space-md, text-body — and differs only in what those names resolve to. The display- and landing- prefixed tokens stay as kit-private extras for surfaces genuinely unique to that kit (display-glow, landing-accent-tertiary), but the shared contract is what components are allowed to reference.

This makes designStyles.affinity checkable for the first time: a component is native to a kit if it references only shared-contract tokens plus that kit's extras, and incompatible if it references another kit's extras. That is a static lint, not a judgement call.

01 — SpacingEight steps on a 4px grid

The base unit --spacing-unit: 0.25rem is already declared and consumed by nothing. These eight are the only legal spacing values; anything else becomes a lint failure.

This ramp deletes a value already in use

ControlBase currently uses px-3.5 — 14px — for its md and default sizes. 14px is off the 4px grid and is not in this ramp. It becomes space-sm (12px) or space-md (16px); I would take 12px, which pairs with the 44px height for a proportion close to Linear's.

03 — RadiusFour roles, already declared — with one correction

All four already exist in vrooli-default. Nothing new to approve except spreading the same four names to the other kits and settling how radius relates to size.

rounded-control6px
rounded-panel8px
rounded-sheet16px
rounded-pillfull
Correction to the 2026-08-04 decision

That entry says a control resolves height, horizontal padding, icon size, and radius from xs–xl. I would drop radius from that list. vrooli-conversion-landing already sets --radius-control: 9999px, meaning every control there is a pill regardless of size — so radius is a kit property, not a size property. Binding it to size would make that kit unrepresentable.

This also fixes a live defect: ControlBase uses rounded-sm, rounded-lg and rounded-xl for three of its seven sizes. Those are Tailwind's built-in scale, not kit tokens, so three sizes silently bypass the design kit entirely. All seven should use rounded-control.

06 — Borders & opacityTwo widths, three alphas

border-hairline1pxDividers, card and input outlines
border-strong2pxFocus ring, selected state, emphasis

border-strong at 2px already matches the outline: 2px solid var(--color-focus) in every kit's base styles — so this codifies existing behaviour rather than changing it.

opacity-disabled · 0.40 opacity-muted · 0.64 opacity-scrim · 0.72

opacity-muted is for de-emphasised content that is still interactive. opacity-disabled must never be the only disabled signal — aria-disabled and cursor carry it too, since 0.40 alone fails contrast.

Three laws, all lintable

Exit is always faster than enter — a leaving element must not hold attention. Only transform, opacity, color and filter animate — animating layout properties is a performance defect, not a style choice. No shake or bounce on error — errors get colour and position change, never a punishing motion.

08 — Per-kit valuesSame names, three resolutions

Spacing, type, layers, borders, opacity and motion are primitive ramps — identical across all three kits. Only radius, elevation and colour are kit-specific, which is what keeps a component portable while still letting a kit have a face.

# Vrooli Context

Vrooli is building a local, self-improving software system where completed work becomes reusable capability.

The platform has moved well past its older framing as a single web app or a loose collection of scripts. It should now be understood as:

- a Go-native project control plane
- a scenario and resource orchestration system
- a local-sovereign operator environment
- a platform that compounds problem-solving ability through reusable software artifacts

## What Matters Most

### Local Sovereignty

Vrooli is optimized for running on infrastructure you control. That includes code, data, models, automations, and supporting services.

### Scenarios As Durable Capability

Scenarios are not just examples or demos. They can be:

- products
- internal tools
- validation surfaces
- building blocks for future work

### Recursive Improvement

The strategic goal is not simply to automate isolated tasks. It is to increase the system's ability to solve future problems by retaining and reusing successful structures.

## Current Platform Truth

At the project level, current documentation should assume:

- the root CLI is `vrooli`
- the project-level control plane is Go-native
- the platform is documented as cross-platform
- Tier 1 local/developer deployment is the current mature path
- deeper deployment portability is still an active area of work

## Documentation Rule

Project-level docs should preserve the project's ambition, but must distinguish:

- what exists now
- what is actively being built
- what remains directional vision

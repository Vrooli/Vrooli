Retiring vrooli-debt-census

Your instinct is right: the fleet should own this. tidiness-manager already ships the exact mechanism — it is just missing four rule kinds.

.vrooli/canonical-seams.json declares 10 seams today, each with a canonical symbol, a rationale, a remediation sentence, an include/exclude scope and a budget. scenarios/tidiness-manager/api/canonical_seams.go matches them against the Go AST in 370 lines. Three semantics that must change with it, or the fleet inherits the same blindness

  • A ratchet must require tightening, not merely forbid loosening. tidinessBudgetFinding fails when a budget rises above baseline and when observed debt worsens. It never fails when a budget was written at the observed value. internal/.vrooli/testing.json and cmd/.vrooli/testing.json use one schema to mean opposite things — the second is a real gate at 1 against baseline: 0, the first is a freeze at 2,752. Reject budget == baseline == observed as a valid state.
  • A seam must be matched structurally, never by package qualifier or operator. B1 and B2 are both this bug. Resolve the symbol, then match; count occurrences, not files containing occurrences.
  • Every gate needs a recorded proof. A transcript showing the gate deliberately broken, observed to fail, and restored. Four of the five blind spots above would have been caught the day they were written by a single proof run.

The seam engine already has a backend

Three code-intelligence scenarios exist, eight validation scenarios already depend on them, and tidiness-manager — the one whose entire job is AST matching — is not among them.

A resolved symbol is exactly what B1 needed: a call matched by symbol identity cannot be evaded by moving a constant from cliout to logx, and cannot miss != because it never looked at the operator in the first place.

Two-thirds of the work is a mapping table. The honest gaps are the last two rows, and they are worth stating precisely because they decide the shape of the change:

  • Literals have no node kind in either producer, and six of the ten seams in .vrooli/canonical-seams.json today are kind: "literal" — repo layout paths, file modes, duration values, root env spellings, tab-delimited format strings, identity variables. Either add a literal node kind to both graph producers — the reserved ranges make that a non-breaking addition — or keep a local literal scanner and broker only the symbol-resolved kinds. The second is the better first move: it delivers declaration, call and shape across both languages without blocking on two upstream scenarios.
  • Go emits no comments. CodeGraphNode.leading_comments is documented as "Empty for Go in v1". The directive rule kind — the one that would catch the 67 //nolint:gocyclo suppressions — cannot come from the graph on the Go side and stays local either way.
  • Go extraction is single-module. ExtractRequest requires exactly one go.mod and rejects workspaces with Unimplemented. The control plane is one module, so this is free; fleet-wide scanning is one call per scenario API module.
The risk this introduces, stated up front

The tidiness phase declares "unavailable": "skip_without_failing". Today it has no scenario dependencies, so it cannot be unavailable. Brokering through code-facts puts a three-scenario chain behind the gate, and if that chain is down the phase silently skips instead of failing — a sixth blind spot of exactly the kind sections 01 and 02 catalogue. None of code-facts, go-code-graph or typescript-code-graph ships a .vrooli/test-genie.json, so the substrate the whole gate would rest on is itself graded by no phase. Both of those must change in the same piece of work: give the three code-intelligence scenarios a phase, and change tidiness's unavailable policy to fail rather than skip when a declared provider is missing.

09

Recommended order

Revised against the decisions in section 08.

Phase 0 is a probe, not a change. Brokering was chosen, so the plan's first obligation is to prove the chain works: start code-facts, request FACT_FAMILY_CALLS for a control-plane: target, and confirm resolved symbols come back with source ranges. If that fails, every later phase is building on an assumption and the plan must say so before it spends a phase.

Then A5 and the required-dependency declaration, together. Until the ratchet rejects a budget written at its own observation, every subsequent fix can be undone by a config edit and nothing will report it — and until code-facts is a required dependency, the gate that reports it can vanish silently. These two are one piece of work; neither is safe alone.

Then the rule kinds, then Tier A. declaration is what lets A1–A3 land with a gate instead of landing on trust, so it precedes them. Tier A then goes as one mechanical sweep: all four items are substitutions with no behaviour change and they share a review. The goconst flip belongs here too, and it drags scenarios/vrooli-onboarding and packages/resource-deployment into the same review.

B2 gets a contract phase before it gets a migration phase. The earlier advice here was to sequence it around another agent's work; measurement retired that — nobody is in internal/app/*, and the one adjacent draft plan touches it zero times. What survives is a downstream dependency: that plan measures through vrooli credentials doctor --format json, and only 2 of the package's 20 commands have their JSON key set pinned by a test. So the first B2 phase writes the missing assertJSONKeys assertions for the other eighteen. That converts an invisible risk into a mechanical one, is worth doing on its own merits at a 22% test ratio, and — once it lands — makes the migration safe to run concurrently rather than sequenced.

One thing worth saying plainly: none of the five blind spots in section 02 required deep analysis to find. Each was visible by running the gate's own claim against a grep.

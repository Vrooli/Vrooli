Track B

Where the ratchet is green and the debt is not paid

Three findings, one root cause: every seam rule bans the specific spelling the previous round produced, inside the specific directory the previous round touched. Change the name or move the file and it passes. The seam file admits the pattern in its own prose — eight why fields begin "Ratchet start: census observed…", a budget written at its own observation.

B1 · Magic numbers were renamed, and the old names moved next door

87 sites

The mnd linter demands named constants. It got them: handlerParameterA through handlerParameterI. Letters, no domain meaning — and the same letter means different things in different packages: handlerParameterF = 2 in four packages, handlerParameterB = 1024 in two.

// internal/safeguards/remote-session-protection/handler.go
const ( handlerParameterA = 100 ; handlerParameterB = 1024 )

memMB  := int(snapshot.Memory.TotalBytes / 1024 / handlerParameterB)  ← /1024 twice, spelled two ways
dMin   := memMB * desktopMinPercent / handlerParameterA               ← this "/100" means percent
swapGB := memMB / handlerParameterB                                   ← this "/1024" means GB

Why the seam missed it. appeasement-number-constants exists at budget 0. Its pattern is ^mnd[A-Z].*NumberValue[0-9]*$ — it bans the names the last cleanup produced. Same retrospective shape in appeasement-string-constants and in stamped-handler-tests, which bans exactly the string TestNameAndKind.

And the banned name itself survives, 51 times. The seam's scope is internal/**. cmd/ is not in scope — so all ten command binaries still carry the original spelling, including mndMainNumberValue2 = 2 in cmd/vrooli-manifest-check/main.go, the checker from A1.

The render-format-prologues row is the worst of the four failure modes on this page: not a loose budget and not a retrospective spelling, but a rule that is structurally incapable of matching anything, carrying a budget of 36 that makes the board look like it is tracking something. The generalizable lesson. B1, B2 and B3 are one bug: rules written as "the token X must not appear in directory D" instead of "this property must hold." Name-and-place rules are cheap to write and cheap to evade — rename, move one directory over, or widen a suppression. Shape-based and semantic rules cost more up front and cannot be walked around. That distinction is the whole of Track E.

C3 · A metric drove a real algorithm regression

Correctness

The plan ledger records sort.Strings calls in internal non-test Go: 0 as a structural result. It reached zero partly by replacing one call with a hand-written insertion sort — while 119 slices.Sort call sites exist elsewhere in the same tree.

// internal/artifactledger/artifactledger.go:546
func sortStrings(values []string) {
  for i := 1; i < len(values); i++ {
    for j := i; j > 0 && values[j] < values[j-1]; j-- {   ← O(n²), over artifact names
      values[j], values[j-1] = values[j-1], values[j]
    }
  }
}

A metric that counts a stdlib call by name is always satisfiable by hiding the call. "Replaced by a private reimplementation" has to be a first-class seam outcome rather than an invisible one.

D1 · The drift checker cannot detect the drift it is named for

Root cause of A1

rootcli.WalkCommandTree() does not walk anything. It returns a hand-maintained var registeredCommandPaths = []string{…} with 142 entries. The checker then compares that list against the 144 leaves parsed from cli/manifest.json.

// internal/cli/rootcli/manifestdrift.go
func WalkCommandTree() []string {
    return commandtree.WalkCommandTree(commandtree.CommandTreeFromPaths(registeredCommandPaths))
}

var registeredCommandPaths = []string{
    "agent launch", "scenario list", "scenario status", …   ← 142 strings, edited by hand
}

So the check compares one hand-written list to another hand-written list. It cannot see a command that exists in code and in neither list, and it cannot see a manifest entry with no implementation. What it can do is fail the build when someone ships a working command and forgets the third list — which is exactly what happened with credentials list and credentials delete.

Deriving the list from the bound handler map is the fix, and it turns the check into a real one.

internal/cli/rootcli/manifestdrift.go · cmd/vrooli-manifest-check/main.go

D4 · Even the migrated domains round-trip back to strings

The bridge

internal/cli/manifestdispatch describes itself accurately: "the small adapter shared by root command boundaries that are still backed by legacy application methods." All four migrated domains reach the manifest through it. The flow is:

argv ──▶ cliapp manifest parser ──▶ RunContext (typed flags, typed args)
                                        │
                                        ▼
                              LegacyArgs(ctx) → []string          flags re-serialized to "--name value"
                                        │
                                        ▼
                          app.Run(ctx, args) → switch args[0]        string dispatch, as before

The manifest supplies parsing and help — which is real value, and is why help text is now consistent across those four domains. But the typed RunContext is immediately discarded, so the domain method still receives []string and still string-switches. Deleting the bridge means giving each domain method a typed request, which is a per-domain change, not a shared one.

What closes this out. Derive registeredCommandPaths from the bound handler map (D1 — fixes A1 permanently and makes the check real). Write the six proto renderers (D2). Then take the three inverted domains one at a time — project is the smallest and has no handlers package yet, so it is the cleanest proof — collapsing each fat …cli into aliases over its app/ types, which retires the C1 duplication as a side effect rather than as separate work.

Change to tidiness-managerWhat it fixes in internal/What it unlocks repo-wide
Rules describe shapes, not spellings B1 — add a semantic-naming rule kind: a constant whose identifier carries no domain morpheme, judged against the surrounding package vocabulary. Catches handlerParameterA, mndMainNumberValue2, and whatever the next round invents. The highest-leverage single change. Every target inherits a rule that cannot be renamed around.
A budget must be re-derived, not remembered B3 — 91 units of slack across five seams, one of them structurally unfireable. Turns budgets from a snapshot into a trajectory, and makes a dead rule impossible to ship.
Suppressions weighted by blast radius B2 — count suppressed declarations, not directives, and add a goconst seam beside the gocyclo one. A file-level //nolint should cost what it actually covers. Makes "green lint" mean the same thing everywhere. No scenario is measured on suppression breadth today.

Closes the loophole that turns every "route X through Y" rule into an invitation to hand-roll Y.
Per-target seam files, and no domain knowledge in the scanner Replace the hard-coded .vrooli/canonical-seams.json with a repo baseline plus per-target overlays. Two shapeKinds compile Vrooli's own manifest schema into the generic engine — service_manifest_decoder literally evaluates structHasJSONNesting(s, "dependencies", "resources"). Unblocks 123 scenarios and packages/ at once, and lets a scenario declare its own invariants in config instead of patching tidiness-manager's Go — which is exactly the pressure that produced a bespoke census twice.
The honest answer. The census kept being rebuilt because tidiness-manager's rules are expressible only as regexes over identifiers within a fixed path scope. Anything needing real semantics — is this constant name meaningful? how much code does this suppression cover? did this call get replaced by a private copy? is this budget still justified? — had nowhere to live, so it got written as bespoke Go in a one-off command. Give the seam engine those rule kinds and the census has no remaining job. Give it per-target config and the other 93% of the repo gets the same instrument for free.

Credit where it is due — observed live

My first run of the census today was fully green. My second, forty minutes later, failed on mnd_findings=3 and unnamed_duration_literals=3. Nothing I did caused it: internal/cli/vroolicli/remote.go was rewritten at 16:44 by the agent working the structural plan, and it introduced three bare 15 * time.Second / 5 * time.Second literals. The ratchet caught a real regression within minutes of it landing. The mechanism works. The argument below is about what it is pointed at, not whether ratchets are a good idea.

Finding 01

Four hundred constants exist to make three metrics read zero

Three of the eleven zeros — mnd_findings, unnamed_duration_literals, bare_octal_file_modes — were reached by renaming values, not by understanding them. The tree now carries a class of identifier whose name encodes its own literal and the package it sits in. These predate both plans; no plan removes them, and once goconst and mnd are switched on for real in Phase 14, this is the shape that satisfies them.

What it was 
strings.SplitN(line, ":", 3)

A magic number. The linter is right to flag it.

What it became 
const mndAttributionLinuxNumberValue3 = 3

strings.SplitN(line, ":",
    mndAttributionLinuxNumberValue3)

Longer, no more meaningful, and named after the linter that complained. The metric now reads zero.

What it should be 
// /proc/PID/status lines are
// "Key:\tvalue" — at most one colon
// belongs to the key.
const statusLineFields = 2

A name that says why. Also reveals the original 3 was probably wrong.

The string case is the sharpest: "windows" is declared under ten different names (literalHelpersWindows, literalInstallationWindows, …), "linux" under ten, "darwin" under seven, "healthy" under six. The pass that was meant to remove duplication multiplied it — and goconst still reports 192 findings, so it did not even finish the job it was gaming.

The same problem wearing a nicer suit: internal/tuning

What tuning/timing.go is 
const (
    Duration10ms  = 10 * time.Millisecond
    Duration250ms = 250 * time.Millisecond
    Duration30s   = 30 * time.Second
    …31 constants, all named
       after their own value
)

Duration30s has 26 call sites. They share a number, not a purpose. Change it to tune one timeout and you move twenty-five unrelated ones.

What a tunable lever looks like 
const (
    // Supervisor reconcile cadence.
    SupervisorTick = 30 * time.Second
    // Ceiling on one scenario start
    // before the runner gives up.
    ScenarioStartTimeout = 30 * time.Second
    HealthPollInterval   = 250 * time.Millisecond
)

Same values today. Independently movable tomorrow, each with an owner, a comment, and somewhere for an override to attach.

tuning/perm.go shows the team already knows how to do this — PermSecret, PermSudoers, PermSocket are named by what they protect, and they are genuinely good. (Two look mis-named and are worth a read: PermOwnerReadWrite = 0o060 is group read/write, and PermGroupMask = 0o077 covers group and other.) The timing file got the mechanical treatment; the permission file got the thoughtful one. Only the permission file is a control surface.

Latent — a broken build reads as a clean one

toolFindingCount counts occurrences of a marker string ("(mnd)") in the linter's output and discards any error that is not "binary not found". If internal/ fails to type-check, golangci-lint emits (typecheck) lines and no (mnd) lines — so the metric returns 0, with no error, and the gate passes. The plan's own Phase 2 risk note called a silently-zero shell-out "the worst failure mode" and then mitigated only the missing-binary case. Distinguishing found nothing from could not look is a handful of lines and should land before anything else here.

The budget file has no floor

.vrooli/internal-debt-budget.json has no baseline field and no anti-loosening check. Raising a number in it makes CI green again. The plan says "never raise one" — as an instruction to a human, not as a check. tidiness-manager already implements the check that is missing here, emitting ratchet_loosened_budget when a budget is edited above its recorded baseline and ratchet_worsened_debt when the observed value climbs. More on that below.

Finding 03

The best abstraction in the tree is used by 41 of 98 places that need it

internal/hostreqkit/hostreqkittest is the strongest piece of test infrastructure here: a table-driven conformance suite whose own correctness is proven by mutation testing (TestSuiteRejectsEachMutant). Adoption among directories that have tests is near-total — 40 of 41. The problem is the other 57 directories, which have no test file at all.

41 handler dirs with tests — 40 use the conformance suite 57 handler dirs with no test file

Untested includes ffmpeg, secret-tool, qemu, openbox, go, claude, git, llama-cpp, helm, curl, k6, xvfb, google-chrome-stable and 44 more. Each one is roughly a ten-line hostreqkittest.Case away from seven behavioural tests.

The other half of the test story

internal/testenv — the shared fixture package — is 47 lines with five functions and four consumers. Meanwhile the test tree contains 1,180 t.TempDir() calls, 276 os.WriteFile calls and 198 os.MkdirAll calls, and dupl finds 163 clone entries among test files. There is a fixture seam; almost nothing goes through it. Building out testenv into a real "scenario tree on disk" builder is the single largest lever on that 163, and it is invisible to every current metric because tests are excluded from most of them.

Finding 04

The census exists because the repo root is missing two files

You asked whether tidiness-manager could make vrooli-debt-census unnecessary. It is much closer than it looks. tidiness-manager already declares control-plane in its phase target kinds, and test-genie already models control-plane as a first-class target (repocontract.TargetKindControlPlane). The capability is not the gap.

Every scenario carries .vrooli/testing.json and .vrooli/test-genie.json. The repository root carries neither — it carries .vrooli/internal-debt-budget.json instead, a bespoke schema with exactly one reader. That absence is the whole reason a parallel budget tool had to be written.

The pattern is already proven in CI

.github/workflows/test.yml has a structure-health job that starts a health scenario through the control plane and then fails the build on the repository contract. A scenario already grades this repo in CI and blocks merges. Wiring tidiness the same way is following a path that exists, not blazing one.

Leave alone

What is genuinely healthy

Checked, not assumed. These need no pass and a refactor here would be pure risk.

  • Error wrapping. 1,354 non-test fmt.Errorf sites wrap with %w. The discipline is consistent enough that this needs no pass.
  • Argument parsing. 101 commandtree.ArgSchema declarations across 13 packages, one shared ParseArgs, two thin per-package wrappers. The plan's claim that this is consolidated holds up — the only debt is the 7 flag.NewFlagSet holdouts above.
  • The handler conformance suite. Adopted by 40 of the 41 handler directories that have tests, and its own correctness is mutation-tested. This is the model the rest of the test infrastructure should copy.
  • Path authority. 122 repocontract call sites against 92 bare literals — the contract is winning, and the remaining literals are concentrated in a dozen files.
  • Package documentation. Every directory under internal/ holding Go code has a doc.go.
  • internal/resources/deprecated.go. The name invites suspicion; it is a real feature (deprecated-resource listing, archival and GC), not dead code. I checked so you do not have to.
Decision

Three ways to play the tooling question

A

Keep the census, sharpen it ~1 day

Fix the swallow-on-failure bug, add a baseline field, retire the dead os_rename gate, and reconcile goconst with the repo's own lint config. Cheapest, and it leaves a second debt-measuring system running permanently beside the fleet — findings that no dashboard shows and no maturity rung reflects.

B

Give the root what every scenario has ~1 week · recommended

Add .vrooli/testing.json and .vrooli/test-genie.json to the repository root and move the budgets there. tidiness-manager already declares control-plane, already implements budgets with a baseline, and already refuses a loosened one. Wire it into CI on the structure-health pattern that is already there. Then shrink the census to the handful of AST queries no linter performs — roughly a third of its current size — and let it feed tidiness rather than stand beside it. Do A first regardless; it is a day, and B inherits the fixes.

C

Generalise the target model across the fleet ~1 month

B, plus teaching the other 21 scenario-only phases to accept a non-scenario root — starting with security-health, performance-health, measures-health and architecture-cartographer, which grade Go source already. This is the version that pays off beyond internal/: every packages/ module and the repo itself become gradeable, and no future audit needs its own bespoke tool. It is also the version most likely to collide with the agent currently executing the structural plan, so it wants to start after that lands.

The principle worth taking away

A debt metric that counts a shape can be satisfied by changing the shape. Three of these metrics were, and the tree is measurably worse for it — 372 constants that no reviewer would defend, and "windows" spelled ten different ways. The metrics worth keeping are the ones where the cheapest way to move the number is to actually fix the code: duplicate-line debt, cyclomatic complexity, untested handler count. Those are also, not coincidentally, the ones tidiness-manager already measures.

The Declared Scenario

A Vrooli scenario declares build, process, port, storage, readiness, dependency, and peer-wiring facts once. The control plane executes that contract locally; Scenario Dependency Analyzer projects it into desktop bundles.

One canonical contract

.vrooli/schemas/service.schema.json is the schema authority and internal/scenario is its Go representation. All 121 manifests validate against it.

{
  "ports": {"api": {"env_var": "API_PORT", "range": "15000-19999"}},
  "components": {
    "api": {
      "role": "api",
      "build": {"kind": "go_module", "dir": "api", "output": "api/example-api"},
      "run": {
        "argv": ["{{bin.api}}"], "cwd": "api", "port": "api",
        "data_dirs": ["data"], "log_dir": "logs",
        "readiness": {"type": "http", "path": "/health", "timeout_ms": 30000}
      }
    }
  }
}

The builder registry covers go_module, pnpm_vite, node_bundle, and reuse. Component metadata owns artifact freshness. Reserved build kinds fail explicitly.

run.argv is never shell-interpreted. cwd, env, port, data_dirs, log_dir, readiness, depends_on, and supervised_by carry the facts formerly hidden in commands.

Derived lifecycle

  1. Setup provisions governed shared packages and runs registered component builders.
  2. Develop topologically orders the component graph and launches one tracked process per component.
  3. The platform seam owns host-specific process creation and termination.

Finite provisioning may use exec: string[]. The removed lifecycle run string has no schema field, Go field, reader, alias, or fallback. The unused manifest test phase and duplicate setup-condition freshness contract are also gone.

Zero-step phase objects are omitted. Both canonical templates generate component manifests with lifecycle health metadata and no empty setup, develop, or test phase.

A build-failing portability test rejects BashCommand, direct bash/sh -c, pkill, and ps executor paths. SCENARIO_SHELL_FORBIDDEN rejects shell interpreters and shell files in declared argv.

Template Manager generation and relocation hooks declare native argv, optional environment overrides, and a working directory. They never invoke a command shell, install or update dependencies, tidy modules, or format generated files. Component builders and Scenario Dependency Analyzer own dependency preparation; template source must already be format- and lint-clean. The control-plane cliinstall boundary is the sole generated-CLI installer.

Ports, storage, and readiness

Tier 1 allocates declared ports and expands a closed ${NAME}/$NAME language. Missing values and shell expression syntax are errors. Port ownership comes from components.*.run.port, never a step-name heuristic.

Declared data and log directories are created through the owned-directory seam. Readiness is explicit component metadata. Host requirements support minimum versions, while host remediation remains control-plane owned.

Resources receive typed declarations rather than lifecycle scripts. The landing-page template declares dependencies.resources.postgres.database; Tier 1 passes it to Postgres's native, idempotent ensure capability before launch. Postgres creates the per-scenario database through its managed service connection, and its native content-removal path owns cleanup.

Peer scenarios

"dependencies": {"scenarios": {
  "landing-page-business-suite": {
    "startup_policy": "try_start", "bundle_policy": "discover",
    "degraded_behavior": "Local work remains available.",
    "bindings": [{
      "env_var": "BAS_API_URL", "form": "http_base_url",
      "port": "api", "when_unavailable": "omit"
    }]
  }
}}

Tier 1 publishes an atomic peer record under <runtime-home>/peers/<scenario>.json only after the durable process and allocated ports exist. internal/scenarioenv resolves bindings and names unavailable required peers.

Tier 2 uses the same codec. Embedded peers receive a <peer>-- service prefix; discovered peers are read from the desktop peer directory and injected under the same binding policy.

The final live Tier 1 proof started Landing Page Business Suite and Browser Automation Studio together through the control plane. LPBS published API port 17691; the environment of the freshly launched argv-native BAS API process contained BAS_ENTITLEMENT_SERVICE_URL=http://127.0.0.1:17691. BAS ran all three declared components. Stopping both scenarios removed both peer records.

Desktop projection

Scenario Dependency Analyzer projects component identity, role, argv, cwd, environment, graph edges, build artifacts, port ranges, data/log paths, readiness, UI assets, and peer bindings. Bundle file inventory is derived from component build directories and outputs; the former folder scanner and folder-to-service inference code are deleted.

Desktop IPC declares port 0 and is allocated collision-safely with service ports. The allocated endpoint is published in the peer record.

The two committed bundles are hello-desktop and browser-automation-studio. Real-scenario construction tests additionally prove the complete projection. Browser Automation Studio contributes its API, UI, sidecar, and peer edge; Scenario to MCP contributes its reused registry process.

Generated-template acceptance

Both canonical templates were generated from clean disposable destinations with native hooks enabled and then started only through vrooli scenario start. The React template reached health with exactly its declared API and UI processes on ports 16841 and 23953. The landing-page template reached health with exactly its declared API and UI processes on ports 19213 and 22392 after its typed Postgres database was ensured.

Both instances stopped through the control plane; Template Manager removed both generated trees, and Postgres's native content command removed the landing database. No disposable scenario, relocated proto tree, or database remains.

Measured result

The final census reports 121 manifests, 121 component adopters, 241 components, 19 argv-only steps, zero live shell syntax, zero lifecycle-invoked shell references, and zero schema violations.

Remaining shell files are fixtures, examples, investigations, integration payloads, CLI bootstraps, or operator tools. Each has an individual disposition; none is declared lifecycle authority.

Recorded plan divergences

  • A literal search for "run": is invalid because components.*.run is canonical; a structural lifecycle query proves zero retired fields.
  • The plan expected eight committed desktop bundles, but the repository has two.
  • Template Manager had two orientation command checks, not four.
  • A rule banning every shell file would contradict the required kept-file dispositions, so enforcement owns declared execution while the census owns inventory.
  • The full fleet HTTP rollup exceeded its client deadline; local schema/shell tests and the deterministic census provide the exact manifest proof.
